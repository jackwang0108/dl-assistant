# 数据集速览模板（code-project-setup）

> setup 数据就绪时，给 repo 用到的每个数据集产一份**速览**——是什么 / 在 repo 里的角色 / 规模 / 格式 / 3-5 个真实样本 / 与论文协议的关系。
> 解决"不知道这些数据集都是啥"的痛。保存 `<repo>-datasets-intro.md`，图片进 `images/`，相对路径引用。
>
> SKILL 讲产出流程，本份是模板。技术术语保留，整体中文。

---

````markdown

> 由 code-project-setup 在数据就绪阶段产出。每个数据集：是什么 + 对我们的研究意味着什么 + 真实样本，让你直观看到数据长啥样。
> 详细的数据 / loader 验证状态见 `setup.json` 和 `setup-report.md`。

## <数据集 1 名>

**是什么**：<任务类型，如 目标检测 / 语义分割 / 图像分类>。<一句话定位：业界标准 / 小众 / 自建>。
**在 repo 里的角色**：<训练集 / val benchmark / 消融用 / demo 用>——<这个角色决定了它要多较真：benchmark 必须版本对齐论文，demo 用可以宽松>。
**规模**：<N 张图 / N 个样本；train / val / test 各多少>。

**与论文协议的关系**：<版本 v2 与论文一致 / v1 论文报 v2 注意 metric 可能对不上；split 用官方 split 与论文一致 / repo 自定义切法注意>。
**来源**：<URL / 官方 / 镜像；是否需账号>。

**样本（3-5 个真实样本）**：
````

## 填好的示例（单个数据集，深度对照）

**浅（不合格）**：

> ## COCO
> 目标检测数据集，20 万张图，COCO json 格式，官网下载。

**深（合格）**：

> ## COCO val2017
> **是什么**：目标检测 / 实例分割，业界标准 benchmark。
> **在 repo 里的角色**：val benchmark——论文主表数字就报在它上面，**版本必须对齐**。
> **规模**：val 5,000 张（train2017 118K，本次只下了 val 做 eval）。
> **标注格式**：COCO json（`instances_val2017.json`，bbox 为 xywh）。
> **与论文协议的关系**：2017 版与论文一致；split 用官方 val，无自定义切法；预处理按 repo config 的 800px 短边 resize，与论文 §4.2 一致。
> **来源**：官方源（镜像站加速），无需账号。
> **样本**：sample-1 典型街景（5 框 person/car）；sample-2 密集人群（23 框小目标，检测难例）；sample-3 严重遮挡的单车（边缘 case）。

差别：浅的只回答"这是什么数据集"；深的回答了"它对我们的研究意味着什么、要多较真、协议对不对得上论文"——后者才是用户判断"这数据能不能用"的依据。

## 模板使用说明

- **真实样本不是装饰**：用户最大痛点是"不知道数据集是啥"，3-5 个样本让他立刻有体感。图片必须从**真实数据**复制（不是论文里的示意图）。
- **「角色」和「与论文协议的关系」是必填的灵魂字段**：是什么/规模/格式网上都查得到，这两个字段是 setup 实测后才能给的判断——benchmark 数据集版本错了，reproduction 阶段的数字全废。
- **图片路径**：统一放 `images/<dataset>-sample-N.<ext>`，md 里相对路径引用——这样整个产出目录可整体搬动，图片不丢。
- **每个数据集都写**：repo 用到几个数据集就写几个，别只写主要的。
- **和 setup.json 衔接**：setup.json 的 `data` 字段记路径 / 状态（机读），本份讲数据集本身（人读），分工不重叠。
