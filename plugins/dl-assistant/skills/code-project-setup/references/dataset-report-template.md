# 数据集速览模板

本文件说明怎样用项目实际读取的样本介绍本轮准备的数据，让用户看懂数据长什么样、用在哪些入口，以及目前核对到了什么程度。

按[数据与权重准备说明](dataset-prep.md#5-速览与交接)填写。需要产出速览时保存为 `<repo>-datasets-intro.md`，在 `setup.json` 的 `dataset_report` 记录相对路径。入口编号沿用入口调查和执行报告。准备命令、资产的绝对路径和详细日志从 `setup-report.md` 查。

```markdown
{用几句话说明本轮用了什么数据、分别支持哪些入口，以及各项已核查到的范围。}

### 内容与本轮用途
```

## 怎样展示样本

- 从项目实际使用的 loader 取样，保留实际 ID 与划分。同一数据集的多个版本或划分若用于不同入口，分别说明范围和选择依据。
- 图像通常展示 3–5 个就能让用户了解输入与标注，可选典型样本，以及会影响读取或评测的边界样本。原图或标注图允许保存时放到 `images/`，用相对路径引用，例如 `![验证样本](images/vision-val-val-001.jpg)`。做了标注叠加或裁切时说明处理。
- 文本和表格可以展示必要片段和实际字段。音频可展示允许分享的片段或真实波形，并注明时长、采样率和目标。其他模态根据用户需要说明。原始内容受访问或分享条件限制时，写明限制，用允许展示的字段、形状、范围或读取记录说明。
- 速览解释选取的样本及其经过的读取检查。若需判断全量分布、跨划分泄漏或正式比较是否有效，引用对应检查及其覆盖范围。

## 完整填写示例 · edge-vision

沿用[数据与权重准备的 edge-vision 示例](dataset-prep.md#示例--edge-vision-的共用权重与验证划分)。以下项目、样本、数量和结果均为虚构。示例展示可写进报告的样本元信息和依据，实际项目可以按条件附真实图片。

```markdown
# edge-vision · 数据集速览

> 2026-11-24，仓库起点 a17c9d2。核查 E02 评测和 E03 训练所需数据。准备与实跑细节见 [setup-report.md](setup-report.md)。

E02 用 Vision-Val 的验证划分计算分类指标，本轮实跑了专门覆盖最后一批的 17 个样本。E03 用 Vision-Train 的训练划分从头训练，本轮用一个真实批次核了数据读取和一次参数更新。

## Vision-Val v1 · val

### 内容与本轮用途

- 输入和目标 | 每条记录是一张图像和一个类别 ID，目标是预测该图像的类别。
- 对应入口 | E02 验证集评测。保留 v1/val、类别映射和正式评测的指标实现。
- 来源与处理 | v1 发布页的 val 图像和标签。正式配置沿用作者的输入预处理。试跑从原划分提取独立 ID 清单，保留原数据和正式配置。

### 三种范围

| 范围 | 数量和身份 | 依据 |
| --- | --- | --- |
| 发布方公布 | 500 张验证图像，v1/val | v1 发布清单 |
| 本机实际取得 | v1/val 全部 500 张和标签文件 | P04 对照发布清单与落盘文件 |
| 项目实际检查 | E02 用批大小 8 读取 17 个指定样本。修复后 17 个 ID 均进入指标统计，最后一批只有 1 个样本 | tools/eval.py 调用的验证集 loader，configs/setup/eval-smoke.yaml，setup-report.md 中 P05 与 E02 的复跑记录 |

### 与目标协议的关系

已核数据版本、验证划分、标签映射和实际配置。试跑沿用仓库指标实现，输入范围为选定的 17 个样本。第一次运行仅统计 16 个，修复及复跑依据见 E02 的执行记录。全量评测结果及其与论文参考结果的关系交复现阶段核对。

### 样本

| 样本 ID 与划分 | 实际输入或可展示摘要 | 读到的标签 | 选取理由 |
| --- | --- | --- | --- |
| val-001 · val | 彩色图像，640 × 480 像素 | 类别 ID 2（台灯） | 展示该入口常见的图像输入 |
| val-008 · val | 竖幅图像，480 × 640 像素 | 类别 ID 5（椅子） | 核输入预处理能处理另一种宽高比 |

### 待核事项

尚未执行完整的验证集评测。复现阶段使用全量配置核指标协议和参考结果。

## Vision-Train v1 · train

### 内容与本轮用途

- 输入和目标 | 训练图像和类别标签。训练 loader 将图像处理为模型输入，类别 ID 作为损失计算的目标。
- 对应入口 | E03 从头训练，使用 v1/train。
- 来源与处理 | v1 发布页的训练划分及标签。试跑沿用训练配置的数据处理和类别映射。

### 三种范围

| 范围 | 数量和身份 | 依据 |
| --- | --- | --- |
| 发布方公布 | 2,000 张训练图像，v1/train | v1 发布清单 |
| 本机实际取得 | v1/train 全部 2,000 张及标签 | P06 对照发布清单与落盘文件 |
| 项目实际检查 | 用正式训练入口读到一个包含 8 张图像的真实批次，完成一次更新 | tools/train.py、configs/train.yaml 和 setup-report.md 的 P07、E03 记录 |

### 与目标协议的关系

已核训练划分和当前试跑使用的数据配置。一次更新说明这个批次进入了训练流程，完整训练过程和性能待后续核验。

### 样本

| train-023 · train | 预处理后 3 × 224 × 224，通道在前 | 类别 ID 2（台灯） | 查看实际用于训练的输入和目标 |

### 待核事项

## 跨数据集注意事项

E02 和 E03 使用同版本的类别映射。验证集统计和训练更新分别用自己的正式划分。此次核对了配置及试跑样本的标签对应关系，剩余检查范围见各入口报告。
```
