# 数据、权重与派生文件准备

本文件说明怎样准备各正式入口需要的数据和权重，从核对来源、版本和划分开始，做到项目能实际读取数据、按预期加载权重，并留下可复查的记录。

按[运行手册 Step 4](workflow.md#step-4-建立或恢复-setup-分支准备环境权重和数据)和已审阅的 spec、plan 执行。先复用选型和入口调查里已确认的来源，再按本机的文件、配置和实际运行结果核验。

## 1. 核对资产身份，再获取和校验

从入口编号反查实际配置、loader 和权重加载路径。为每份资产记录适用入口、用途、发布来源、版本或 commit、划分或模型配置、目标路径、访问条件及发布方校验值。共用同一身份的资产只准备一次。不同版本、划分或模型变体分别记录。

先查现存文件、共享目录、缓存和正在运行的下载，核对它们的来源和版本。空间检查覆盖实际下载、缓存、解压和派生文件所在的盘。按实际路径选择以下命令。

```bash
df -h "$asset_dir"
ls -lh "$asset_file"
du -sh "$dataset_dir"
# 从可信发布方取得校验清单后，在清单对应的目录核验。
sha256sum -c SHA256SUMS
# macOS 可用等效命令。
shasum -a 256 -c SHA256SUMS
```

- **缺文件时获取。** 公开资产在获准范围内查源、下载并核对。认证、限流、网络和源文件缺失按[网络与镜像](../../dl-assistant/references/network-mirror.md)处理。大文件按[长任务启动与恢复](workflow.md#长任务启动与恢复)执行，先查原会话和产物，再沿同一来源、版本和路径续传。半截文件与已校验资产分别记录。
- **分开核文件与内容。** 对照实际大小、文件类型、发布方校验值和分片清单。压缩包按实际格式先检查目录结构，例如 tar 包用 `tar -tf "$archive_file"`。解包后核预期目录、标注、分片和文件数量，再进入项目读取验证。自己计算的哈希可以标识当前文件，缺少可信参考时将原版一致性写为待核。
- **遇到需用户处理的访问条件。** 先核是否已有授权、可用官方来源或相同版本的合法副本。仍需申请权限或接受条款时，一次说明资源、发布版本、用户需要做什么、文件应放哪、预期目录结构和拿到后如何验证。凭据用项目认可的私有方式配置。其他可独立准备的入口继续。

## 2. 数据格式、预处理与划分

### 先读实际数据入口

从入口的最终配置追到 loader 和预处理脚本，核清原始数据版本、划分、样本或组 ID、标签与单位、排除规则、预期目录和文件名。沿配置继承、命令行覆盖、环境变量和默认值确定实际生效的路径。作者已有 `preprocess.py` 或 `prepare_data.sh` 时，先看所需依赖、输入、参数和输出，再按审阅过的方案执行。

### 转换或预处理后逐项比对

保留原始数据，派生文件另存。记录输入和输出的身份、转换脚本及版本、参数、样本清单和输出位置。对照实际数据定义检查以下项目。

| 检查 | 怎样核对 |
| --- | --- |
| 样本身份和数量 | 对照转换前后 ID 或身份映射、数量、遗漏和重复。有意过滤时保存规则和受影响清单 |
| 标签、坐标和单位 | 按字段核实际含义。例如检测框的 `xyxy` 和 `xywh`、类别 ID 映射、分割编码、音频采样率或时间单位。抽查真实样本和目标值 |
| 划分与组 | 对照官方清单和项目读取到的划分。按数据定义检查同一个体、视频、场景等是否跨越应独立的集合。需要固定划分时保存其清单 |
| 项目实际读取 | 用同一入口配置和项目 loader 读取真实样本及批次，核 ID、标签或目标、数量、形状和单位。中间文件通过结构检查后仍需验这一步 |

路径修正按批准范围处理。新的样本排除、标签修正、单位变化或重新划分会影响比较时，先说明触发样例、受影响入口及验证方法，回 Step 3 确认。根据本轮比较条件判断数据版本和协议需要保留到什么程度。

## 3. 用项目读取路径验证，并排查空集合或缺样本

先用最终配置查看实际根目录和划分清单，再用项目 loader 读取真实样本和批次。保存输入的样本 ID、读回的目标或标签、实际数量和错误位置。有条件时核哪些样本最终进入统计或输出，让读取与后续执行的范围可复查。

| 观察 | 排查顺序 |
| --- | --- |
| 找不到文件或路径仍指向作者机器 | 从实际命令和展开后的配置找根目录及覆盖来源。用 `rg -n -e data_root -e data_dir -e dataset_root configs scripts tools` 查项目中存在的相关目录，回读硬编码路径和命令行默认值。用 `ls -ld "$dataset_dir"` 确认修正后的真实位置，再复跑读取 |
| loader 返回零样本或比预期少 | 先核解析后的数据根目录、实际选中的 split 和清单。再查目录层级、后缀和文件命名、过滤规则与预处理日志。记录是输入清单为空、文件无法匹配，还是样本在读取或筛选时被跳过 |
| 样本数一致但数据内容不对 | 比对真实返回的 ID、标签、单位、划分及配置。用实际资产版本核预处理与映射，必要时抽查原始文件和派生结果之间的对应 |
| loader 读到样本但评测记录变少 | 检查批处理、最后一批、抽样器、分布式汇总和指标输入。将选定清单、实际读取的 ID 与参与统计的 ID 对照，找到丢失位置 |

清单是每行一个 ID 且无表头时，可先用 `wc -l "$split_manifest"` 看规模，用 `LC_ALL=C sort "$split_manifest" | uniq -d` 查重复。CSV、JSON 和有分组的清单按实际格式解析，再比较身份和数量。行数和目录存在用于定位，最终状态以项目实际读取为依据。

### 为试跑准备可复查的小样本

从正式划分中取真实样本，记录数据版本、split、选择规则或随机种子、样本 ID 和单独的试跑配置。可以特意包含边界样本，例如不满一批的数据。保留项目所需的布局和标注关系，让同一 loader 能读取。明确试跑实际覆盖的行为和输入，完整划分的训练、性能或覆盖另行验证。

## 4. 权重身份与实际加载

1. **先核应该加载什么。** 从发布记录、入口配置和代码确认模型结构及变体、训练阶段、权重版本、文件或分片、使用的参数范围。核清该入口是从头训练、读取初始化权重、恢复训练，还是加载用于推理与评测的模型。在实际配置中定位模型、主干和可能分别加载的适配器。
2. **走真实入口的加载逻辑。** 记录解析后的文件路径、实际模型配置和加载结果，核关键参数及缓冲区、缺失键、多余键、形状不匹配和有意重新初始化的部分。按具体框架跟踪它如何报告未覆盖项。涉及分片、量化或适配器时核分片是否齐全、底座与适配器是否对应，以及入口实际上启用了哪些组件。
3. **查实加载效果和验收边界。** 若失败，先核文件身份和完整性，再核配置与参数名、形状及载入位置。即使加载未报错，也要核关键组件的实际覆盖。名称映射保留转换规则和未覆盖项。放宽加载、换模型或改初始化可能影响训练或比较时，说明影响后回 Step 3。用真实输入完成计划要求的最小调用，保存权重加载和入口结果的对应证据。

例如，项目允许部分加载时，脚本可能成功返回，但日志显示分类头所需键缺失。先核这个 checkpoint 原本是整模型还是仅主干权重，再对照当前配置的用途。如果本轮要验发布模型的推理，分类头仍是新初始化时就记录未通过。若作者明确规定这里应替换分类头，则按该入口的实际目标和批准条件核这项替换。

## 5. 速览与交接

在 `setup-report.md` 和 `setup.json` 对应资产与入口记录中，分别填写来源和版本、目标路径、获取与校验结果、实际读取或加载、受影响入口和未决项。上游有实测待办时逐项说明观察结果是否回答了原问题。有未知就保留并写清下一步由谁接手。

按[数据集速览模板](dataset-report-template.md)从项目的真实 loader 取本轮已准备的数据样本，展示适合当前数据类型的输入、标签或目标，注明样本来自哪个划分。按实际使用和分享条件保存图像、文本或其他内容。

## 示例 · edge-vision 的共用权重与验证划分

沿用[入口调查报告](entrypoint-report-template.md#完整填写示例--直接试跑论文仓库)的虚构项目。

1. **核资产与入口。** 从 r1 发布页和实际配置核 E01 推理、E02 评测、E04 单张轨迹共用 Vision-S r1。E02 另外需要 Vision-Val v1/val，E03 从头训练，需要 Vision-Train v1/train。已有资产按实际版本核对，共用权重只获取一次。
2. **核落盘与读取。** 将发布文件名、大小和可信校验值与本机文件比对。按配置核训练和验证清单、目录和标签映射，分别用真实 loader 读样本，记录 ID 和划分。用 E01 实际加载 Vision-S r1，核预期模型及分类头都读到了相应参数，再运行单张推理。E02 与 E04 各自试跑时还要核实际使用的是同一份权重配置。
3. **保留覆盖最后一批的试跑配置。** E02 从 Vision-Val v1/val 选 17 个真实样本，保存 ID 清单，用独立试跑配置设批大小 8。落盘原配置、试跑配置和清单。验收时对应样本读取与统计输出，预期这 17 个 ID 都进入指标计算。
4. **定位剩余差异。** 若日志只统计了 16 个，先对照原划分、试跑清单和实际 loader，确认数据已正确到位，再查最后一批在哪丢失。若修复会改变统计口径，回 Step 3 确认。通过后只记录这 17 个样本的评测路径已验，完整验证集的参考结果交给复现核对。
