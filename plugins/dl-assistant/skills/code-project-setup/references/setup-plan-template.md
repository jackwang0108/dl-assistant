# 执行计划模板

保存为 `setup-plan.md`，根据同一版准备规格编写，两份文件一起交审。任务拆分、命令准备和完整示例见[准备规格与执行计划编写指引](setup-spec-and-plan.md)。

## 可复制的执行计划

````markdown
# {仓库名} · 执行计划

## 范围与执行顺序

- 对应材料 | {入口报告与准备规格的路径及版本、当前代码起点、目标机器。}
- 本轮交付与范围 | {受影响的入口、验收范围、计划使用的资源和允许的改动。}
- 工作分支与环境 | {准备分支和起点、工作目录、计划使用的解释器或容器入口。}
- Git 交接 | {本轮提交的文件范围。建议合回开工时的项目分支，写明实际目标分支和是否纳入本次批准。若只交付 setup 分支，写明该决定。}
- 执行顺序 | {先后依赖、可共用的准备任务、确实受阻时可独立推进的部分。}

| 任务编号 | 可核查产出 | 对应 spec 交付、资产或验收 | 入口编号 | 前置任务 |
| --- | --- | --- | --- | --- |
| {任务编号} | {产出或验证结果} | {章节及条目} | {E01、E02 等} | {任务编号或无} |

## 任务详情

### {任务编号 · 任务名称}

- 目标与关联 | {要实现的产出、对应 spec 验收和入口编号。}
- 前置条件 | {前置任务、版本、设备、环境、输入与所需授权。}
- 执行与检查命令 | {工作目录、实际解释器或容器、完整命令及输入和配置。若参数仍待核，写明取值依据及此任务的启动条件。}

```bash
{填写已核对的命令；此处仅为占位}
```

- 完成条件与证据 | {看哪些结果，怎样比对，产物、日志与执行报告写在哪。}
- 资源与托管 | {时间、空间和设备依据。长任务填写目标机器、会话名或调度器提交方式、日志路径、启动与恢复检查。}
- 异常及处理 | {如何判断失败，允许的恢复或替代，何时回 Step 3 确认。}

## 交付核对

- 已覆盖 | {环境、数据、权重和可运行入口分别关联到哪些任务。}
- 留待处理 | {暂缓或不适用的入口与交付、受阻条件、后续责任。}
- 执行记录位置 | {setup-report.md、setup.json 与日志位置。执行时按任务编号和入口编号回填。}

## 审阅记录

{对应的 spec 与 plan 版本、用户实际答复、批准范围，或待确认。}
````
