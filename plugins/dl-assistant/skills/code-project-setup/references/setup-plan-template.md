# 本轮准备与检查计划

保存setup-plan.md，引用spec及实际授权。按依赖和可核实产物分任务，不强制T1—T8、固定层数或最后merge。简单任务可在spec内明确引用，不为重复材料增加确认。

```markdown
# 准备执行计划
> 来源spec/授权、项目与组件版本、资源边界、当前已完成项。

## 任务总览
任务ID | 对应操作/R需求/survey实测ID | 产物或检查 | 依赖 | 状态 | 成本依据/未知

## {任务ID}：{具体操作}
- 目的、负责范围与关联组件。
- 当前已知、剩余未知，哪些材料已核实，哪些需实际下载/运行。
- 实际动作、目录/环境、输入资产/版本和候选入口；未跑命令标未验证。
- 检查对象/输入条件、预期与依据、要保存的观察、成功只能支持什么范围。
- 相关数据/加载/计算改动、对应检查与授权；超出范围时返回准备/选型/研究讨论。
- 日志、输出、代码/config/diff、最小检查脚本及环境记录保存位置。
- 预算/停止条件，失败/阻塞或需要调查时如何处理，不编结果。
- 复用条件与恢复办法，如何确认已有任务结束/输出完整，避免重复启动。

## 汇报与交接
按任务即时保存实际操作/结果和偏差；每个survey任务均回应，不属于setup的保留责任。
交接前自查：证据可追溯、范围不夸大、改动已验证、未决项有责任和下一步。
是否提交/merge/push按项目约定和已有授权，不作为操作就绪的通用前置条件。
```

可用任务类型：现场/版本核对，环境和必要网络访问，资产完整性与读取，组件行为，真实入口，资源/随机性观察，报告交接。无必要的不做；数据读取需要实际环境时正确记录依赖，不能机械沿用旧T编号。

几步训练、极小子集或--help只覆盖其各自范围。改变输入/步数的检查配置单独保存；不为得到预期结果不断调参数。调查依据不足、重复失败无新信息、超预算或需改设计时及时汇报，用户无需全程在线。
