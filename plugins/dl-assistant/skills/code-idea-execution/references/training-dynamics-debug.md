# 训练与测量异常诊断

本文件说明怎样从训练或测量的实际异常出发，定位最早出现偏差的环节，选择能区分可能原因的检查，并记录排查结果及其对本轮实验的影响。

在[运行手册 Step 3](workflow.md#step-3-准备实现并审阅开跑条件)的实现检查和 [Step 4](workflow.md#step-4-登记并按阶段执行)的正式运行中使用。组件基础行为见 [setup 的组件与数值检查](../../code-project-setup/references/numeric-sanity.md)，与参考结果的可比性及差距见[复现差异排查](../../code-paper-reproduction/references/trust-traps.md)。

## 1. 先保留现场，确定异常最早在哪里

1. **留住原记录。** 从实验和 run 记录取命令、代码 commit 或 diff、生效配置、数据和权重、设备、seed 或重复编号、日志与退出状态。保存原始读数和最近的可用 checkpoint。先确认原任务是否还在运行，再决定是否做独立诊断。
2. **定位第一次异常。** 从日志和产物确定最后正常及首次异常的位置。训练注明 epoch、microbatch 或优化器更新步，分布式任务还记实际 rank。评测或测量注明样本 ID、分组、计时区间和实际设置。记录触发样本、分项 loss、学习率、精度及恢复来源等相关条件。
3. **写下要区分的原因。** 把观察、可能解释和待核条件分开。例如「loss 有值但第 37 次更新后参数不变」，下一步先区分目标参数没有梯度、梯度有值但未执行更新，以及确实发生了更新但观测点不对。
4. **用最小能重现问题的检查。** 尽量固定输入、起始权重、配置和执行路径，只改变或观察拟检验的因素。简化条件后仍需保留异常触发点。另存诊断配置与运行记录，注明和原实验的差异。

如果运行日志有带步数的异常记录，可先用下列命令找前后文。将变量设为本次运行的实际日志，从命中的行回查对应的更新步、样本或 rank。

```bash
rg -n -i -C 3 -- '\bnan\b|\binf\b|non[- ]?finite|overflow|skipp(ed|ing)' "$run_log"
```

日志可能只报告最后发生的错误。用上游观测确认最早的异常，保存实际命中的位置及仍未查到的环节。

### 需要查看运行时状态时用断点

用一个要区分的问题来选断点。例如要区分「配置没加载」和「配置已生效但数据走了另一分支」，就停在配置解析处和首次进入分支处，观察实际配置和输入。能从日志确定原因时直接记录。需要看实际调用栈、局部变量或异常现场时，如果当前会话有 `mcp-debugger`，按独立安装的同版本上游 skill 操作。工具不可用时，可用项目已有调试器或局部诊断脚本核同一问题。

1. **绑定实际运行条件。** 从原 run 或 `setup.json` 核对解释器、工作目录、入口和参数。Python 调试时确认该解释器有 debugpy。优先用同一入口或失败测试，使用能触发偏差的最小输入。缩减数据、步数、精度或进程数时，记录差异，并核是否仍触发同一现象。优先启动独立诊断进程；需要暂停现有任务时先核批准范围和暂停对进程及其他 rank 的影响。
2. **定位首次偏离。** 从最后一个已知正常点和第一个异常点收窄范围。每次只查能区分原因的值，记实际文件和符号、栈帧、变量和触发条件。分布式问题记录实际 rank 和进程，单进程结果只覆盖实测路径。结束时关闭自己启动的调试会话。
3. **复核并留证。** 修正后用同一触发条件复跑，再执行相关常规测试或按获批方案重新取证。沿用现有实验报告和尝试记录，关联原 run，保存诊断命令、配置、代码版本、断点、修正前后观察与输出位置。临时材料可放 `scratch/`。涉及计时、吞吐或分布式同步时，用正式测量协议重新采集对应读数，诊断记录用于解释原因。

## 2. 按实际症状选检查

| 实际观察 | 从哪里查，保存什么 | 接下来怎样判断 |
| --- | --- | --- |
| 训练第一步或刚换数据就异常 | 从真实 loader 取输入、ID、标签或目标、掩码，核预处理和增强前后对应关系。查当前初始化、实际权重加载、未加载参数及分项 loss 的输入 | 比较同一输入下各分支的输出和分项 loss。若最早差异出现在数据准备，先追到产生该字段的变换或拼批 |
| loss 有值，目标参数没变化 | 查目标参数是否参与计算、梯度状态、冻结标记、优化器参数组及更新调用。对照梯度累积边界、学习率和精度相关的跳步记录。保存同一次更新前后的参数观测 | 区分未传到梯度、梯度为零、未调用更新、更新被跳过，以及更新已发生但观测精度或位置不足。用模型与目标的实际预期解释梯度量级 |
| 某次更新、学习率切换或续训后才异常 | 将曲线按实际更新步对齐，核调度器调用、学习率、输入及数据覆盖。查 checkpoint 是否恢复了模型、优化器、调度器、精度状态及相关随机状态 | 若只在切换后出现，试着从最近可用状态重现切换，记录切换前后实际差异。恢复状态不全时，在解释前注明影响 |
| 出现 NaN 或 Inf | 从输入和当前权重开始，按实际调用顺序记录激活、分项 loss、梯度和更新前后的有限值情况 | 找首个非有限值及其输入。当时所有更早已查量都有限时，优先追该算子、掩码、归一化、分母或精度路径 |
| 训练读数正常，评测指标或分组异常 | 先查实际评测权重、样本覆盖、后处理、分母和聚合口径。用同一份预测和标签重跑相关统计，或对照实际的评测入口 | 定位差异首先出现在权重选择、数据与预测，还是测量和统计。从所查范围解释读数 |
| 只在某类输入、更多样本或更长训练下异常 | 查异常批的样本及增强、实际张量形状、分组组成、训练阶段和配置。逐项扩展会触发问题的条件 | 例如问题在累积结束才出现，检查必须走到真实更新；问题在末批才出现，检查必须覆盖末批。按观察界定已核范围 |

已确认适合单批次拟合检查时，先写该任务的预期行为和前提。固定一小批样本，用实际前向、损失和更新路径记录变化。观察到拟合只说明该设置下的学习行为。若未观察到预期变化，先核目标、随机增强、正则、冻结和更新，再判断需要检查哪里的实现。

## 3. NaN／Inf 从首个非有限值查起

1. 按实际执行顺序核输入和当前参数、关键前向中间量、各项 loss、梯度及更新后的状态。先用已有逐步日志缩小阶段，再针对少数候选模块加临时记录。每条记录写步骤、模块、张量名、形状、数据类型、有限元素数，并保留会区分原因的实际量，例如掩码有效项计数或归约分母。
2. 在可重现的诊断中，用同一输入、起始权重和计算路径比较实际精度及获准的 FP32 设置。记录精度修改的实际范围。FP32 下恢复正常时，优先回查该精度路径的算子、量级、缩放和更新处理。两种情况下同一环节均异常时，继续核共同输入和计算。
3. 先取能够区分原因的证据，再提出修改。变更 `epsilon`、`clamp`、梯度裁剪、学习率、精度或 batch 时，写明会影响哪些样本、计算或比较条件。超出已批准的设计或调整范围时，带具体影响和验证计划回审。
4. 采用修正后，先复跑异常触发点，核原来第一个非有限值出现的位置，再复跑相关的正常路径。需要用于正式取证时，在已确认的实际配置及范围内重新收集结果。

## 4. 记录尝试、停止点和证据影响

每次排查在对应实验下记录实际命令、配置、输入、代码、起点、所改诊断条件、观察及输出位置。涉及恢复时，核新尝试真正恢复了哪些状态。用实验报告说明已查证据支持或削弱哪个解释、哪些问题仍未知、哪些运行仍可用于原比较。

原问题已能用证据定位，或下一项检查会改变决定时，按当前授权推进。反复出现相同错误且没有新证据、预计超预算、关键条件无法保留或需调整研究设计时，向用户汇报已试路径、首个异常位置、剩余解释、建议及成本。结束时把执行或测量障碍和对证据范围的影响留给 iterate。

## 示例 · 第 37 次更新出现 NaN

以下为虚构训练案例，用于说明怎样从原始运行追到一个可核的问题。

| 尝试 | 固定什么、查什么 | 实际观察及下一步 |
| --- | --- | --- |
| `train-attempt-01` | 保留正式命令、日志、实际配置与完成第 36 次更新后的 checkpoint。记录第 37 次更新所用样本及掩码 | 日志首次记录辅助 loss 为 NaN。先围绕该更新查输入和分项 loss |
| `diag-attempt-01` | 核 checkpoint 的实际恢复范围，使用同样输入、掩码与精度重现。记录输入、前向中间量及分项 loss | 输入和进入归约前的观测均为有限值，首次异常出现在辅助 loss 的掩码归约。记录归约位置和分母 |
| `diag-attempt-02` | 在获准诊断范围内改用 FP32，保持起点、输入和同一归约，核实际执行路径 | 两次检查都在同一处出现 NaN。源码和打印值显示这一批的有效项数和掩码后的损失和均为零，归约执行了 0/0。两次精度对照帮助把调查聚焦到共同的实现和输入 |
| 修正与复核 | 查数据定义和已批准的 loss 规则，说明空掩码应如何统计。若原方案未定义，提出处理建议并确认对样本贡献、分母和比较的影响 | 获准后用原触发输入核新行为，用非空掩码样本核原计算，再按批准配置从可验证状态复跑受影响范围。原失败尝试保留，记录哪些正式比较需要重新取证 |

向用户汇报时说明「第 37 次更新的异常已定位到空掩码的辅助 loss 归约」，并附两种精度的实际观察及源码位置。修正能支持的结论是该触发条件和已复测路径的行为，原方法假设仍需相应实验取证。
