# 训练与实现异常排查

用于定位执行和优化问题，不能从一次调试推断科学假设是否成立。按症状选择必要检查，保留每次尝试与条件，不能为追求好结果无限调参。

## 小样本检查

小batch、简化增强、已知答案/恒等分支、输入输出形状、梯度依赖等检查有助于定位问题，但“能过拟合”不证明代码正确，“不能过拟合”也不证明有bug：正则化、随机目标、不可实现任务和优化困难都可能导致。先核对目标和约束是否允许预期行为。

## 检查顺序

1. 数据：样本、标签/目标、划分、预处理与增强是否对应，打印或可视化实际输入。
2. 计算：分项loss、张量维度、mask/梯度、冻结参数、权重加载的缺失键是否符合设计。
3. 数值：定位首个非有限值；使用可比较的精度对照，检查算子、缩放与梯度。FP32不报错只是定位线索，不证明混合精度溢出是唯一原因。
4. 优化：学习率、初始化、schedule、batch与目标是否匹配。小规模对照必须在允许调整和预算内，不能在测试结果上挑最优设定。
5. 规模：逐步扩样本或长度、定位何时异常，同时检查数据和条件变化；不能由“100 batch失败”直接断言唯一根因。

梯度幅度没有通用阈值，参数、归一化和尺度都需考虑。clip、clamp、epsilon、精度、batch改变可能影响训练/测量语义，记录改动、对照与需重新确认的设计。

反复相同失败无新信息、预计超预算、对照无法定义或需改科学设计时及时上报：已试什么、错误/日志、当前解释与替代解释、建议和成本。可靠数据与代码检查仍不足时，结果标执行/测量未核实，不写成方法无效。
