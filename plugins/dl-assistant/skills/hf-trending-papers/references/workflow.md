# Hugging Face 论文观测流程

本文件说明怎样确定查询范围、核实际 JSON、分类和补查重点论文，并把平台关注度、研究内容和阅读建议分开保存。

## 1. 确定查询和阅读范围

沿用用户给的日期、周、月、主题或最近热门，以及已有的研究问题。相对日期在用户时区解析为具体日期并告知。保留原始说法、时区和发送给 HF 的实际参数。官方窗口边界未知时记未知。周按实际 ISO 周，月按年月；主题搜索与热门榜按实际模式独立记录。

快速浏览从列表开展。完整分析默认对有明确阅读或核查理由的 5–10 篇查详情，可按用户任务调整；未补查的论文保持列表级记录。推荐名额通常 3–5 篇，是给用户的阅读顺序。

## 2. 调用 CLI 并保存实际返回

按 [命令速查](hf-cli.md)核本机版本与相关帮助。先按已确认范围调用一次，保存 JSON 和退出状态。下面以明确日历日期为例，`run_dir` 和 `hf_date` 用实际值。

```bash
mkdir -p "$run_dir/raw"
hf papers ls --date "$hf_date" --limit 50 --format json > "$run_dir/raw/001-list.json.part"
```

仅在退出成功且核 JSON 顶层和条目身份后，将临时结果保存为 `raw/001-list.json`。列表和搜索核数组，单篇详情核对象和与请求一致的 ID。正常空数组、进程失败和 JSON 结构变化分别记。原日期不可用时保留实际报错和该日期；报错若给出最新日期，只作可选查询。访问失败按手册处理，单篇失败时其余可用结果继续。

用[请求记录模板](request-log-template.json)逐次登记实际命令、版本、获取时点、窗口解释、排序、上限、数量、请求状态和原始文件。达到上限或覆盖未知时按有限样本报告。原始凭据值留在认证环境。

## 3. 分类并按需查重点论文

1. 先用稳定 arXiv ID 去重，保留实际版本及出现的来源。摘要级按具体问题、方法或数据场景分类，允许只有一篇或属多个话题。每篇至少注明话题或「待分类」。
2. 完整分析对选中论文分别执行 `hf papers info <arXiv-ID> --format json`，记各请求获取时间，保留成功、失败和未查的 ID。对照原始摘要后再用平台生成的 `ai_keywords` 或 `ai_summary`。区分作者报告、平台生成说明和本次判断。
3. 对关注度和资源单独对账。按稳定 paper ID 处理论文，按规范仓库地址处理仓库，按模型、数据集各自的 ID 处理资源。仓库由多篇论文关联时，话题或全局统计只计相应范围内的同一仓库一次。详情只返回部分 ID 或只有总数时，报告已见的去重资源或逐篇总数，并注明范围。
4. 保存实际字段状态。明确的 `0` 写数值 0，字段缺失与显式 `null` 分开。列表和详情同一指标值变化时各保留一次观测及出处。机构只使用实际可核字段，说明可见样本及缺失。

## 4. 写阅读建议，按需对比可比历史

每篇重点推荐分别写「平台观察」「研究内容与为什么值得读」「阅读时核什么」。例如作者说记忆模块改善长上下文任务，阅读问题可写成「对照的输入长度和计算预算是否一致，消融是否能区分新增记忆的收益？」只有摘要时注明这是待核问题。定位到真实章节时再写阅读位置。

有历史时先核当前和历史的查询类型、范围、窗口长度、是否结束、排序、limit 和获取时点是否可比。用定义、关键词和研究问题对齐话题。逐窗报告样本篇数、占比和缺失。重叠窗口标同一论文的重复出现；同窗重跑选定一份观测用作窗口统计。只有同一论文在相近口径下有多次指标观测时才报告累计值差异，写清两个获取时间。

## 5. 保存与续做

按[报告模板](report-template.md)保存 `radar.md`，按需保存[逐篇快照](radar-snapshot-template.json)。报告给实际原始记录、已查详情范围、推荐名单和未核事项。续做先核请求记录、样本和成功文件，再处理待补详情或缺失分类。后续给 paper-reading 的交接记录包含稳定 arXiv ID、已核版本或版本未知、原始来源和具体阅读问题。
