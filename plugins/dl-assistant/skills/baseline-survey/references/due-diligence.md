# 选型调查与验证分工

先对应当前研究或复现需求，再核查工程事实。不要求固定候选数或为每个候选完整读一遍所有代码。明显不合必要条件的可以有依据地排除；未知不等于不匹配，也不能伪装为支持。

## 1. 研究适配性与证据

以R编号列必要观察、对照、数据/模型条件、测量定义、资源约束。每候选逐项判断supported_by_sources/mismatch/unknown/not_applicable，附文件/配置/原文位置、版本、依据类型、未验证部分与影响。supported_by_sources仅指当前来源支持，不表示运行正确。

不能只看模块名称。追到必要输入输出、数据预处理/排除、模型内部状态、梯度/干预、指标实现和聚合；判断实际接口是否支持测量，是否需要改核心方法，是否会破坏对照。动态注册和复杂依赖无法从当前文件确认时，记录边界和所需查证，不补造调用关系。

纯复现根据明确论文/配置定义需求；理论检查、纯分析和数据处理按实际需要，不强制训练、官方checkpoint或已有benchmark分数。引用的参考结果必须与当前待验证组件和协议相关，不能拿无关model zoo指标代表研究测量已可信。

## 2. 代码与工程条件

读取相关依赖清单、配置、入口和关键实现，不只看README。列重要版本约束、编译扩展、硬编码路径、外部服务/硬件依赖、真实扩展点；不常见依赖解释其作用与当前相关性。

调用路径只记录实际追到的文件/函数：训练、评测、数据或测量中哪些相关就查哪些。每条标源码核查/推断及未运行。tests、CI、日志、配置和社区活跃度是辅助信息，不证明科学正确；少量代码也可能足够，框架成熟也不保证适配。

工程成本记录所需改动、依赖/资源依据和未知。低/中/高需说明参照范围；没有机器实测不编显存、耗时和确定安装成功。不为容易实现的方案擅自改变本轮问题。

## 3. 权重、数据和许可分别核查

- 权重：模型/训练阶段、发布revision/文件名、配置、来源、已公布校验值、加载格式与申请/认证条件。无checkpoint对纯分析不一定构成问题，是否必须自训取决于取证需求。
- 数据：版本、split/样本ID、预处理/增强/排除、目标/标签、采样与指标定义；来源、获取条件和已知问题。协议差异现在可通过源码查证时直接查，不只交下游“检查数据”。
- 许可：代码、模型、数据分别给原始条款来源、版本与针对用户用途的明确限制。未声明/未取得/范围不清楚分别记未知；仓库许可不自动覆盖下载的权重或数据，不给超出条款依据的可用保证。

浏览到发布页面或文件清单只证明取得这些信息，不证明完整文件可下载、无损坏、可加载。认证/限流/网络故障不是资源不存在的证据；记录实际访问范围。下载和加载验证交setup，不在survey试装或跑模型。

## 4. 社区记录与来源身份

官方身份用作者主页/论文项目页与仓库关系核查。社区成功/失败记录逐项给issue/讨论/复现链接、日期、代码/权重/数据版本、配置/指标、报告结果和处理状态。不知道条件就保留未知，不把报告当本次验证。相互转述去重，不按抱怨数量判断不可用。

没有记录不表示可靠；解决了旧问题不证明当前环境没有问题。stars/更新频率可辅助判断维护成本，不替代研究适配、源码和实际协议。

源码链接优先绑定commit或不可变发布revision；未能定位就明确未固定版本及影响。tag/分支可能变化，记录当时解析到的commit（可取得时）。所有来源标实际读取时间和范围，不把搜索片段当全文核实。

## 5. 缺少完整实现或需要组合

有论文/作者声明、代码引用或具体实现证据才记录代码来源关系；找不到就未知，不假定有某个旧仓库稍改即可复现。对替代实现列已知差异、未明确设计、权重兼容、成本依据与剩余未知。

路径/格式适配与重建核心算法分开。需要重建方法或改变数据/比较时交研究设计讨论，再安排实现与验证，不隐含授权setup/reproduction自行设计。找不到合理方案可以停止推荐或申请有范围的实现可行性调查，不无限寻找替代。

组合候选需额外核查模型接口、表示/单位、数据身份与划分、预处理、版本和许可条件能否一致。分别可用不表示组合可用。保留每组件的角色和验证目标，不把多个组件压成一张“主仓库已选”记录。

## 6. survey现在做什么，后续做什么

| 项目 | survey现在完成 | 后续真实验证 |
| --- | --- | --- |
| 权重 | 核查发布身份、配置/版本、文件清单、访问/申请条件与声明校验值 | setup实际获取、校验完整性并检查加载；成功加载仍不代表性能对齐 |
| 数据 | 查源码/文档中的版本、split、预处理和指标差异 | setup核实际文件/样本、预处理与loader；reproduction按对应协议核结果 |
| 模型内部量或干预接口 | 读必要forward/输出/hook等代码，确认静态可见支持和限制 | setup可做批准范围的接口/形状检查；若涉及新增科学测量或干预实验，交研究设计与execution |
| 依赖与入口 | 查版本约束、编译需求、实际配置和入口，不伪造ready命令 | setup在真实环境安装、最小运行与数值检查 |
| 参考结果 | 摘确切模型/权重/数据/split/指标/协议/原文位置，确认它与目标组件相关 | reproduction核评测或训练可信范围；没有恰当参考数时先定义其他有效验证，不能编造主指标 |
| 方法重建/设计变化 | 查明缺失设计、差异、成本依据及影响 | 返回idea-find/iterate讨论设计，批准后交execution；不是普通setup任务 |

首批实测任务不是未完成调查的通用待办。每项必须指向具体剩余未知和调查依据，并说明判定方式；无法定数值界限就说明需要哪些可信参照，不填任意阈值。按依赖先做有必要的低成本检查，关键不匹配时暂停依赖任务，而不是先下载/训练全部内容。

自查时用反例检查行动：成熟框架不能取得必需状态量，就不能因易安装而推荐研究使用；README列权重但未下载，只能说有发布信息；明确原样复现且唯一官方实现无需凑替代；没有候选合适可如实不推荐。能力未知但可用预算明确的接口测试判断时，可以条件推荐先做准备验证，不称研究已就绪。
