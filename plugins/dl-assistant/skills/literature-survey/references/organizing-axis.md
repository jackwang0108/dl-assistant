# 文献分类与详细阅读分工

本文件说明怎样根据实际找到的论文提出分类、判断何时需要补查或调整，并把用户确认的分类变成逐篇可执行的阅读任务。

按 [运行步骤](workflow.md) 的 Step 3 提出并确认分类和阅读方案，Step 4 执行阅读，Step 5 用新增论文重新核对受影响的部分。分类维度是组织文献的依据，例如按方法、要解决的子问题或适用条件组织。先给能回答用户当前问题的暂定分类，说明依据和局限。

## 一、从候选论文提出分类

1. **确定分类要帮助用户回答什么。** 从 `spec.json` 读取本次用途、范围、纳排条件和用户关注的问题。选技术方案时可能需要比较设备上的代价。定位已有工作时，可能更关心哪些论文采用了相近的机制。
2. **用候选论文提出初分。** 查看 `pool.json` 的纳入项、标题、摘要或 `approach`。字段冲突时回查 `observations` 指向的原始批次。身份或范围尚待核实的论文可供了解边界，继续标为待核。标题和摘要足以提出临时分组，涉及机制、设置和关键假设时还要核对原文。
3. **挑有区分力的论文验证。** 各重要类别选能说明其特点的代表作；再查容易跨组的边界论文，以及可能改变现有划分的相关近作。用 [tex-mcp](../../tex-mcp/SKILL.md) 或 [pdf-mcp](../../pdf-mcp/SKILL.md) 定位决定归类的章节、图表或评测设置。读到足以区分该项内容即可；证据还不足时注明需要核对什么。引用数可帮助定位已被广泛讨论的工作，代表性仍按论文内容判断。
4. **准备呈现给用户的划分。** 为每类给一个能说明分类依据的例子，说明交叉项、未分类项和仍缺的证据。用户给出调整意见后，只重查受影响的分类和阅读任务。

## 二、按问题选择分类维度

| 用户要回答的问题 | 可选主维度 | 怎么验证这套分法有用 | 容易出现的问题 |
| --- | --- | --- | --- |
| 现有方法具体怎么做，我的方案最接近谁？ | **方法或机制** | 比较实际改动的组件、推理过程或训练目标，判断各方法是否有可描述的差异。 | 仅凭论文给方法起的名字归类；同一工作采用多种机制时可加交叉标签。 |
| 这个方向有哪些子问题，分别有哪些解法？ | **研究问题或任务环节** | 能具体说出每组在解决什么，例如数据稀缺、遮挡处理或跨域评测。涉及任务定义、训练、推理和部署时，可按这些环节划分。 | 把方法名称和所解问题混在同一层级。若两者都重要，选一个主维度，另一个作标签。 |
| 哪些方案适用于我的设备、数据或成本约束？ | **适用条件与取舍** | 原文有可核对的模型、数据、假设、评测对象或资源条件，能解释在何种条件下可比较。 | 用不同设置下的指标直接排序；条件未知的论文先标待核。 |
| 这个领域怎样发展，重要做法什么时候出现？ | **时间或发展阶段** | 有可核实的年份、事件和代表工作。阶段边界能说明研究重点的变化。 | 用发表先后推断承接或取代；并行发展的路线可以分别列时间线。 |
| 论文太少，用户只想了解代表解法 | **平铺或轻量标签** | 直接比较几篇即可回答问题；需要时用标签标明侧重点和近期工作。 | 为满足组数人为制造差异。 |

这些维度可以组合。比如按方法作为主分类，再用「设备端实测」「批大小为 1」辅助比较。只有第二层能回答额外问题时才增加。用户了解领域的背景程度影响报告的解释顺序，分类维度仍按调研用途和实际文献选择。

## 三、分类检查

- **内容有依据。** 标题和短摘要可初分。代表作、边界案例、相关近作要核对到足以确认类别的位置。说明哪些判断来自摘要，哪些已查正文。
- **允许交叉。** 一篇论文可以有一个主类别和多个交叉标签。范围尚不清楚时可暂待分类。保留跨类别比较所需的信息和同一论文标识。
- **允许不均衡。** 大类、少数新方法和独立论文均可保留。只有一篇也可以代表一个有明确问题和实际证据的类别。数量差异可能来自真实分布或检索不足。
- **可用，并标明覆盖限制。** 分类应帮助用户回答本次问题。未分类、待核实和未覆盖的范围显式保留。候选池里能归类的论文，只说明本次候选范围内的分布。

类别数和层级由用途及文献决定。阅读任务按工作量分批，可以一批看多类，也可以把较大的类别分成数批。正式调研由主会话提出方案并请用户确认；速览可直接给代表作和阅读顺序。

### 分清发表、承接与阅读顺序

| 关系 | 需要的依据 |
| --- | --- |
| **发表先后** | 已核实的首次提交、正式发表等日期及相应口径。 |
| **工作承接、扩展或替代** | 论文明确引用、采用或扩展前作的位置，或能够支持比较判断的证据。无明确关系时可以并列描述。 |
| **建议阅读顺序** | 读者理解某项工作所需的概念或方法。讲解更清楚的综述可能比原论文晚发表，也可以先读。 |

## 四、决定补查、调整还是继续

| 观察到的情况 | 下一步 |
| --- | --- |
| 很多论文反复落入两个类别，现有定义难以解释区别 | 先查代表作和边界论文，明确各类回答的问题。可保留交叉标签、改变层级或换一个主维度。 |
| 一组论文少，查询记录显示还有别名、日期窗、来源失败或未取完的结果 | 按 [检索策略](search-strategy.md) 对具体缺口补查，记录实际查询和结果。 |
| 某个少数路线的归类清楚，又没有发现具体检索缺口 | 可以保留小组或单列条目，说明本次找到的证据和覆盖限制。 |
| 新论文能归入现有类别，且不改变关键比较 | 补标签和原文记录，按既有方案补充阅读。 |
| 新证据支持独立路线，或实质改变主类别、比较结论或阅读范围 | 向用户说明新增证据和受影响的部分，回到 Step 3 确认调整。 |

## 五、把分类变成逐篇阅读任务

向用户说明「为什么这样分类、选哪几篇、读哪部分、每篇回答什么」。给出方案的总工作量、未读或待查范围。确认后按 [调研方案模板](templates/spec-template.md) 将主维度、分类理由、类别与阅读分工保存到 `spec.json`。

每个阅读任务写清用途、独立笔记路径和需要核查的论文。每篇至少列：

- `pool_id` 或已核实的稳定标识、标题、主类别及需要保留的交叉标签。
- 要读的章节、图表、公式或附录，尚未定位时写具体要找的内容。
- 这篇要回答的问题，以及需要对照的证据和条件。
- 可以复用的旧笔记及其版本、原文位置，仍需补查的内容和本次工作量。

按 [详细阅读笔记模板](templates/notes-template.md) 写入 `notes/`。跨组论文可复用已有原文核查，保留同一身份和笔记出处。主会话负责综合比较和核查冲突，重要判断须能追到原文。

## 示例：边缘设备上的视觉模型加速

以下为虚构例子，用来演示如何从论文池走到阅读方案。用户关心批大小为 1 时的端到端延迟。

**先初分。** 候选摘要里有两类改动。一类压缩模型或修改特征处理，一类调整运行时和算子实现。建议按「改动发生的位置」分类。设备型号、批大小和计时口径另作比较条件。只有一篇近作依赖特定设备的算子融合，也可以保留，注明目前只找到这一项证据。

**核对边界。** 近期论文 C 的摘要同时提到瘦身和算子融合。先读模型配置、算子实现和对应消融。假设正文显示默认配置先压缩模型、再启用算子融合，可把它放在「模型级改动」下，另标「运行时与算子优化」。如果实验只比较新旧整套配置，保留「两项改动同时变化，无法分开归因」的判断。在两个分组中引用同一条论文记录和笔记。

**给用户确认详细阅读方案。** 初步安排两篇代表作和一篇近期工作。其余候选先保留摘要分类。

| 入选论文与类别 | 读哪部分 | 要回答什么 | 保存位置 |
| --- | --- | --- | --- |
| `p00001` 代表论文 A，模型级改动 | 模型结构、实验设置和表 2 | 延迟下降是否来自模型轻量化？表里是否用同一硬件和批大小比较？ | `notes/model-optimization.md` |
| `p00002` 代表论文 B，运行时与算子优化 | 算子实现、计时范围与延迟表 | 增益是否依赖特定算子库？测量的是融合算子还是整条推理？ | `notes/runtime-optimization.md` |
| `p00003` 近期论文 C，主类为模型级改动，带运行时交叉标签 | 方法概述、消融和部署附录 | 模型压缩和算子融合的作用是否分别验证？覆盖了哪些此前未测的设备？ | `notes/model-optimization.md`，运行时比较引用同一笔记 |

若补查只找到同一类的新设备验证，补记录和必要证据即可。若找到此前未覆盖的方案，且它改变了关键条件或技术路线比较，展示新证据，请用户确认是否调整分类或增补阅读。
