# 查询设计、补查与停止条件

本文件说明怎样把调研问题拆成可执行的查询、沿综述和引文补足覆盖，以及根据实际新增和预算判断何时停止。

按 [运行步骤](workflow.md) 的 Step 1 设计查询，Step 2 执行并记录，Step 5 检查覆盖。来源和日期口径见 [来源选择](source-strategy.md)，请求、原始观测和纳排记录按 [检索记录模板](templates/search-template.md) 保存。

## 一、从研究问题拆出查询组

先确定这次调研要帮助用户做什么，再选择每组查询要回答的问题或补足的范围。入门优先找综述与清楚的代表作；找研究方向时优先追最相关且近期的工作；定位已有工作时查直接竞争方案和不同社区的说法；技术选型时围绕用户在意的约束找可比较的解法。熟悉度用于调整需要补哪些历史和术语。

| 查询入口 | 适合补什么 | 设计方法 |
| --- | --- | --- |
| 核心概念 | 领域概览、常见问题与代表路线 | 从领域的主要叫法开始，必要时另查带 `survey` 或 `review` 的表达式。 |
| 方法或机制 | 某条路线或关键组件 | 用已读论文的具体方法名组合任务或应用条件。 |
| 任务、数据集和指标 | 可比较的实验或特定使用场景 | 用任务名、常见基准、指标或约束查实际证据。 |
| 别名和相邻社区 | 主流术语之外的工作 | 从摘要、综述和引文里找另一社区的称呼，单独查并记录目的。 |
| 近期进展 | 截至本轮日期的新工作 | 第一批就查近作，让结果参与分类。按来源支持的日期口径分开查询，再按遗漏路线补查。 |

查询组数随调研问题变化。主题窄可以少设组，多个社区或使用条件差异明显时可以分开。查询分组与执行分工分别决定，可以由主会话分批执行，也可按已确认方案委派。每组在 `spec.json` 说明目的、确切查询、来源、日期和预算，写清它相对已有查询增加了什么。工具用法见 [paper-search v2 调用示例](../../paper-search/references/tools-and-examples.md)。

### 示例一：边缘设备上的视觉模型加速

用户要比较单图推理的技术方案。先按下面的问题设查询组。分类仍在检索与核查之后确定。

| 这一组回答什么 | 可以执行的查询 | 查到后重点核对什么 |
| --- | --- | --- |
| 模型本身有哪些减小开销的改法？ | `on-device vision inference model compression` | 是否真有设备测量，还是只报告参数量或 FLOPs。 |
| 同一模型还能怎样通过运行时或算子加速？ | `mobile vision inference operator optimization` | 设备、算子库、批大小、端到端延迟与单算子计时。 |
| 截至本轮日期有哪些新方案？ | `single-image inference latency edge device`；需要时换 `batch-1 inference` 等别名补查 | 用确认的近期窗口先查。若 arXiv 查首次提交、另一来源查发表，就分开调用并各自保存覆盖。 |

如果系统论文更多使用 `batch-1`，可依据标题、摘要或引文记录这个别名，再补一组。它要回答的问题是「有没有只用运行时术语描述的相关比较」，由这个缺口决定是否追加查询。

## 二、查综述、奠基作和代表工作

1. **找到并看清综述的范围。** 用主题加 `survey` 或 `review` 搜索。需要在 arXiv 按标题限定时，用单来源 `syntax="source_native"` 配合 `ti:survey` 和主题条件。对相关综述先看覆盖日期、纳入对象和分类理由。
2. **读取综述的分类及关键引用。** 有 arXiv 源码时用 [tex-mcp](../../tex-mcp/SKILL.md) 的 `tex_open`、`tex_outline` 和 `tex_read` 定位并读取分类段。按 [pdf-mcp](../../pdf-mcp/SKILL.md) 读取对应 PDF 或同版本结构化全文。将综述给出的分类和别名当候选，和本次已找到的代表作、边界论文及近作对照，再确定分类。
3. **核实早期工作起了什么作用。** 沿综述及代表作的参考文献回查问题是在哪篇定义的，或哪篇引入了后来沿用的方法。引用数、年份和多篇综述反复提及都可帮助定位。将某篇列为奠基作或里程碑时，写清它实际提出的内容和后续论文采用或改动了什么。近作是否值得列为代表也按具体内容判断。

## 三、沿引文扩展候选

按实际缺口选种子，比如定义问题的早期论文、最接近用户场景的代表作，或有潜力补上某条路线的近作。先核身份，用已知稳定标识直接查书目，只有标题时先经 `resolve_papers` 核对候选。将已核实的稳定标识传给相应工具。

| 要补的缺口 | 动作 |
| --- | --- |
| 找思路的来源、标准评测或被引用的早期方法 | 从代表作调用 `get_paper_references`，对照正文说明这些工作与本次问题的关系。 |
| 查代表作之后的延续、改进或反例 | 调用 `get_paper_citations`，核对候选是否实质讨论或使用了该工作。 |
| 找采用其他术语的工作或相邻社区 | 按支持情况用 `find_related_papers` 获取相关候选，再从原始标题、摘要或正文确认关联。 |

用 `get_query_results` 和真实游标读取当前本地快照。需要继续取上游结果时用 `extend_query(action="fetch_more")`，查看来源、覆盖和预算。每轮写清新增了哪条路线、哪篇关键论文，或哪项比较需要修订。预算允许且还有具体缺口时再继续。可复用已经保存且仍适用的查询记录。

## 四、保留原始观测，交给脚本核对身份

按 [检索记录模板](templates/search-template.md) 保存实际查询及纳入、排除、待核查的理由和阅读层次。分批执行或委派时，各批写独立的 `search/*.json`，汇总时给出用途、实际命中、关键候选与文件路径。引用数保留来源和观测时间。

跨批重复正常保留，使用 `merge_pool.py` 按共享的稳定标识关联。同标题仅提示可能重复。URL 应指向具体论文页面。预印本与出版版标题相近时，需核对稳定标识、出版商链接、作者和版本关系。会议版与期刊扩展版如有重要新增，可各自保留并注明关系。未核实身份或出现纳排冲突时，回到原批次核对，记录更正依据后重建论文池。

## 五、发现缺口后选择补查动作

对照批准计划检查哪些查询实际执行、结果是否取完、来源有无失败、各主要路线是否有可追查的代表证据，以及近期窗口是否覆盖到约定范围。把问题、影响、实际补查、实质新增及待补项写入 `coverage-review.md`。

| 查漏发现什么 | 下一步 |
| --- | --- |
| 查询未执行，或执行失败 | 先查来源能力、参数和失败原因。缺的查询按计划执行；可重试的 MCP 来源用 `extend_query(action="retry_failed")`。 |
| 本地还有未读页，或上游结果尚未取完 | 分别用 `get_query_results` 读本地页、用 `extend_query(action="fetch_more")` 补上游。核查日期过滤与预算是否仍然有效。 |
| 查询有效但未命中，怀疑术语或社区遗漏 | 用原文发现的别名补一组，或从已核种子沿引用扩展。论文检索快照支持时，可用 `extend_query(action="add_queries")` 增加表达式。需要改变日期或过滤条件时另发查询。 |
| 找到新路线或足以改变关键比较的近作 | 将补查写为独立批次并重新合并，核对新增证据。分类或详细阅读范围需要调整时，回 Step 3 请用户确认。 |
| 已到预算，或已批准查询完成且定向补查没有实质新增 | 按已查范围交付。保存剩余缺口、已尝试的查询及续做入口。 |

### 示例二：从近期覆盖缺口到停止

假设近期窗口内暂未找到运行时优化论文。先查原请求：如果只是本地页没读完，就续读该快照；如果上游被截断且还有预算，就取更多结果。若查询已有效执行且未命中，可根据代表作采用的术语补查 `edge inference batch-1 operator fusion`，沿用获批的近期窗口并记录实际返回。

如果找到一篇近期论文，先读到足以确认它的任务、设备、批大小和比较口径。它若补足原来缺失的一条路线或改变了关键比较，就更新分类和分析范围。若预算到达且仍无可核实的新证据，写明实际查过哪些日期和表达式，将缺口列入 `coverage-review.md`。报告的「近期进展」说明在该范围内未发现符合条件的论文，并注明仍需补哪些来源。最新命中日期和计划截至日期分别记录。
