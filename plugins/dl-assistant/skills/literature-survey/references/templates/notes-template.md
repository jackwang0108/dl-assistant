# notes/<子领域-slug>.md 模板（Step 4 负责子领域分析的子 agent 保存到文件 · 中文）

`notes/` 保存摘要未包含的细节，供主会话撰写 `report.md` 和 `reading-list.md` 时查阅。

逐篇笔记记录单篇论文的事实，包括它与既有工作的关系。方法对比部分利用这些记录归纳各篇共有的机制与设计差异。每项归纳应能追溯到相关论文。

## 结构

```markdown
# {子领域名}（轴：{axis}，用途：{purpose}）

## 逐篇笔记
### {论文标题}（arXiv:xxxx, 年份）
- **核心 idea**：一句话 + 它赖以为真的关键假设（方法成立所依赖的前提）
- **关键设计**：每个设计记「为什么这么设计、不这么设计会怎样」——记设计动机，不只记设计内容
- **与其他候选论文的关系**：本文基于哪些工作、解决了哪些已有局限。供绘制阅读依赖图参考。
- **值得精读吗**：值得 / 不值得 + 一句理由（阅读清单筛必读的素材）
- **limitation / future work**（找研究方向用途时重点记）

## 方法对比和可引用依据（供 Step6 主会话执笔用 · 跨篇归纳）
- 本派核心机制的一句话归纳 + 各篇关键设计差异点（机制层面，非逐篇复述）
- 可直接引用的关键句（带出处）：数据点、benchmark 数字、作者原话
- 与其他子领域的对比要点，供撰写报告的路线对比章节时使用。

## 里程碑标注
- {论文} —— 候选里程碑：{它改变了什么走向，一句}（全局认定归主会话，这里只是候选）

## 本类读到的开放问题（汇入 survey.json 的 gaps）
```

## 示例：逐篇笔记需要多详细

对照以下两种写法，采用能支撑跨论文分析的详细程度。

```markdown
# 浅（不合格：高级摘要，主会话还得回读原文）
- 核心 idea：提出 Latent Diffusion，在 latent 空间做扩散，效果好。
- 关键设计：用了 VAE 压缩，用了 cross-attention 做条件控制。

# 深（合格：主会话不回读原文也能做机制归纳）
- 核心 idea：把扩散过程从像素空间搬到 VAE 的 latent 空间——关键假设是
  「图像的语义内容在低维 latent 里基本无损」，假设成立才能用 1/10 算力换几乎不掉的质量。
- 关键设计：VAE 下采样 8 倍——压缩更多会丢失细节，压缩更少会降低算力节省，实测选择 8 倍；
  cross-attention 注入条件——因为条件来自任意模态（文本/布局/深度图），
  attention 比 concat 更能对齐异构信息，也为后来的多条件控制提供了基础。
```

检查主会话能否依据笔记比较各方法的机制。细节不足时，补记关键假设、设计动机和证据。

## 纪律

- 用要点记录对比结论和可引用依据，供主会话撰写报告。
- 单篇事实写入逐篇笔记，跨论文归纳写入方法对比部分，并注明对应论文。
