# report.md 模板（Step 6 用 · 主会话执笔 · 纯人读散文）

`report.md` 是调研的最终交付之一：一张**自给自足的领域地图**。机读数据（taxonomy / 论文池 / gaps）在 `survey.json`（schema 见 `survey-template.json`），入门阅读路径在 `reading-list.md`——三者边界清晰，本报告只写人读散文，**不写推荐阅读顺序**（那是 reading-list.md 的地盘）。

## 执笔纪律（先读这个，再动笔）

- **主会话亲自写整篇，不拼接子 agent 文本。** `notes/` 里是写作素材包（要点、对比、可引用句），不是成稿——直接拼接 3-5 个子 agent 的段落，必然声音不一、背景重复、没有主线。
- **写完先对照末尾 checklist 自查，再交付。**

## 怎么从一摞 notes 串出主线（动笔前先做这步）

新手写综述卡壳，卡在"素材都在、主线没有"。主线不是写出来的，是**找出来的**，三步：

1. **把里程碑候选按时间摊开**：收齐各 `notes/` 里的里程碑标注，连同奠基作、近期关键新工作，按年份排成一列；
2. **每个转折写一句「从什么到什么」**：逐个问——这篇之后，这个领域什么变了？（"从像素空间直接扩散 → 到 latent 空间扩散"、"从单条件 → 到任意多条件控制"）。写不出"从什么到什么"的，就不是里程碑，划掉；
3. **主线 = 转折句连成的因果链**：把留下的转折句按时间连起来读一遍，能顺下来的就是主线——第 2 节写它，第 3 节的分述挂在这条链上，第 4 节的对比解释链上的分叉为什么这么走。

主线定了再动笔。没有主线的报告只是素材的陈列。

## 报告结构

```markdown
# {主题} 文献调研报告

> **调研元信息**：{日期} · 用途：{找研究方向} · 熟悉度：{有点了解} · 范围：{近 3-5 年} · 规模：候选池 {N} 篇 / 深挖 {M} 篇 · 组织轴：{按方法}
> **覆盖边界**：{一句话诚实声明，与 survey.json 的 coverage_notes 一致，如"主要覆盖英文主流叫法；X 社区的 'Y' 叫法未深挖"}
> **入门精读路径**：见同目录 `reading-list.md`（谱系树 + 逐篇导读），本报告不重复。

## 速览（三行）

- 这个领域一句话：{在解决什么问题、为什么难}
- 主线一句话：{从什么范式走到什么范式，当前前沿在卷什么}
- 给 {用途} 读者的一句话：{按用途说最该知道的一件事，见「用途决定详略」}

## 1. 这个领域在解决什么问题

## 2. 发展脉络与里程碑

## 3. 技术路线分述

### 3.1 {子领域1}

### 3.2 {子领域2}

## 4. 横切对比

## 5. 当前挑战与开放问题
```

### 速览（三行，必有）

报告开头先给三行结论——读者（尤其几个月后回来的自己）不读全文也知道这报告讲了什么。三行分别回答：领域是什么、主线是什么、**按本次用途**最该知道的一件事。速览不是摘要重写，是判断的浓缩——写完正文再回来提炼它。

### 骨架随轴适配（动笔前先过这条）

上面五节是**默认骨架，最合「按方法谱系」型轴**。组织轴是从文献里自然浮现的（见 `organizing-axis.md`），轴不同，第 3/4 节的形态必须随轴变，不硬套：

- **按方法**：第 3 节按方法派别分述；第 4 节对比表 = 路线 × 维度。
- **按问题**：第 3 节按子问题分述（每个问题下各路线怎么攻、攻到什么程度）；第 4 节对比表 = 问题 × 路线（哪条路在哪个问题上占优）。
- **按时间**：第 3 节按时期分述（每个时期的主导范式与未解之痛）；第 4 节对比表 = 时期 × 范式能力边界。

轴是别的形态就照这个精神推：第 3 节的分述单元 = 轴的分类单元，第 4 节的对比 = 分类单元 × 关键维度。五节之外的节（背景/评测体系等）需要就加，不需要就砍——骨架服务读者理解，不是形式主义。

### 用途决定详略（每一节的笔墨跟着用途走）

四种用途的读者想从报告拿的东西根本不同，详略跟着用途倾斜：

| 用途 | 重头节 | 读者要的是什么 |
| --- | --- | --- |
| 学习理解 | 第 1/2 节 | 把领域讲懂；术语块全嵌；第 4 节从简 |
| 找研究方向 | 第 4 节判断层 + 第 5 节 | 哪里有真空、trade-off 的实质、哪些路线在衰落 |
| 定位自己的工作 | 第 3/4 节 | 每条路线的边界与空白在哪——读者在找「我的位置」 |
| 选技术方案 | 第 4 节 | 落地维度说透（数据需求/算力/成熟度/社区采纳） |

非重头节照常写但不堆料；重头节写到「读者能直接拿去做决定」的深度。速览第三行用的就是这张表。

### 1. 这个领域在解决什么问题（2-4 段）

- **写**：问题定义（任务输入输出是什么）、为什么难、为什么重要（应用 / 理论动机）。
- **不写**：方法细节、论文罗列。
- 目标：一个外行读完这节，知道后面所有方法在攻什么。

### 2. 发展脉络与里程碑（2-4 段 + 一张表）

- 散文串主线：用上面三步找到的因果链——问题何时被提出 → 奠基作定了什么范式 → 哪几个关键转折（各一句"从什么到什么"）→ 当前前沿在卷什么。**这节是全报告的脊柱**，后面分述和对比都挂在它上面。
- 里程碑表：`| 论文 | 年份 | 一句话贡献 |`，5-10 行，只放真正改变走向的工作，不凑数。
- 全局里程碑认定是主会话的活（需要全局视角），`notes/` 里的标注只是候选。**这节的脉络和里程碑认定要与 `reading-list.md` 的谱系树一致**——同一次判断的两个呈现，不能打架。

### 3. 技术路线分述（按轴 3-5 节，每节 3-6 段 + 一张代表论文表）

每节内部按这个次序组织：

1. **这派在干嘛**（1 段散文）：核心 idea，为什么这条路能走通。
2. **代表论文表**：`| 论文 | 年份 | 一句话"走什么路子" |`。
3. **核心机制与关键设计**（散文）：这派的共同骨架是什么、各篇的关键设计差异在哪——**机制层面的归纳，不是逐篇摘要**。
4. **派内演化**：这派内部怎么迭代的，新工作解决了旧工作的什么坑。
5. **局限与开放问题**：点到为止，展开归第 5 节。

用户**基本陌生**（或学习理解用途）时，主会话判断用户可能不熟的关键术语，在**首次提及**的段落后嵌术语解释块（模板见下）；其他情况不嵌。

### 4. 横切对比（2-4 段 + 一张对比表）

这节是主会话全局判断最重的一节，写法分两层：

- **对比表（事实层）**：路线 × 关键维度。维度词汇从这堆里按用途挑 4-6 个：**核心机制 / 数据需求 / 算力成本 / 成熟度 / 适用场景 / 代表性弱点 / 社区采纳度**——定位自己的工作、选技术方案用途这节是重头戏；学习理解可从简。
- **散文分析（判断层）**：表格回答"有什么差异"，散文要回答**"这些差异意味着什么"**。每个有分量的维度追一句"这个差异在实践中意味着什么"（"A 的数据需求低 → 小实验室也能玩，这是它社区采纳快的真正原因"）；然后给三个判断：**什么场景选哪条路线、trade-off 的实质是什么、有没有正在收敛或被取代的路线**。没有判断层的横切对比就是两张表格的流水账。

### 5. 当前挑战与开放问题（按主题归类的列表 + 短段）

- **按主题归类**（性能 / 效率 / 数据 / 评测 / …），不按子领域重复第 3 节已说的。
- 每条带论文锚点（哪个工作的 limitation / future work 提到的）。
- 只客观记录，**不判断哪个值得做**——那是 idea-find 的活。

## 写作风格规约

- **散文为主，列表 / 表格为辅**。论述推进靠段落，不靠 bullet 堆砌。
- 每篇被引论文**首次出现**带（标题， 年份）+ arXiv 链接，后文可用简称。
- 中文正文；论文名 / 方法名 / 数据集 / 指标等专有名词保留英文原文。公式符号用 LaTeX。
- **自给自足**：只读 report.md 就能懂这个领域，不依赖 notes/ 和 search/（阅读路径除外——那是 reading-list.md 的职责，不算外部依赖）。
- **诚实**：覆盖边界、不确定处、没深挖到的，明写，不假装全覆盖。

## 反模式清单（写完逐条对照）

- **速览缺位或写水**：开头没有三行结论，或速览只是把第 1 节摘要了一遍——速览是判断的浓缩，写完正文再提炼。
- **硬套骨架**：组织轴明明是按问题/按时间，第 3 节还按方法派别分述、第 4 节还做路线×维度表——形态必须随轴变。
- **详略一刀切**：四种用途一个写法——找方向的报告第 5 节水、选方案的报告第 4 节没有落地维度，都是没按用途倾斜。
- **逐篇摘要堆砌**：报告不是 N 篇摘要的排列（逐篇笔记在 notes/，报告要做机制层面的归纳）。
- **拼接痕迹**：节与节之间声音 / 详略 / 格式不一，同样的背景知识重复出现。
- **无锚点断言**：「该方法效果很好」——好到什么程度、哪个 benchmark、哪篇论文说的？
- **列表代替论述**：整节全是 bullet，没有一段完整推理。
- **骨架式报告**：每节两三句话，信息密度不如 survey.json。
- **有对比无判断**：横切对比只有表格和事实罗列，没有"差异意味着什么"的分析。

## 术语解释块模板（第 3 节内嵌用，用户基本陌生时）

用户基本陌生（或学习理解用途）时，主会话判断用户可能不熟的关键术语，在首次提及的段落后紧跟一个引用块：

```markdown
> **{术语名称}**
>
> {是什么——通俗语言说定义和基本原理，一段}
>
> {解决什么问题、在本领域扮演什么角色，一段}
>
> 入门阅读：[{论文标题}]({链接})（{作者}, {年份}）——{一句为何推荐}
```

## 完稿 checklist

- [ ] 速览三行能独立成立——不读全文也知道领域、主线、按用途最该知道的一件事。
- [ ] 外行读第 1 节能知道这领域在干嘛。
- [ ] 第 2 节串出了一条因果主线；里程碑每个都能说"从什么到什么"。
- [ ] 第 3/4 节形态跟着组织轴走（分述单元 = 轴的分类单元），没硬套方法谱系骨架。
- [ ] 详略跟着用途走——重头节写到「读者能直接拿去做决定」，非重头节不堆料。
- [ ] 每个子领域一节，是机制归纳而非逐篇摘要。
- [ ] 横切对比有表**有判断**——每个分量维度都追了"差异意味着什么"。
- [ ] 每个开放问题带论文锚点，按主题归并不重复。
- [ ] 全文一个声音，无拼接痕迹、无重复背景。
- [ ] 每个实质性断言都能指到具体论文（标题 + 年份 + 链接）。
- [ ] 基本陌生用户的关键术语都有解释块，且在首次提及处。
- [ ] 覆盖边界明写在元信息块，与 survey.json 的 coverage_notes 一致。
- [ ] 全文无阅读顺序 / 推荐阅读内容（阅读路径只在 reading-list.md）。
- [ ] 脉络、里程碑认定与 reading-list.md 的谱系树一致。

> **对话式速览**：用户要存盘时落单个 `report.md`，用同一模板但可从简（元信息块保留，各节篇幅随用途压缩）。
