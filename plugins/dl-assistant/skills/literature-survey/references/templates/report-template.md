# report.md：调研报告

报告独立可读，有来源、有比较、有明确范围；与 survey.json 及阅读清单保持一致，不为了文风或文件分工删掉必要信息。主 agent 综合各批材料，核查冲突并统一术语，允许有依据地复用材料，不把“绝不拼接”当质量证明。

## 建议结构

```markdown
# {研究问题} 文献调研

> 用途、范围、检索/获取日期、实际执行来源、候选与详细核查数量。
> 部分完成项和覆盖限制；阅读清单与结构化数据链接。

## 主要发现
几条有明确依据的结论与它们对本次用途的意义。

## 问题定义与必要背景
输入输出、关键术语、研究范围及不涵盖的内容。

## 分类与发展关系
分类依据、交叉与边界；重要工作的具体贡献和关系依据。

## 各类代表工作
机制、假设、证据、限制，区分核查层次。

## 跨论文比较
研究问题、方法、假设、数据、评测、成本、限制及来源位置。

## 待验证问题
作者声明、跨篇归纳、推测分别标明，说明当前状态与核查范围。

## 覆盖、停止依据与剩余工作
请求与实际执行情况、分页/截断/故障、补查新增、未完成任务。
```

结构按用途调整，不要求固定五节或每节固定段数。可以给适用条件下的路线建议，但不能以跨设置数字直接判优，不拿 star、引用数证明质量或真实采纳。每个实质性判断给稳定论文标识、版本和原文定位；不能只给标题而无证据位置。

重要性评价说明具体贡献及依据，不把时间顺序连成必然因果，也不要求领域必须有单条发展史。不确定继承关系就并列叙述。引用数只是各来源观测，不是里程碑判据。

开放问题不写成确定的研究空白；补搜无结果写明已检索范围，不称“已验证沉寂”。证据支持程度和与已有工作差异分开，课题验证交 idea-find。

交付检查：数量与 pool 一致；纳排/身份冲突已解释；已读层次明确；比较可追查且标不可比项；阅读建议与分类无矛盾；限制、停止原因和剩余任务真实。
