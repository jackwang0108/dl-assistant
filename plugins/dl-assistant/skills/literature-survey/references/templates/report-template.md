# report.md 模板（Step 6，由主会话撰写）

`report.md` 是供用户独立阅读的调研报告。`survey.json` 保存分类、论文清单和开放问题，格式见 `survey-template.json`。`reading-list.md` 说明推荐阅读顺序。

## 执笔纪律（先读这个，再动笔）

- 主会话根据 `notes/` 的笔记、方法对比和可引用依据撰写整篇报告，避免直接拼接不同子 agent 的段落。
- **写完先对照末尾 checklist 自查，再交付。**

## 写作前梳理领域发展过程

先根据各子领域的笔记找出推动领域发展的论文和转折，再撰写报告。

1. **按时间整理候选论文**。汇总各份 `notes/` 中标记的候选里程碑、奠基作和关键近期工作，按年份排序。
2. **说明每篇候选里程碑改变了什么**。例如，扩散模型从像素空间转到 latent 空间，或从单条件控制扩展到任意多条件控制。只能明确说出改变的论文才列为里程碑。
3. **梳理变化的顺序和原因**。按时间连接关键转折。第 2 节给出发展过程，第 3 节展开各子领域，第 4 节解释路线为何分化及各自取舍。

确认发展过程后再开始写报告。

## 报告结构

```markdown
# {主题} 文献调研报告

> **调研元信息**：{日期} · 用途：{找研究方向} · 熟悉度：{有点了解} · 范围：{近 3-5 年} · 规模：候选论文清单 {N} 篇 / 深入分析 {M} 篇 · 分类维度：{按方法}
> **覆盖边界**：{一句话诚实声明，与 survey.json 的 coverage_notes 一致，如"主要覆盖英文主流叫法；X 社区的 'Y' 叫法未深入分析"}
> **入门精读路径**：见同目录 `reading-list.md`（阅读依赖图 + 逐篇导读），本报告不重复。

## 速览（三行）

- 这个领域一句话：{在解决什么问题、为什么难}
- 主线一句话：{从什么范式走到什么范式，当前研究在关注什么}
- 给 {用途} 读者的一句话：{按用途说最该知道的一件事，见「用途决定详略」}

## 1. 这个领域在解决什么问题

## 2. 发展脉络与里程碑

## 3. 技术路线分述

### 3.1 {子领域1}

### 3.2 {子领域2}

## 4. 比较不同技术路线

## 5. 当前挑战与开放问题
```

### 必须包含的三行速览

正文写完后，在开头用三行概括：这个领域研究什么、主要发展过程是什么、按本次用途最值得关注什么。

### 根据分类方式调整报告结构

下面的五节结构默认适用于按方法组织的调研。第 3 和第 4 节根据已确定的分类方式调整，见 `organizing-axis.md`。

- **按方法**：第 3 节按方法方法家族分述；第 4 节对比表 = 路线 × 维度。
- **按问题**：第 3 节按子问题分述（每个问题下各路线怎么攻、攻到什么程度）；第 4 节对比表 = 问题 × 路线（哪条路在哪个问题上占优）。
- **按时间**：第 3 节按时期分述（每个时期的主导范式与尚未解决的问题）；第 4 节对比表 = 时期 × 范式能力边界。

采用其他分类维度时，第 3 节按既定分组组织，第 4 节比较各组在关键指标或条件上的差异。可按需要增加背景、评测体系等章节。

### 用途决定各节详略

四种用途的读者想从报告拿的东西根本不同，详略跟着用途倾斜：

| 用途 | 重点章节 | 读者要的是什么 |
| --- | --- | --- |
| 学习理解 | 第 1/2 节 | 把领域讲懂；术语块全嵌；第 4 节从简 |
| 找研究方向 | 第 4 节判断层 + 第 5 节 | 哪里有真空、trade-off 的实质、哪些路线在衰落 |
| 定位自己的工作 | 第 3/4 节 | 每条路线的边界与空白在哪——读者在找「我的位置」 |
| 选技术方案 | 第 4 节 | 落地维度说透（数据需求/算力/成熟度/社区采纳） |

重点章节写到读者能够据此作决定，其他章节适当简写。报告速览第三行也按本表选择内容。

### 1. 这个领域在解决什么问题（2-4 段）

- **写**：问题定义（任务输入输出是什么）、为什么难、为什么重要（应用 / 理论动机）。
- **不写**：方法细节、论文罗列。
- 目标：一个外行读完这节，知道后面所有方法在攻什么。

### 2. 发展脉络与里程碑（2-4 段 + 一张表）

- 按前面的三步梳理研究问题的来历、奠基作建立的范式、关键转折及当前进展。后面的子领域分述和路线对比与这一节保持一致。
- 里程碑表：`| 论文 | 年份 | 一句话贡献 |`，5-10 行，只放真正改变走向的工作，不凑数。
- 全局里程碑认定是主会话的活（需要全局视角），`notes/` 里的标注只是候选。**这节的脉络和里程碑认定要与 `reading-list.md` 的阅读依赖图一致**——同一次判断的两个呈现，不能打架。

### 3. 技术路线分述（按既定分类写 3-5 节，每节 3-6 段和一张代表论文表）

每节内部按这个次序组织：

1. **这类方法解决什么问题**（1 段）。说明共同思路及其为何可行。
2. **代表论文表**。使用 `| 论文 | 年份 | 一句话"采用什么技术路线" |`，用一句话写明每篇采用的技术路线。
3. **核心机制与关键设计**。归纳各篇共有的机制，再解释关键设计差异。
4. **本组的发展**。说明后来的工作如何改进较早方法、解决了什么问题。
5. **局限与开放问题**：点到为止，展开归第 5 节。

用户**基本陌生**（或学习理解用途）时，主会话判断用户可能不熟的关键术语，在**首次提及**的段落后嵌术语解释块（模板见下）；其他情况不嵌。

### 4. 比较不同技术路线（2-4 段 + 一张对比表）

这节是主会话全局判断最重的一节，写法分两层：

- **对比表（事实层）**：路线 × 关键维度。维度词汇从这堆里按用途挑 4-6 个：**核心机制 / 数据需求 / 算力成本 / 成熟度 / 适用场景 / 代表性弱点 / 社区采纳度**——定位自己的工作、选技术方案用途这节是重点；学习理解可从简。
- **散文分析（判断层）**：表格回答"有什么差异"，散文要回答**"这些差异意味着什么"**。每个有分量的维度追一句"这个差异在实践中意味着什么"（"A 的数据需求低 → 小实验室也能玩，这是它社区采纳快的真正原因"）；然后给三个判断：**什么场景选哪条路线、trade-off 的实质是什么、有没有正在收敛或被取代的路线**。没有判断层的比较不同技术路线就是两张表格的流水账。

### 5. 当前挑战与开放问题（按主题归类的列表 + 短段）

- **按主题归类**（性能 / 效率 / 数据 / 评测 / …），不按子领域重复第 3 节已说的。
- 为每个开放问题列出具体出处，例如哪篇论文的局限或未来工作提出了它。
- 只客观记录，**不判断哪个值得做**——那是 idea-find 的活。

## 写作风格规约

- **散文为主，列表 / 表格为辅**。论述推进靠段落，不靠 bullet 堆砌。
- 每篇被引论文**首次出现**带（标题， 年份）+ arXiv 链接，后文可用简称。
- 中文正文；论文名 / 方法名 / 数据集 / 指标等专有名词保留英文原文。公式符号用 LaTeX。
- **自给自足**：只读 report.md 就能懂这个领域，不依赖 notes/ 和 search/（阅读路径除外——那是 reading-list.md 的职责，不算外部依赖）。
- **诚实**：覆盖边界、不确定处、没深入分析到的，明写，不假装全覆盖。

## 反模式清单（写完逐条对照）

- **速览缺位或写水**：开头没有三行结论，或速览只是把第 1 节摘要了一遍——速览是判断的浓缩，写完正文再提炼。
- **报告结构与分类不一致**。按问题或时间分组时，第 3 和第 4 节也要按该维度组织。
- **详略一刀切**：四种用途一个写法——找方向的报告第 5 节水、选方案的报告第 4 节没有落地维度，都是没按用途倾斜。
- **逐篇摘要堆砌**：报告不是 N 篇摘要的排列（逐篇笔记在 notes/，报告要做机制层面的归纳）。
- **拼接痕迹**：节与节之间声音 / 详略 / 格式不一，同样的背景知识重复出现。
- **论断缺少出处**。说明哪篇论文、哪项评测、具体达到什么效果。
- **列表代替论述**：整节全是 bullet，没有一段完整推理。
- **骨架式报告**：每节两三句话，信息密度不如 survey.json。
- **有对比无判断**：比较不同技术路线只有表格和事实罗列，没有"差异意味着什么"的分析。

## 术语解释块模板（第 3 节内嵌用，用户基本陌生时）

用户基本陌生（或学习理解用途）时，主会话判断用户可能不熟的关键术语，在首次提及的段落后紧跟一个引用块：

```markdown
> **{术语名称}**
>
> {是什么——通俗语言说定义和基本原理，一段}
>
> {解决什么问题、在本领域扮演什么角色，一段}
>
> 入门阅读：[{论文标题}]({链接})（{作者}, {年份}）——{一句为何推荐}
```

## 完稿 checklist

- [ ] 速览三行能独立成立——不读全文也知道领域、主线、按用途最该知道的一件事。
- [ ] 外行读第 1 节能知道这领域在干嘛。
- [ ] 第 2 节串出了一条因果主线；里程碑每个都能说"从什么到什么"。
- [ ] 第 3 和第 4 节与选定的分类方式一致。
- [ ] 用户最关心的章节足以支持其判断，其他章节适当简写。
- [ ] 每个子领域一节，是机制归纳而非逐篇摘要。
- [ ] 比较不同技术路线有表**有判断**——每个分量维度都追了"差异意味着什么"。
- [ ] 每个开放问题附具体论文出处，按主题归并。
- [ ] 全文一个声音，无拼接痕迹、无重复背景。
- [ ] 每个实质性断言都能指到具体论文（标题 + 年份 + 链接）。
- [ ] 基本陌生用户的关键术语都有解释块，且在首次提及处。
- [ ] 覆盖边界明写在元信息块，与 survey.json 的 coverage_notes 一致。
- [ ] 全文无阅读顺序 / 推荐阅读内容（阅读路径只在 reading-list.md）。
- [ ] 脉络、里程碑认定与 reading-list.md 的阅读依赖图一致。

> **对话式速览**：用户要保存时落单个 `report.md`，用同一模板但可从简（元信息块保留，各节篇幅随用途压缩）。
