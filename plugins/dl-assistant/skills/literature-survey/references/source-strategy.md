# 检索来源与使用方式

本文件说明针对当前调研问题应该查哪些来源、每个来源负责查什么、怎样核对近期论文的覆盖，以及某个来源不可用时如何补查。

在 [运行步骤](workflow.md) 的 Step 1 选来源和时间口径，Step 2 执行并保存查询，Step 5 核对遗漏并补查。查询词的设计和引文扩展策略见 [检索策略](search-strategy.md)。

## 一、按任务选择来源

先用 [paper-search MCP v2](../../paper-search/SKILL.md) 的 `get_capabilities` 核对实际启用的来源，以及它们支持的日期字段、筛选、排序和操作。用 `search_papers` 检索。已有稳定标识时用 `get_papers` 查书目；只有标题时用 `resolve_papers` 核对候选。追溯或向前扩展已确认的论文时，按需调用 `get_paper_references` 或 `get_paper_citations`，传入稳定标识。[调用示例](../../paper-search/references/tools-and-examples.md)

| 来源 | 适合查什么 | 日期口径 | 怎么调用与核对 |
| --- | --- | --- | --- |
| **arXiv**（`arxiv`） | 查该领域投稿到 arXiv 的预印本和修订稿。用主题词、别名和分类号覆盖常见表述。 | `first_submitted` 查首次提交，`updated` 查修订。 | 用 `search_papers` 指定该来源。需要 `cat:`、`ti:`、`abs:` 时用单来源 `syntax="source_native"`。自由文本按词和短语构造查询，替代表述需要单独补查。 |
| **Semantic Scholar**（`semantic_scholar`） | 主题检索、从种子论文向前和向后查引文，补充书目信息。 | `published`。上游可能只提供年份或未知日期。 | 检索用 `search_papers`，引文扩展用 `get_paper_citations` 或 `get_paper_references`。查月内近作时核对实际日期精度。 |
| **Scholar**（`scholar`） | 补候选论文、替代表述和引文线索。 | 发表年份范围，无法确认精确到日或月的覆盖。 | 能用时以 `search_papers` 补查。精确时间窗另选来源。只有 `snippet` 时，把它作为定位线索，回查摘要或原文再判断。 |
| **OpenAlex**（`openalex`） | 按发表日期找近期出版记录，补查作者、机构或引用关系。 | `published`。如果计划只纳入正式发表的论文，另核对出版类型、版本与官方页面。 | 以 `search_papers` 用发表日期过滤；实体查找和作品查询按 v2 操作说明。 |
| **HF Papers**（`hf papers` CLI） | 补候选、替代术语和社区关注的工作。 | `search` 返回后按 `published_at` 筛选，并记录日期字段来自 HF。 | 独立运行 `hf papers search "<主题或别名>" --format json`，不将 HF 填入 MCP 的来源参数。后筛只覆盖本次返回的社区样本。见 [HF 补充检索](hf-papers.md)。 |
| **官方会议、期刊和专题目录** | 查主要在正式出版渠道出现的论文，核实版本、收录范围和历史截点。 | 按目录所用日期记录，例如在线发表日期或会议年份。 | 选与调研问题相关的目录，保存栏目、时间窗、URL 和实际读到的范围。需要跨来源核对标识时再用 paper-search。 |

入门调研优先查清楚的综述和代表作；定位工作或找研究方向时，补查最接近的论文和近期进展；技术选型时，优先找能比较数据、成本与评测条件的证据。熟悉度影响解释与历史铺垫，检索范围按确认的用途决定。来源选择说明采用理由及仍可能遗漏的范围即可。

引用数、投票和 GitHub stars 可帮助选出需要核查的候选。记录来源、观测日期和当时的数值。论文是否重要、是否属于里程碑，还要看它具体贡献了什么及后续证据。

## 二、第一批查近作，查漏时再定向补查

正式调研的第一批检索就纳入近期工作，让它们参与分类。查漏时根据已有分类，从缺少当期证据的路线、别名或研究社区出发做定向补查。若用户限制为历史时段，则核对截至该时段上限的进展。

在检索方案里写清四项：

| 要写的内容 | 含义 | 示例 |
| --- | --- | --- |
| **近期窗口** | 哪段时间算本次的近期研究 | 2025-08-01 至 2025-08-31 |
| **截至日期** | 本次调研希望核查到哪一天 | 截至 2025-08-31。即使最新命中只到 8 月 20 日，也分别记录截至日期和最新命中日期。 |
| **日期口径** | 用哪一种事件来判断论文是否落在窗口内 | arXiv 按首次提交，出版记录按发表日期；查修订另用更新日期。 |
| **实际检索来源** | 哪些来源真正执行了这些查询，并注明状态和限制 | arXiv 查首次提交，OpenAlex 查发表记录；若某一来源被截断或失败，单独说明。 |

机器学习方向的初步入门可从近 3–6 个月开始，找研究方向可考虑近 1–2 年。按领域更新速度、用户用途和预算调整。若该方向近期论文主要出现在其他数据库或官方目录，按实际渠道查近作。HF 可补术语和候选，它的返回量和后筛范围不足以单独证明近期覆盖。

### 用 v2 分开查首次提交和发表日期

以下日期为固定示例，实际执行时换成本次确认的窗口。先按能力确认支持的排序。日期类型是整次 `search_papers` 调用的过滤条件，首次提交和发表日期分别发起查询。详细边界见 [paper-search 日期规则](../../paper-search/references/date-filtering.md)。

```python
search_papers(
    queries=[{"text": "diffusion", "sources": ["arxiv"]}],
    filters={"date_range": {
        "date_type": "first_submitted", "start": "2025-08-01", "end": "2025-08-31"
    }},
    sort="date_desc",
    budget={"max_requests": 2, "max_items": 3, "max_seconds": 12},
)

search_papers(
    queries=[{"text": "diffusion", "sources": ["openalex"]}],
    filters={"date_range": {
        "date_type": "published", "start": "2025-08-01", "end": "2025-08-31"
    }},
    sort="date_desc",
    budget={"max_requests": 2, "max_items": 3, "max_seconds": 12},
)
```

示例预算用于小范围核对接口。正式调研按已批准的预算和查询组执行。检查实际日期字段、精度和来源状态。同一工作可能在两个日期窗口都命中，合并论文身份时仍保留各条来源与日期。近期结果和限制写入覆盖记录及报告的「近期进展」章节。

## 三、来源失败或覆盖不足时怎么补查

- **先看 `source_reports`、`coverage` 和预算消耗。** 分开记录未执行、执行失败、有效但零命中、部分返回或截断。查看具体原因，例如缺配置、不支持所选条件、网络错误、源站限流或预算耗尽。查询有效但没命中时，再检查关键词、别名与日期窗。
- **区分读本地快照和补上游。** 用 `get_query_results` 和实际的游标读取已经取得的结果。需要上游继续取回或重试时，按 [v2 调用示例](../../paper-search/references/tools-and-examples.md) 用 `extend_query` 的 `fetch_more` 或 `retry_failed`，并保存新快照及状态。
- **换来源时核对它能覆盖什么。** 假如精确日期条件不受支持，单独调用支持该口径的来源。采用更宽条件时，记录哪些过滤未生效及后续如何核对。暂时无法补齐的范围写进 `coverage-review.md`；全部失败时说明诊断结果、需要的配置或材料及后续可行入口。
