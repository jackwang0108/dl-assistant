# 从官方要求到人工提交清单

本文件说明怎样查适用规则、按范围核实际材料，并为用户准备可操作的提交待办。

## 1. 定范围与材料身份

先用用户指定目标、年份、轨道、论文类型及阶段。按提交实际区分摘要登记、初投、作者回复、返修和最终稿。影响规则而尚未确认的条件可以先标待核，继续查共用规定。仅查规则时直接进入下一步。

用户给 PDF 或某项材料时先记录路径、文件用途与校验值。需从论文工程定位时，依次看用户指定路径、当前工程、`papers/` 下的候选。工程内读取 `_draft/config.json` 和实际 TeX 入口，沿用配置的本地或 Overleaf 构建方式。本地成品按项目配置和构建记录定位。Overleaf 根据 [Overleaf MCP](../../overleaf-mcp/SKILL.md) 核项目、编译记录和诊断，下载选定编译的 PDF 和可用日志。PDF 可单独检查，缺同版日志时将构建相关项目留待核。

## 2. 查官方要求并建立检查项

按[官方来源核查](official-guidelines.md)打开目标当届投稿指南、模板、重要日期、公告和适用的平台公开说明。已有 `venue-contract` 时从其中的出处开始，核其当前有效性。把每条要求写清实际含义、ID、适用条件、强制程度、来源和位置。核对下列容易混淆之处：

- 截止时间分别记摘要登记、全文、回复或最终稿的原文、完整日期、时区及当地换算。日期或时区未确认时记待核。
- 落实页面计数口径。单独确认参考文献、附录、声明等是否计入，以及标题页是否计入。正文与参考文献共页时，回查官方如何计该页。
- 核匿名、署名、补充材料、外链和平台限制是否分阶段生效。找到不一致的官方表述时，记录来源日期、轨道和各自影响；需要用户在账号内确认的项保留入口。

仅查规则时填写正式来源、要求和待办。选择核材料或完整准备时继续。

## 3. 核指定文件和实际页面

### 自动观察与页数

先从指定 PDF 获取实际总页数、字体和元数据。页限比较要有规则出处。正文计数只在规则明确且已核实际页面范围后才填。日志只有在构建记录给出的两个摘要与实际 PDF 和日志均相符时，才作为这份 PDF 的构建证据。以下命令按实际文件和规则选用，参数和输出状态见[材料检查工具](material-checks.md)。

```bash
bash "$skill_dir/scripts/submission-check.sh" \
  --pdf "$paper_pdf" --checks pages,fonts,metadata --format json

bash "$skill_dir/scripts/submission-check.sh" \
  --pdf "$paper_pdf" --checks pages --page-limit "$page_limit" \
  --page-scope main --main-pages "$verified_main_pages" \
  --main-pages-basis "$main_pages_basis" --rule-ref "$rule_ref"

bash "$skill_dir/scripts/submission-check.sh" \
  --pdf "$paper_pdf" --log "$build_log" --checks references,labels \
  --build-record "$build_record"
```

保存脚本输出及其核查范围。根据适用要求判断是否阻塞，例如未嵌字体的观察只有在适用嵌入要求时才直接支持不符合的结论。工具失败和日志未绑定均记录限制。

### 页面显示和身份

按 [PDF MCP](../../pdf-mcp/SKILL.md) 用 `pdf_open` 固定实际文件，`pdf_render` 分批渲染。完整检查浏览全部页面，重点查看首页、含图表页、参考文献起始页和末页。单项检查只看覆盖该要求的页面，并写清页码或区域。

- **版式**：检查页面边界、跨栏公式和表格、图中文字、图注截断、特殊符号和缺字、页码和行号的显示。编译警告可协助定位，用实际页面确认。
- **匿名**：按实际匿名要求查首页作者和机构、致谢、自引、项目与代码链接、数据路径、补充材料及文件元数据。若提交源码，核该源码包实际包含的信息。宏、注释和匿名占位结合实际提交的形态判断。
- **署名及致谢**：适用时核作者顺序、拼写、机构、通讯地址、致谢、基金和必要链接。匿名占位仅在实际是匿名占位时列为问题。检查对应版本页图和提交材料，要求平台登记的资料单独列待办。

每项附规则 ID、材料版本、位置和观察。无法完成的项目记待核，说明还缺什么。

## 4. 准备材料、声明与平台待办

从作者包、官方说明和已有论文待办提取实际材料。逐项列主 PDF、回复、补充材料、源码包或平台另传文件等适用要求。核存在、格式、大小、文件命名、用途和校验值。仅按官方要求整理包清单。

- **已核事实**：页数、数据使用、图表或附件范围等，附实际来源后填进离线草稿，或列成建议答案供用户使用。
- **声明及承诺**：原创性、作者资格、伦理审查、版权、开放承诺等。写清问题、可核依据、建议答案和待用户确认之处。答案起草与用户实际确认分开记录。
- **平台操作**：按公开可见的官方步骤列链接、先后依赖和所需文件。需要登录才可见的字段列成用户待核项。平台填写、上传、声明和提交由用户完成。

## 5. 保存报告并交接

按[报告模板](report-template.md)记录来源、适用范围、实际结果及待办。完整终审可给提交建议，说明具体阻塞项、位置、修复后要重核什么。正文或图表修正交 writing-paper，回复正文交 writing-paper-response，构建问题按实际工程调用对应构建流程。规则或文件更新后只重新检查受变化影响的项目，保留原记录。

### 示例：只限正文页数，补充材料待核

用户给初投 PDF，官方要求只限正文。脚本先记录总页数。渲染参考文献起始页并按官方口径确定正文实际包含哪些页，再用 `--page-scope main` 验证。报告将正文页数和总页数分别列出，并标注实际依据。若补充材料尚无文件，只记录官方要求和待核项。若本次仅核页数，不对整套提交材料给结论。
