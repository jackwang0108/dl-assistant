# 直接入选条件与第 1 轮摘要初筛（arxiv-daily-paper · Step 2）

子 agent 读取 `raw.json` 并完成以下检查。主会话只接收简要结论，避免把全部摘要读入会话。

## 检查直接入选条件

符合以下任一条件的论文直接进入下一轮，跳过摘要淘汰环节：

- `comment` 注明会议录用，例如 “Accepted to CVPR/ICML/ECCV…”。
- `comment` 提供代码或项目页，例如 GitHub 仓库或项目主页。
- 有 `journal_ref` 记录。

## 第 1 轮摘要初筛

阅读其余论文的完整摘要。按所选分类的投稿总数决定保留数量：

- **总数 ≤ 45 篇**。只分类，全部保留。
- **总数 > 45 篇**。目标保留约 30-45 篇，通常约占总数的 20-25%，供第 2 轮的 2-3 个子 agent 各处理约 15 篇。投稿较多时收紧筛选，数量中等时按比例保留，避免超过第 2 轮的处理量。

需要筛选时，默认排除摘要中缺少具体、可验证技术内容的论文。以下例子用于理解标准。判断时阅读完整摘要，不能仅凭例子中的关键词作决定。

- 只陈述研究愿景，缺少明确的方法或结果。例如使用 “we explore / we discuss”，但没有解释具体做法。
- 只说对已有方法做了小幅改进，例如 “a minor improvement over X”。
- `comment` 标为 workshop 或技术报告，且摘要缺少具体技术内容。
- 摘要很短，且未提出具体主张。
- 标题声称有重要贡献，摘要缺少相应的技术内容。

**以下论文必须保留**：满足任一直接入选条件、在多个领域交叉列出的论文（cross-list，提示可能适用多个领域），以及摘要明确提出新任务、新基准或新范式的论文。

## 子 agent 分批处理

- 按每批约 80-100 篇分给一个子 agent，并行处理。少于 100 篇也分给一个子 agent。一律使用 `general-purpose`，以便保存结果。主会话只负责分批与汇总。
- 子 agent 将完整初筛结果写入 `round1-screen.md`，每篇入选或未入选的论文都附一句理由。向主会话只返回入选的 arXiv ID、未入选数量和原因统计。
- 子 agent 按投稿总数调整保留数量。多个子 agent 按各批占比分配保留数量。例如，200 篇分给 2 个子 agent 时，每批保留约 15-22 篇。

## 完成后汇报

告诉用户从 {N} 篇中保留了 {M} 篇，未入选的 {K} 篇有哪些主要原因，例如仅做小幅改进、摘要没有具体方法或内容偏离主题。告知完整记录位于 `round1-screen.md`。完整筛选随后进入量化评估。

## 今日速览的推荐标记

今日速览跳过第 2 轮。在 `digest-lite.md` 中，从满足直接入选条件且摘要中有明确技术主张的论文里标记少量推荐论文。具体主张包括新任务、新基准，或明显超过当前 SOTA 的具体数字。每组话题推荐 1-3 篇。明确说明推荐仅基于摘要、未读全文，判断置信度低于完整筛选的入选结果，不能作为论文质量结论引用。
