# 完整摘要检查

读取 `raw.json`。约每 80–100 篇分配一个子 agent，按实际并发能力分批；每篇只由一个子 agent 负责。子 agent 类型按当前环境的读写能力选择，不绑定某个宿主名称。

## 逐篇记录

每篇保存 arXiv ID、版本、问题、方法或研究内容、作者报告的主要发现、处理状态及理由。处理状态：

- **进入正文检查**：摘要提供值得进一步核实的具体问题、方法、发现或资源。
- **待核查**：摘要不充分、内容不明确或当前评估预算不足，尚不能做可靠判断。
- **不推荐进一步检查**：有具体且能说明的排除理由；不能只写“质量低”、不相关或名额已满。

理论、分析、数据集、负结果和方法论文采用适合其研究类型的判断，不能因为没有性能提升数字、实验数量少或标为技术报告而直接排除。摘要声称新任务、新方法或新基准时记录为作者声明，进入适当的后续核查；不能仅凭新颖措辞确认创新性。

录用信息、代码链接、`journal_ref`、跨分类投稿都单独记录，不直接免检，也不保证入选。来源不明的信息标记待核实。

## 并行文件与汇总

子 agent 仅写 `round1/part-<编号>.md`，返回该文件路径、处理数量和建议优先检查的 ID。主 agent 检查各分片没有遗漏、重复或未知 ID，再汇总为 `round1-screen.md`。失败分片保留为待处理，不伪装为已完成。

不强制压缩到 30–45 篇。需要优先检查部分论文时，说明排序依据，剩余论文放在待核查清单。汇报各状态数量、主要理由与后续工作量。

## 快速浏览

快速浏览对所有论文分类，不做正文质量判断。每个话题可列少量优先关注项，依据为摘要具体内容及与用户问题的关系。输出明确注明“仅依据标题与摘要，未经全文核查”；其余论文可在完整分类清单查到。
