# 第 0 道 + 第 1 轮：粗筛（arxiv-daily-paper · Step 2）

读 `raw.json`，先做两件事。**全程在子 agent 里做，主会话不读全量摘要**（主会话只接收子 agent 回传的精简结论——否则上百篇摘要会塞爆主会话上下文）。

## 第 0 道·硬信号直通

`comment` 含中会（"Accepted to CVPR/ICML/ECCV…"）、含代码/项目页（github/project page）、或有 `journal_ref` → **直接入围**，不参与下面的淘汰（已有客观背书）。

## 第 1 轮·摘要粗筛

对其余论文读**完整摘要**，砍掉证据强度弱的。这是一道**控量**的刀，不是"拿不准就留"——但**目标量按全域大小自适应**：

- **全域 ≤ 45 篇**：**只分类、不淘汰**（量本就小，砍了反而误杀信息）。
- **全域 > 45 篇**：目标砍到 **~30-45 篇**（约全域的 20-25%，够第 2 轮 2-3 个子 agent 各 ~15 篇消化）；大日砍狠点，中型日按比例——宁可砍狠也别让第 2 轮过载。

砍的判据不变：摘要没透出具体、可验证的技术内容就砍，只有命中下面反向保护才一律保留。

判断的原则是问一句：**这篇摘要有没有透出"具体、能验证的技术内容"**？**透不出就砍**（默认处置）——通篇宏大叙事、读完不知道它具体做了什么/比什么的，一律淘汰。下面是几类**典型示意（举例帮理解，不是逐条匹配的清单，更不要字面抓关键词）**：

- 通篇只有愿景、没有具体方法/结果（如满屏 "we explore / we discuss" 却没 method）
- 纯增量自述（如 "a minor improvement over X"）
- comment 标 workshop/技术报告且摘要单薄
- 摘要极短且无任何 claim
- 标题党配空洞摘要

- **反向保护**（命中任一**不准砍**）：第 0 道任何硬信号；cross-list 多领域（野心/通用性信号）；摘要明确 claim 了新任务/新 benchmark/新范式。

## 子 agent 分片（强制，不论数量都不在主会话做）

- 按每 ~80-100 篇一个子 agent 并行粗筛（一律 `general-purpose`，禁 Explore——要落盘写 `round1-screen.md`；不足 100 篇也派一个，**主会话只负责拆分和汇总，绝不内联读摘要**）。每个子 agent **把完整粗筛结果（幸存 + 淘汰各附一句理由）写入 `round1-screen.md`**，返回主会话只给"幸存 arXiv ID 清单 + 淘汰数/理由统计"。
- 子 agent 须知目标产出量：**按全域自适应**（全域 ≤45 不砍、>45 砍到 ~30-45）。多个子 agent 并行时各自按比例控量（如全域 200 篇分 2 个 agent，各自留 ~15-22 篇）。

## 完成后汇报

**向用户汇报粗筛情况**（透明度 + 方便发现误杀）："{N} 篇 → 留下 {M} 篇。砍掉的 {K} 篇主要集中在：{纯增量 X 篇 / 无具体方法的宏大叙事 Y 篇 / 跑题 Z 篇 …}。想看被砍清单见 `round1-screen.md`。进入量化细评。"

## 速览模式的 top 标注（仅今日速览模式）

速览模式不走第 2 轮，但 digest-lite 要给"今日 top"。标注判据：**第 0 道硬信号命中的** + **摘要透出强 claim 的**（明确 claim 新任务/新 benchmark/显著超 SOTA 的具体数字）少数篇——**每个话题簇 1-3 篇**，宁缺毋滥。digest-lite 里必须写明：**top 是摘要级粗判、没读全文**，置信低于深度漏斗的入选篇——别把速览 top 当质量结论引用。
