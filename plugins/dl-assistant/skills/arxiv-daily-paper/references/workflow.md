# arXiv 日报执行流程

本文件说明怎样固定抓取范围，分轮核查论文，保存优先阅读建议，并在可比的日期范围内统计话题。

## 1. 定范围并核抓取结果

优先沿用用户给的日期、分类、研究问题和阅读预算。没有指定日期时可用 UTC 今天，先显示解析后的具体日期和分类。方向用自然语言描述时按[分类映射](digest-and-interaction.md)转成候选分类。只补会影响范围的条件。明确要按公告日或本地自然日查询时，先核是否有对应来源或查询能力，再按实际口径处理。

从项目根使用 skill 的绝对路径抓取。下面是已明确查 UTC 提交日期的例子，把变量换成实际路径和日期。抓取成功后再发布 `raw.json`；失败时查看实际错误并保留原记录。

```bash
mkdir -p "$run_dir"
uv run "$skill_dir/scripts/fetch_arxiv_daily.py" \
  --date "$utc_date" --categories cs.CV cs.LG --max 500 > "$run_dir/raw.json.part"
```

核进程退出状态和 JSON，再将临时输出归档为 `raw.json`。检查 `date`、`date_basis`、`timezone`、`fetched_at` 和分类集合与本次范围一致。`total_count` 是去重后的篇数，`raw_count` 是去重前收到的条目数。`truncated: true` 表示请求达到上限，覆盖待确认。按范围提高上限重查，或继续做明确标为部分覆盖的报告。脚本返回零篇时保留原日期，写查询时间和已查分类。用户另要求找最近有结果的一天时才追加查询。

## 2. 按完整摘要逐篇检查

1. 在 `raw.json` 中按稳定 ID 划分任务，每个 ID 只分配一次。几十篇时可直接逐篇处理，材料较多且环境允许时分批并行，否则用相同分片串行。每个分片写自己的 `round1/part-<编号>.md`。
2. 按[摘要检查规则](round1-screening.md)记实际版本、话题、研究类型、作者报告、状态和一句理由。已录用、项目页或代码链接作为单独线索。工作超过当前评估预算时，把剩余 ID 列为待核查，并说明数量。
3. 汇总前核各分片 ID 与 `raw.json` 对应，查重复、缺失和未知 ID。区分已核摘要和待核。快速浏览到这里保存 `digest-lite.md`，明确所有推荐为摘要级，按需另做趋势。

## 3. 对选定论文核正文和证据

对需要继续核的论文先用 [tex-mcp](../../tex-mcp/SKILL.md) 定位指定版本及相关章节、对象；源码不可用时切换 [pdf-mcp](../../pdf-mcp/SKILL.md)。按[正文检查手册](round2-quantitative.md)核实际读到的版本、位置和限制。需要下载并复用 PDF 时用安全版本文件名，成功解析且核到实际版本才记为可用。

逐篇按类型选检查内容。例如方法论文先查主结果表、对照及配置，数据集论文先查构建、划分和覆盖，理论论文先查定义、假设与定理。将具体对照、统计口径、证据不足之处和下一步问题记入 `round2/<安全版本ID>.md`。进度不足时可先交当前覆盖，之后延续同一组版本继续核。

## 4. 确认重点名单并查全文

根据用户主题、值得关注的证据和需核的新问题给优先阅读名单，默认 5–8 篇。每篇附目前已读范围、推荐原因和未决项，同时保留补充推荐与待核清单。用户确认本轮名单后，按[全文评价手册](round3-deep-read.md)查实际全文、必要的相关工作和证据。尚未充分查到的相关工作继续标为待核。核过的依据和当前结论保存到 `round3/<安全版本ID>.md`。

只有部分论文完成全文检查时，在日报逐篇注明阅读层级。用户希望深入理解某一篇时，交 paper-reading 该论文 ID、版本和本次记录。

## 5. 汇总日报、趋势和后续阅读

按[简报格式](digest-and-interaction.md)先列范围、覆盖和阅读建议，再列补充推荐、待核篇目及相关研究线索。按需从全部返回论文的标题与摘要保存[趋势快照](trend-snapshot.md)。有可比历史时注明有效和缺失日期，保留抓取限制。

续做核原 `raw.json` 日期、分类和版本，以及每轮文件实际覆盖。可复用同版本记录；新增、遗漏或版本变化的论文按需要核查。后续交接给用户的最小材料含稳定论文 ID、实际版本、报告路径、已读范围和剩余问题。
