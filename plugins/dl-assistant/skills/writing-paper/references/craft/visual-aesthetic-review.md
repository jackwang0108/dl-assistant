# Visual & Aesthetic Review

`latex-landing` Step F 的详细规则（write-section 逐节 / audit·finalize 收尾都跑）。**编译通过 ≠ 产出合格**——渲染 PDF 后既查正确性，也查美观性。学术 PDF 的美观不是锦上添花：拥挤、闷、重点不突出的版面会直接拉低 reviewer 的第一印象。

> 本 reference 只管**呈现层**。所有"内容是什么"的问题（该不该有这张图、这段该不该拆）不在这里改——标出来回 `writing-paper`。

## 渲染哪几页

```
overleaf_download_output(project_id=project, compile_id=run, filename="output.pdf")
  → overleaf_render(project_id=project, compile_id=run, pages="1-3", dpi=150)
```

- **首过**：渲染全部页，整体扫一遍版面密度和图表分布。
- **重点页**：teaser/首页、有大图大表的页、章节首页、参考文献页单独细看。
- dpi 150 够看排版；查字号是否够大可临时调高。

## 检查清单

### 一、正确性（必须全过）

| 检查 | 怎么看 |
|---|---|
| 图表是否显示 | 渲染页里图/表实际出现，不是空白框或 `[图片缺失]` |
| 引用解析 | 正文无 `[?]` / `??`；`\cite` 都解析、参考文献列表非空 |
| 编号连续 | 图/表/公式/section 编号连续无跳号、无重复 |
| 公式排版 | 公式不溢出栏宽、上下标不重叠、长公式有换行 |
| 交叉引用 | "see Figure 3" 指向的确实是那张图 |

### 二、美观性（影响观感，呈现类可调）

| 维度 | 症状 | 调法（呈现层） |
|---|---|---|
| **图表占比** | 图太小看不清 / 表太大占满整页 / 一页塞太多浮动体 | 调 `\includegraphics[width=]`、`\columnwidth` vs `\textwidth`（单栏图跨栏用 `figure*`）、调浮动体 placement |
| **浮动体位置** | 图表飘到很远的页、和正文脱节、章节末尾堆一堆 | 调 `[t]/[b]/[h]` placement、`\clearpage`、必要时微调引用点 |
| **文本节奏** | 整页大段 plain text、没有图/表/公式穿插、读着闷 | 把已有图表移到该出现的位置；若内容本就没安排图表→**回内容层** |
| **强调突出** | 该粗体/斜体的关键术语、贡献点没标 | 落实内容产物里的 `**bold**`/`_italic_`；若内容里就没标重点→**回内容层** |
| **双栏溢出** | Overfull hbox、文字/公式/表格超出栏宽、伸到页边 | log 搜 `Overfull \hbox`；调表格列宽、长 url 用 `\url`、长公式换行、`\resizebox` 表格 |
| **caption** | caption 走位、过长挤占、字号不一致 | 跟模板 caption 风格、移到图下/表上（按领域惯例）、精简 |
| **留白/间距** | 图表与正文挤在一起、section 间距失衡 | 调浮动体间距、`\vspace`（节制使用，别破坏模板规范） |

### 三、从 log 抓线索（不只靠肉眼）

编译 log 里这些 warning 直接对应美观问题，渲染前先扫：

- `Overfull \hbox (... too wide)` → 双栏溢出，定位到行号
- `Overfull \vbox` / `Float too large` → 浮动体超页
- `LaTeX Warning: Citation ... undefined` → bib 没挂好（正确性）
- `LaTeX Warning: Reference ... undefined` → 交叉引用断了（正确性）

## 处理边界（最关键的判断）

每发现一个问题，先问**根因在哪一层**：

- **呈现层**（怎么排）→ agent **直接调**：浮动体位置/大小、栏宽、间距、强调标记落实、宏包参数、表格缩放。
- **内容层**（是什么）→ **标出来回 `writing-paper`**，不在 Overleaf 改：
  - 内容本身就没安排图/表（不是"图飘走了"，是"压根没有图"）
  - 该拆的长论述在内容里就是一整段
  - 强调缺失是因为内容产物里就没标哪些是重点
  - 图表表达的信息本身不对/不足

> 一句话判据：**调"呈现"不碰"语义"。** 改完后语义和内容产物完全一致，只是看起来更好——就是呈现层，可以做；否则回内容层。

## 迭代与放行

```
渲染 → 列出问题（分正确性/美观，标根因层）
  → 呈现类：调 → 本地编译 → 重渲染确认（同步节点再远端复核）
  → 内容类：汇总回 writing-paper
  → 直到正确性全过、呈现类美观问题清完
  → 交人类做最终视觉审阅（finalize）
```

agent 不自行判定"美观达标"——清完能调的、汇报清楚，**最终由人类视觉审阅放行**。
