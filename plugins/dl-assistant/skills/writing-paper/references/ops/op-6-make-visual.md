# 根据真实内容制作图表

读取图表意图、对应研究主张、方法/数据来源与当前术语。图表是否需要、放正文还是附录，由论证必要性、可读性和投稿要求决定，不预设首图或架构图不可移动。

1. 明确读者要看懂什么，选示意图、数据图、表或真实样本网格。已有用户风格参考直接使用；没有时 agent 根据内容提出设计，不强制先问参考或搜同 venue 图。
2. 示意图用适合的可编辑工具（SVG、HTML、TikZ、矢量编辑等），表示真实方法或明确标注的概念。检查数据/控制方向、输入输出、公式、术语和比例关系；保存源文件和必要资源。
3. 数据图/表由确定性代码从真实数据生成，保存来源、脚本、样本选择/排除、统计量、单位和条件。生成式图像不能替代实验数据、真实样本或模型输出。示例与实际结果清楚区分。
4. 使用一致的视觉编码、可读字号和非单一颜色区分；按实际模板栏宽设计，并在最终显示尺寸下预览。数据图以解释准确为先，不为突出优势截断柱图或弱化不确定性。
5. agent 先检查内容与渲染；重要设计选择给用户可看的预览，已授权细修连续完成。用户要求人工制作或缺少素材时才交付明确需求，不强制 PPT 重画。
6. 输出实际适用格式、可编辑源、必要数据/脚本和来源到 manifest；能达到投稿要求即可 final，不因由 agent 制作而永远标 draft。数据本身是图像时允许恰当分辨率的栅格图，不强制所有资产 SVG。

详情见 [视觉设计](../craft/visual-design.md)、[数值展示](../craft/numerical-display.md)、[示意图](../craft/schematic-figure.md) 和 [版式检查](../craft/visual-aesthetic-review.md)。
