# 目标 2：design-story（蓝图初建或重塑）

## 何时用

两个触发：**初建**（从零写，init-setup 后）和**重塑**（故事线实质变更——贡献变了、总论点变了；或 write-section 标了「蓝图脱节」；或修改清单含 re-frame 项；或 ingest-results 报**优势换位**——数据揭示更强卖点/原优势锚被证伪，见 blueprint-design 蓝图更新规则）。蓝图是**活文档**，不是一次写完的。

## 读哪些

- `references/sections/blueprint-design.md`（蓝图 schema + 节清单四步程序 + 三位一体 + refuted/abandoned 用法 + 活文档规则）。
- 初建：收口包 + `claims.json`。重塑：现有 `blueprint.md` + 成稿现状 + 触发材料。
- `paper-state.json`（venue 页限用于页数参考；节状态用于评估波及面）。

## 子动作

1. 读材料 → 出（或改）`blueprint.md` 的叙事主体：**故事线（一段连贯散文，人读核心）** + 总论点 + **核心优势锚**（一句话：本文赢的是哪场比赛，全文叙事围绕它组织；打不赢的维度不设为比赛）+ contribution 清单（2~3 句白话 + 对账字段：挂 claim / 验证维度 / 实验类型）。**不写段级大纲**；叙事主体禁工作语言（见 blueprint-design 写作纪律）。
2. **定节清单（设计决定，走 blueprint-design「节清单怎么定」四步程序）**：故事线拆叙事任务 → 往默认七节装箱（装不进去的过三条判据：任务独立 / 硬塞会污染 / 体量够节）→ venue 对标校准（authorkit 填充 tex 节结构 + 1~2 篇同 venue 同方向近两年论文）→ 节清单 + 每节角色标注定稿。随后按实际节清单写每节叙事任务（读者该相信什么 + 3~5 要点）+ **页数参考（消费 venue 页限，量级分配，软约束不硬卡）** + **首图（teaser）信息意图**（一张图说清问题+方法+效果——首图塑造故事线，蓝图阶段就定，不进正文才想）+ locked_decisions（末节对账区）。
3. 和用户逐项过：故事线讲得通不通、总论点立不立得住、**核心优势锚抓没抓对（本文赢的是哪场比赛）**、**节清单（有没有该立的节没立 / 该并的没并）**、contribution 分组、每节叙事任务、首图意图、页数参考量级对不对。用户质疑/调整 → 改 → 循环。
4. **重塑特有**：对比新旧蓝图，列出受波及的节（术语/gap/named-abstraction/contribution 变了的；**节清单变了的——新增/合并/删除节本身是实质变更**），**自动生成这些节的修订项进 backlog**（source=user 或 review-response，type=write-section）——故事变了，受波及的节必须排队回改，不许靠人记。

## 产出

`_draft/blueprint.md`（初版或新版）；重塑时外加一批波及节修订项。

## 状态更新

`blueprint_version` 递增；初建——注册各节写作项 + 首图项进 backlog（source=blueprint-init），sections 各节置 planned + 写 page_budget（参考量级，软约束）；重塑——受影响节 status 置 needs-revision + 修订项进 backlog。

## 确认点

**蓝图逐项过、满意才散**。初建后通常接 design-experiment（v1）；重塑后按生成的修订项排期。

## 易错点

- **蓝图是人读优先**——故事线段必须写连贯散文，叙事主体禁工作语言；产出先过「故事线一段读完不看其他材料能讲清论文吗」这条自查。
- **节清单是设计决定，不是默认七节照抄**——走四步程序（拆任务 → 装箱三判据 → venue 对标 → 定稿），和用户过；新节要有角色标注，决定 write-section 读哪个指南。
- **不写段级大纲**——段级结构留给 write-section 的方案子步即兴定。
- named-abstraction 必须**非 generic 词**（禁 "novel framework" 等），否则总论点立不住。
- **每个 contribution 必须有验证维度+实验类型**——没验证路径的 orphan contribution 蓝图层就标出来（补实验维度或砍）。
- **总论点/contribution 必须答得出「为何不是拼接」**——方法由多个组件/insight 构成时，说清组合产生了什么单拎任何一边都没有的东西（新能力 / 新视角 / 互相解除瓶颈）；答不出 = 缝合怪立论，reviewer 一问就塌，蓝图层就要打回故事线重想，别带着进写作。
- **故事线必须围绕核心优势锚组织**——不是按「我们先做了什么、后来尝试了什么」的工作汇报顺序展开，也不把打不赢的维度设成主战场；优势锚立不住（证据撑不起/其实不占优）就在蓝图层换锚重排，别带着进写作。
- **页数是软约束**——蓝图只记页限 + 参考分配（量级感知）；不在蓝图层砍 contribution/消融，取舍统一留给 finalize 压缩工序（用户拍板）。
- 三位一体在蓝图层就要锁（intro gap ↔ RW 定位 ↔ method 机制名 ↔ experiment 组件名）。
- **重塑必须生成波及节修订项**——只改蓝图不排回改，蓝图和成稿就会长成两个东西。
- **首图意图蓝图阶段定**——它塑造故事线；写正文时才想首图，故事已经散了。
