# 组织研究贡献与论文结构

读取 paper-package、实际证据、最接近工作、当前稿件和修改原因。使用 [结构指南](../sections/blueprint-design.md) 与 [研究记录](../research-records.md)。旧操作名保留兼容，不要求先确定一个占优指标。

1. 执行结构前自查：定义的问题、原有认识、新增或改变的知识、重要性及五项写作依据。区分已获支持、待检验、事后形成和已不再追踪，不把停止追踪当证伪。
2. 建立或更新 evidence-map。agent 主动检查最强反对证据、竞争解释、适用范围和收窄后的价值；不把这些判断留给用户凭直觉完成。
3. 用一段能独立理解的文字说明研究问题、已有认识不足、研究做法、实际发现和意义。理论/现象/评测论文按内容组织，不强制命名方法、贡献数量或七节结构。
4. 确定各章要解释的问题、依据与前置知识、术语及页数参考。避免用尚未介绍的方法解释基础概念；首图按实际沟通价值决定，不强制有图。规划必要正文与附录，而非全文写完才取舍。
5. 用户确认核心主张、重要范围/内容取舍；已有决定沿用。普通组织和措辞改进在授权内完成。
6. 研究判断或结构实质变化后执行变化影响检查，生成受影响章节、图表、引用、实验和数值记录的具体待办。核心结论动摇返回 iterate，不能只换论文结构。

保存带版本的 blueprint、证据表、关键自查和 state。细化段落可按需要，不禁止有效大纲；不因结构确认自动安排一批长周期 GPU 实验。
