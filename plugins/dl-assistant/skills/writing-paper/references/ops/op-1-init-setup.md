# 初始化材料、投稿要求与写作环境

1. 核用户目标、现有材料/论文根、编辑范围和授权。能从材料读到的信息不重复问。新稿读取 paper-package 或等价研究记录；改稿读取现稿和修改需求，不要求旧 spec.json、创新点清单或已定故事。
2. 核五项研究判断与当前条件，缺核心证据转研究讨论。允许先整理材料或草拟有明确占位的内容，不宣称具备完整写作依据。
3. 已有writing-paper-submission的官方要求记录可核适用性后复用，不强制重复查询。需要目标会议/期刊要求时，按 [投稿要求](../craft/venue-specs.md) 查适用年份、轨道、阶段的官方要求与模板，记录 URL、版本、日期、范围及冲突。没有目标 venue 可先写，不编造要求或期限。
4. 优先使用现有论文项目；新建时选择适用模板及实际主文件。Overleaf 不是必经项，仅按已有授权配置或同步，工具用法读对应 skill。不要求用户重建已有项目。
5. 保存 config：主文件、各节编辑来源、实际编译命令/工具链、材料与研究判断来源、工作记录备份方式、可同步范围和敏感内容边界。保护原 ignore 与用户改动，不存密钥。
6. 按需试编适用模板或现稿并读日志；已有论文不覆盖成模板 demo。工具缺失如实记录，可先继续授权的内容工作，不伪报编译或远端可用。
7. 初始化或增量恢复 paper-state；既有状态先与文件对照，不重置。登记投稿必需材料、研究未决、来源核查和写作任务。选题复盘可按用户需要追加到指定位置，不默认写跨项目文件。

产出 config、适用的 venue-contract.md/json、可恢复工作记录及下一步建议。只确认缺失且影响工作的选择、研究变化、资源或同步授权；不对已知信息连续设置确认点。
