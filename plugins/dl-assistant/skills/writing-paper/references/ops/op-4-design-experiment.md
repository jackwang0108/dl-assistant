# 规划一批论文补充实验

当提纲已经明确论文要主张什么，需要补一个可说明的比较、测量或分析时，填写本批计划。核心现象、机制或贡献本身仍待判断时，把受影响的主张和关键未知交回 `code-idea-iterate`。已有证据能回答问题时，先核是否可复用，再考虑新增运行。

## 准备材料

- 从 `_draft/blueprint.md`、论文准备材料及对应的 `claims.json` 和执行结论定位主张、已有证据、实际代码与适用范围。
- 用 `_draft/paper-state.json` 找已有批次、数据依赖、`experiments.new_needs` 和截稿日期。用用户认可的修改清单定位新增需求。
- 同时使用[人读计划模板](../templates/paper-experiment-plan-template.md)和[机读计划模板](../templates/paper-experiment-plan-template.json)。

## 逐步编写

1. **先做证据覆盖表。** 对每条受影响的论文主张，填已有证据及条件、当前缺口、需要的实验 ID 和仍无法回答的问题。可以按性能、组件、机制、泛化、效率、公平及定性例子查漏，逐项判断与主张是否相关。例如只主张在指定设备上的效率，就明确该边界，已有同设备基准也可复用。保留可比性、样本选择、重复或失败记录有缺口的项目。
2. **把每项实验写到能排程和审阅。** 为任务填写唯一的 `exp_id`、关联的论文主张及研究命题 ID、规模、代码或配置位置、模型或权重、数据划分、公平条件、关键测量和重复方案。在 `comparison` 写组别及控制条件，在 `measurements` 和 `replicates` 写指标、单位、统计方法和独立重复身份。在 `interpretation` 写预测、读数判据及其依据。分别说明什么结果支持、削弱、未能区分或无法比较。数值依据可以来自同协议下的已核波动、误差或研究意义。依据不足时说明待核项。后续解释仍须回实际测量和原始证据。
3. **分开填写投入和论文用途。** `priority` 说明这项取证在本批的优先级，`paper_locations` 列预计回填的章节、表格、图或附录。一项必要的可比性核查也可以放在附录。若必做项未能完成，如实保留它留下的证据缺口；实际投稿范围需要变更时，说明理由和影响，交用户确认。
4. **写真实依赖与停止点。** 只有依赖前置结果的实验才填对应 `depends_on`。例如使用主 run 的 checkpoint 作图时引用该实验。配置已确认时记录准确的版本。确需先选配置时，把选择依据、验收条件和用户确认写入前置任务。配置选择使用预先确定的验证数据，保留测试集用于正式评估。列出估算依据、所需资源、预期回包日期和到达资源上限或关键条件失效时的停止点。可独立运行的任务标为可并行。
5. **交审并交接已批准版本。** 核两份计划的实验 ID、比较、依赖、停止点与投入一致。检查有无重复实验、关键证据缺口或无法核实的配置。向用户说明本批预计回答的问题、投入及仍待确认项。在 JSON 的 `approval` 保存决定引用和获批实验集合，填唯一 `batch_id`。获批后将匹配的 `plan-vN.md`、`plan-vN.json` 和实际代码版本交 CPE。后续新增或实质修改任务时保存新的计划版本，保留原批准文件和决定。跨机器传输沿用项目约定。

## 产出与续做

- `_draft/experiments/plan-vN.md` 供人审阅，包含证据覆盖、依赖图、逐实验卡片和核查记录。相同版本的 `plan-vN.json` 供当前 CPE 读取。
- 在 `paper-state.json` 的 `experiments.batches` 登记 `batch_id`、`plan_version`、计划路径和实际状态，初始 `handoffs` 为空。在 `experiments.data_dependencies` 用 `batch_id` 和 `exp_id` 记录哪些主张、章节和图表在等待数据。把纳入计划的 `experiments.new_needs` 对应到该批。
- CPE 根据获批计划绑定 run-spec 和实际入口。执行侧报告条件变化时，先核是否影响比较、主张和投入，必要时确认受影响的修订。等待结果期间可推进独立的写作任务。有回包时按[结果导入手册](op-5-ingest-results.md)逐项核对。
