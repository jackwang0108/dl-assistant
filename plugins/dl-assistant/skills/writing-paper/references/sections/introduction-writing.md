# Introduction Writing

`writing-paper` 写引言的详细规则。引言是论文的"漏斗"——从大问题收敛到 contribution，也是三位一体的**「动机」面**（Introduction 讲动机 / Method 讲实现 / Experiment 讲证明）。reviewer 第一印象在这里形成。

## 起手时机

`blueprint.md` 定了引言的**节意图**（总论点 + contribution + 引言一句话意图）；**段级结构（每段写什么）在 write-section ① 方案定**（提 2-3 个写法方案时定段级），不在蓝图。起草顺序 **Related Work 先写**（锚定位），定位清楚后引言顺着写：

1. blueprint 定节意图（总论点 + contribution + 引言意图）。
2. write-section ① 方案定引言段级（5 个 goal → P1–P5，见下「默认结构」）。
3. Related Work 写完（gap/定位清楚）→ 引言按方案实写第一遍（contribution 数字可待数据批到了由 ingest-results 回填）。
4. 数据批到了 → ingest-results 回填引言 contribution 数字 / 润色 insight（全文定型，引言才准）。

## 默认结构 = 5 个写作决策点（goal）

挂靠 `blueprint.md` 的章节叙事"引言"，按 5 个 goal 展开（对应原 P1–P5）。**每个 goal 都有多条打法，先看「选择逻辑」定打法，再看 do / dont。**

| goal              | 作者在想什么                      | 对应段 |
| ----------------- | --------------------------------- | ------ |
| 1. 建立 stakes    | 大问题为什么值得做                | P1     |
| 2. 梳理 gap       | 现有路线卡在哪（要文献支撑）      | P2     |
| 3. 抛 key insight | 本文核心洞察一句话                | P3     |
| 4. 方法定位       | insight 怎么落成方法              | P4     |
| 5. 列贡献         | contribution 清单（可验证 claim） | P5     |
| （可选）路线图    | 章节预告导航                      | P6     |

## 逐 goal 写作技法

每个 goal 下：先「选择逻辑」（什么情况用什么打法），再 `✓ do`（推荐做法）和 `✗ dont`（反模式）平级列出。do 带「为什么好 / 怎么写 / 解剖」，dont 带「为什么坏 / 自查信号」。

### goal 1：建立 stakes —— 大问题为什么值得做

**选择逻辑**：正当性靠什么立？

- 任务有高层价值 / 广泛应用 → 任务价值 + 应用清单（配引用簇）
- 任务是学科基石 / 长期目标 → `long-standing goal` / `cornerstone` 定语
- 现实代价 / 部署紧迫 → 现实成本或部署趋势
- 有演化脉络 → 代际时间线（`from X to Y`）

- ✓ **do：漏斗式开场——宏观命题逐层收窄到具体任务**（大领域→子领域→任务→瓶颈）
    - 为什么好：降低读者进入门槛，为问题蓄势，自然落到本文 gap。
    - 解剖："With the rise in usage of generative AI systems, there is a growing need to distinguish content generated by a model from human-written content."〔宏观趋势→具体需求〕
- ✓ **do：应用清单建立重要性**——一串具体应用配引用，用数量与多样性倒推价值
    - 解剖："...has attracted attention in digital avatars, virtual reality, interactive entertainment, and online meetings..."〔应用清单 + 引用簇〕
- ✓ **do：学科级愿景/共识开篇**（`A long-standing goal in AI is...` / `cornerstone of...`）。
- ✗ **dont：用孤立短句/戏剧断言做枢纽**（"This capability is expensive." 单独成段）
    - 为什么坏：表演性修辞，靠一句口号"告诉"读者重要，而非让重要性从证据浮现；做作、自我感动。
    - 自查：出现单独成段的 3–6 词裸断言。
- ✗ **dont：用危机/伦理/道德色彩框架放大严重性**（带推销色，降低可信；同 abstract）。

### goal 2：梳理 gap —— 现有路线卡在哪（要文献支撑）

**选择逻辑**：你的 gap 是哪种？

- 前人方法在某边界失效、有数据 → `However` 钉具体失效（`fails / breaks down / lags`）
- 前人依赖一个不成立的隐含假设 → 揭假设（`implicitly assuming...which is violated`）
- 多类方法各有局限 → 二分/三分 taxonomy 逐类点局限
- 是普遍现象但没人命名定位 → 命名根因

- ✓ **do：让步转折先立再破**（`Although/Despite X...However Y`），gap 钉在可陈述的失效上
    - 为什么好：先公允承认前人贡献，再把缺口钉成一句可被引用的陈述，不 strawman。
    - 解剖："Despite tremendous progress in replacing artificial neurons with spiking counterparts, the broader use of SNNs for graph representation learning remains underexplored."〔让步+转折+hedged 空白〕
- ✓ **do：逐类拆解前人局限**——点名竞品（具体到作者/方法名），对每类先陈述做法再 `However` 点具体局限。
- ✓ **do：二分/三分 taxonomy 把领域方法结构化归类再否定**（`either A or B` / `fall into N categories`），为自己的中间地带腾位置。
- ✓ **do：招牌 gap 收束句**（`remains a challenging open question` / `remains unexplored`）正式坐实空白。
- ✗ **dont：多层转折螺旋堆叠**（同 abstract；intro 也易犯，自查 ≥2 层 However/Yet/Furthermore 链）。
- ✗ **dont：三连贬义词否定整条路线**（"often results in human biases, extraneous noises, and labor-intensive efforts"）
    - 为什么坏：三个笼统贬义词概括整条路线，不可证伪、不指向具体技术缺口，稻草人化对手。
    - 自查：一句里堆 ≥3 个贬义/负面词给整条研究路线扣帽子。

### goal 3：抛 key insight —— 本文核心洞察一句话

**选择逻辑**：你的核心是？

- 一个反直觉发现 → 反直觉钩子（`challenges the conventional wisdom` / `Remarkably`）
- 一个核心设计思想 → `key insight` 标签句（`Our key insight is that...`）
- 一个命名现象/术语 → 造词命名（`termed X` / `we refer to...as`）
- 一个待解问题 → 设问句（`This raises the central question: Can we...?`）

- ✓ **do：`key insight` 标签句把核心直觉/抉择前置成可检验论断**（放引言中段，不藏深处）
    - 解剖："Our key insight is that the interaction between a graph and a shared frozen encoder reveals its domain characteristics, which can be captured by a gradient fingerprint."〔一句话核心思想〕
- ✓ **do：为现象/gap 命名造词**铸可复用概念资产（`intention overfitting` / `trilemma` / `RoPE dilemma`，紧跟定义）。
- ✓ **do：设问句抛核心研究问题作叙事枢纽**，后续贡献对照回答（`To answer this, we...`）。
- ✗ **dont：把贡献写成客观规律断言而非第一人称**（"Model scale helps:... But the grade dimension dominates..."）
    - 为什么坏：模糊"贡献（我们做了什么）"与"发现（我们观察到什么）"的界限，把受限于设定的经验结果拔成普适规律，用虚假客观性回避对产出的所有权。
- ✗ **dont：用格言/对仗箴言当核心论点**（"The verifier itself can be automated; the artifact that resists automation is the specification."）
    - 为什么坏：追求对仗工整牺牲内容精确，记忆点替代论证，无法被证伪。

### goal 4：方法定位 —— insight 怎么落成方法

**选择逻辑**：方法怎么出场？

- 由 gap 倒逼 → `To address this gap, we propose` 桥接句
- 由洞察推出 → `Motivated/Inspired by this insight...`
- 对比定位 → `Unlike X that..., our Y`

- ✓ **do：`To address` 桥接句把方法显式挂回 gap**（`NAME` + 同位语一句话定位）。
- ✓ **do：`Inspired/Motivated by` 把方法动机绑到有据可循的依据**，让方法显得由证据驱动而非凭空。
- ✓ **do：`Unlike/In contrast` 显式差异化定位**（差异点要具体可检验），方法名做成自解释 named-abstraction（术语全篇一致）。
- ✗ **dont：gap→方法间插 `Consequently, X is imperative...` 必然性演绎句**（同 abstract）。

### goal 5：列贡献 —— contribution 清单

**选择逻辑**：贡献怎么组织？

- 做法+收益配对 → 每条动词+做法+`enabling/thereby` 收益
- 问题-方法-验证三层 → 按递进动词（`identify → propose → show`）
- 首创/范式级 → `the first` 放首条带 hedge

- ✓ **do：贡献写成做法+收益配对**（`We propose X that/which/enabling Y`），每条自带可核验回报
    - 解剖："We devise a DeepFake Fine-Grained Adapter that intertwines a shared branch with task-specific branches, enabling the detector to inherit fine-grained forgery..."〔做法 + enabling 收益〕
- ✓ **do：固定导语+编号+平行动词**（`Our contributions are threefold: (i) We propose... (ii)...`）。
- ✓ **do：挑战↔贡献编号镜像对应**（`G1↔method1`），让每个设计有出处、可追踪。
- ✓ **do：首创声明放首条带 hedge**（`To the best of our knowledge, the first...`）。
- ✗ **dont：贡献只是功能列表**（"我们实现了 X"）——每条 contribution = 可被实验验证的 claim，ref C-ID。
- ✗ **dont：贡献写成客观规律断言**（同 goal 3 的反模式）。

### goal 6（可选）：路线图导航

- ✓ **do：引言末尾路线图段**（`The paper is structured as follows: Sec 2 reviews..., Sec 3 introduces...`）。
- ✓ **do：贡献条尾嵌章节锚点**（`(§3)(§4)`），让贡献清单兼做目录。

## 全节自查（反模式信号清单）

写完逐条勾：

- [ ] 开头是否用了孤立短句/戏剧断言单独成段（"This capability is expensive."）？
- [ ] gap 是否**没被文献/观察支撑**（strawman）？是否堆三连贬义词给整条路线扣帽子？
- [ ] gap 是否多层螺旋堆叠（≥2 层 However/Yet/Furthermore）？
- [ ] 核心论点是否写成了**客观规律断言**（非第一人称）或**格言对仗箴言**？
- [ ] gap→方法间是否插了 `Consequently, X is imperative` 必然性演绎句？
- [ ] contribution 是否只是功能列表（非可验证 claim）？是否写成客观规律断言？
- [ ] （现有保留）问题重要性是否立得住（防 reviewer "so what?"）？insight 是否先于机制（不堆模块名）？named-abstraction 是否立住（非 generic 词如 "novel framework"）？每条 contribution Method/Experiment 是否兑现？

## 与全文协同（三位一体锁死）

- contribution 列表 = `blueprint.md` 的 Contribution 投影（首次完整呈现，后文逐条兑现）。
- P1 的问题 = Abstract 第 1 句；P2 的 gap = Related Work taxonomy 终点 = Abstract 第 2 句。
- P4 的关键机制名 = Method 的机制名 = 架构图模块名 = `blueprint.md` 的 named-abstraction。

## 文风 lint

写完按句段、字词和常见生成式写作问题三类写作要求 跑一遍（`sentence-craft.md` + `word-craft.md` + `anti-ai-patterns.md`，句段/字词/AI 跨节通用；论证层查本节 checklist）。
