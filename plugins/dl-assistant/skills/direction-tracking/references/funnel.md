# 相关性检查、正文核查与阅读建议

## 第一轮：相关性

子 agent 接收本次配置快照、被分配的完整摘要与来源、独立输出路径。每篇用包含/排除/边界定义给出：相关、不相关或待判断，附具体理由和对应范围。关键词命中、引用了种子、来自会议都不能单独证明相关。

不相关的保存排除理由；边界案例、摘要缺失或无法可靠判断的进入待核查。相关项进入正文核查或按用户批准范围先以摘要级记录收录。每个分片写 `runs/<run>/round1/part-<编号>.md`；主 agent 核对所有输入身份恰好被处理一次，失败分片保留待办。

## 第二轮：正文与证据

参照 `arxiv-daily-paper` 的 [正文检查原则](../../arxiv-daily-paper/references/round2-quantitative.md)，按论文类型核查，不能用 baseline 年份/数量、算力、录用信息或代码链接简单代替质量。

源码优先，失败时使用可解析的 PDF；按所引用参考中的下载检查要求保存文件并核对实际版本。文件名兼容旧式 ID 中的斜杠。记录来源、章节/页码与阅读范围，不能把读摘要写成读全文。

会议论文与预印本使用相同证据标准。用户只批准快速浏览时可以不取正文，但标为摘要级、证据未核实，不以录用免检。正文不可用、复现条件不足或实验支持弱时分别说明，不自动判不相关或从累计库删除。

每篇记录研究问题、作者论点、可核查结果与条件、证据支持/不足/相反之处、资源可用性及待核查事项。作者报告不等于独立复现；与已有工作的差异只记待核查线索，不在此确认创新性。

分片内使用互不重叠的论文，每篇写独立的 `round2/<安全版本ID>.md`。arXiv 旧式 ID 中的斜杠用下划线表示。仅有 DOI 或 URL 时用可追溯的文件标识，在记录中保留原身份。主 agent 更新处理事件与累计文件。

## 数量与确认

候选多时分批处理，用户确认评估预算。预算控制本次做多少，不是只保留多少；会议抽样、关键词预筛或引用者截取都明确范围，未处理部分不能冒充已排除。派遣前确认与中途汇报沿用入口规则。

## 推荐理由与阅读问题

主 agent 组织报告，通常选 3–5 篇重点，其余相关项仍可进入累计库。每篇重点解释为何值得读，并给一个具体阅读问题。例如作者声称改善组合泛化时，可问“测试是否包含训练未见的属性组合，能否排除单纯增加数据量的解释？”问题须从真实摘要或正文出发，不暗示未证实的缺陷，不编造章节位置。

分别展示首次发现与旧论文更新；更新要说明对照版本和实质变化。没有新版正文对照时只说版本已更新、内容待核查，不直接称为重要进展。未读全文也可建议用户深读，但必须说明当前判断层次。

种子新增只作提名，用户确认后更新配置，并按生命周期规则确定引用检索回补范围。
