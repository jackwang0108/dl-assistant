# 相关性筛选、量化评估与简报

## R1 相关性筛选

子 agent 分批阅读摘要，必要时补看少量元数据。根据方向配置（`direction`、`keywords` 和种子论文的主题）判断每篇是否相关。

- **相关**：进入 R2。
- **不相关**：保留在 seen 记录中，不加入 library。

每篇只给「相关」或「不相关」及一句理由，不打分。关键词命中但主题不同的 A 类结果，以及引用种子论文但主题不同的 B 类结果，都应判为不相关。

> 本技能把方向相关性作为筛选条件。`arxiv-daily-paper` 用研究方向决定展示优先级。

### 委派 R1 任务

- 委派前告诉用户候选篇数、分批数量及各批要做的工作，由用户确认后开始。
- 一律使用能读 PDF 和写文件的 `general-purpose`，禁用 `Explore`。
- 每批收到候选论文的标题、摘要、元数据和方向配置。
- 将每篇的相关性判断和一句理由保存到文件，只向主会话返回简要清单。

## R2 逐篇量化评估

子 agent 下载 PDF，阅读 Experiment 和 Related Work，记录对比基线的年份与数量、是否包含 SOTA、实验规模、算力和可复现性。

直接使用 `arxiv-daily-paper/references/round2-quantitative.md` 的评估标准和字段。

- **C 类会议论文**已通过同行评审，只看摘要和元数据，做简要评估，跳过 PDF 下载。
- 量化证据较弱或不可复现的论文不通过此轮。

### 委派 R2 任务

- 委派前告诉用户 R1 通过了多少篇、R2 准备分几批，等用户确认后开始。
- 一律使用能下载 PDF、阅读实验部分和写文件的 `general-purpose`，禁用 `Explore`。
- 每批收到通过 R1 的候选论文 PDF。C 类按前述规则使用摘要和元数据。
- 按 arxiv-daily 第 2 轮的字段保存逐篇量化评估记录。

## 主会话撰写简报

将 R1 对相关性的说明和 R2 的评估要点写入简报。条目格式见 `output-contract.md`。在条目中标记「值得深读」的论文，全文精读交给 `paper-reading`。

在本次 runs 简报末尾添加 **「推荐继续阅读或用于选题的论文」**。列出 3–5 篇，逐篇给出 arXiv ID 和具体理由。优先推荐已标记「值得深读」的论文和被提名为新种子的论文。说明每篇为什么值得 `paper-reading` 精读，或为什么适合 `idea-find` 作为选题起点。

## 候选较多时如何限制数量

- **首次收集**：对 B 类引用者按发表时间保留最近 N 篇，默认约 50 篇，见 `lifecycle.md`。
- **会议候选较多时**（例如 CVPR 约 2000 篇）：将候选分批交给 R1，必要时先按关键词初筛或抽样。
- **常规更新**：细分方向一周通常新增几篇至十几篇，一般无需额外限制数量。

## 何时请用户确认

- **常规更新**：筛选前集中确认一次，说明候选篇数和 R1、R2 各分几批。
- **首次收集或会议查询的候选较多时**：R1 结束后再汇报相关论文的篇数，并请用户确认是否进入 R2。
