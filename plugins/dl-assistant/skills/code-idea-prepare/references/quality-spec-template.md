# 质量改动方案模板

本文件提供可复制的 `quality-spec.md` 和完整填写示例，用于记录有具体依据的结构整理和行为修复建议。调查时用[结构整理与行为修复指引](quality-guide.md)，在[运行手册 Step 3](workflow.md#step-3-写方案和前后验证办法)提交方案。

有质量改动建议时建立此文档。已在 `cleanup-spec.md` 写过的保留范围、改前 run 和共同检查可以直接引用。记录每项的实际影响、批准情况和验证依据。

## 可复制模板

````markdown
# {仓库名} · 质量改动方案

- 起点与依据 | {版本、相关 diff、环境和改前 run；已有清理方案可引用}
- 目标与范围 | {具体阅读或开发困难、拟处理的入口和调用方}
- 状态 | {待审、确认的版本及范围，或暂缓及原因}

## 1. 逐项建议及影响

| ID 与位置 | 实际问题与证据 | 类型与拟议变化 | 要保留的行为、预期变化与兼容影响 | 建议及确认 |
| --- | --- | --- | --- | --- |
| {Q-01} | {触发输入、源码、日志或调用关系} | {保持行为的整理／经确认移除的功能／有意改变行为的修复} | {正常与异常行为、调用方、接口、历史资产和原复现证据} | {做或暂缓，依据、待核事项和批准情况} |

## 2. 改前、改后检查

| 检查 ID 与关联改动 | 改前证据或待补证据 | 改后操作、预期与比较依据 | 证据位置及限度 |
| --- | --- | --- | --- |
| {CHECK-01} | {原运行、输入、配置、输出或异常} | {同输入前后比对，或异常输入验证新行为并用正常输入复核} | {run、日志、读数和未覆盖范围} |

## 3. 批次、预算与撤销

| 批次与改动 | 检查、先后与预计成本 | 停止和局部撤销办法 |
| --- | --- | --- |
| {B01、Q-01} | {逐批检查、最终复核、前置条件和投入} | {本批路径和经检查的撤销范围，何时需重新审阅} |

## 4. 待确认与交接

- {各项实际决定、确认出处和范围}
- {仍需验证的兼容性、受影响的原复现结论及接手阶段}
```

## 完整填写示例 · edge-vision 的评测结构与异常处理

沿用[运行手册](workflow.md#贯穿示例--edge-vision-的评测入口整理)的虚构仓库和改前评测。异常输入、成本和待审决定用于示范填写。

````markdown
# edge-vision · 质量改动方案

- 起点与依据 | c91b7e4，计划使用 code/baseline-cleanup 分支和 edge-dev-01 的 /srv/envs/edge-vision/bin/python。正式评测和保留用途见 cleanup-spec.md 的 USE-01、USE-02 与 EVAL-01 v1 的 eval-attempt-02。
- 目标与范围 | 让读者能从 tools/eval.py 一处跟到实际配置，另评估缺标签时能否及时给出明确错误。
- 状态 | 待审。建议先做 Q-01，Q-02 单独确认影响和补证范围。

## 1. 逐项建议及影响

| ID 与位置 | 实际问题与证据 | 类型与拟议变化 | 要保留的行为、预期变化与兼容影响 | 建议及确认 |
| --- | --- | --- | --- | --- |
| Q-01，tools/eval.py | CLI 参数与文件默认值在两处合并，需要沿包装函数才能判断生效顺序 | 保持行为的整理。将配置解析收在一处，沿用现有参数、默认值和覆盖顺序 | 保持解析值、EMA 分支、数据清单和 Top-1 聚合，同样支持正式配置调用旧模型 | 建议先做，待确认 |
| Q-02，评测 loader 的缺标签分支 | 用三条样本的本地诊断清单复现。第二条缺标签，当前跳过它并以其余两条计算指标，退出码为 0 | 有意改变行为的修复。遇到缺标签时退出并说明具体样本 | 正常清单继续按原定义评测。异常清单计划返回非零退出码并报缺失 ID。调用方可能因失败状态而重试或停止，原先依赖跳过行为的结果需要单独说明 | 单列待审。先核项目任务脚本如何处理非零状态，确认是否接受该变化 |

## 2. 改前、改后检查

| 检查 ID 与关联改动 | 改前证据或待补证据 | 改后操作、预期与比较依据 | 证据位置及限度 |
| --- | --- | --- | --- |
| CHECK-Q01，Q-01 | eval-attempt-02 的 EMA、500 个样本 ID 与 392/500。改前补一份配置解析记录，包含一个确实被 CLI 覆盖的键及生效值 | 用同一正式命令和一次带覆盖项的短跑，分别对照解析值及顺序。完整评测核 EMA、500 个 ID 各计一次和正确计数 392 | 解析记录及评测配置、日志、ID 和指标存入独立 run。旧模型兼容路径在本轮仅核配置与注册引用 |
| CHECK-Q02，Q-02 | 缺标签诊断输入的三条 ID、原退出码 0 和实际分母 2。正常输入可复用 Q-01 的正式配置和评测基准 | 获准后在独立批次复用三条诊断输入，核非零退出码、错误消息包含缺失 ID，且没有发布可误用的部分指标。用完整合法清单核 500 个样本和 392 个正确，并核确有受影响的调用脚本 | 保存异常尝试的退出码和日志、正常复跑的 ID、指标及实际调用方核对结果。本轮覆盖指定缺标签场景 |

## 3. 批次、预算与撤销

| 批次与改动 | 检查、先后与预计成本 | 停止和局部撤销办法 |
| --- | --- | --- |
| B01，Q-01 | 先核 CLI 覆盖和配置读回，再按 CHECK-Q01 完整评测。预算以同机复现耗时估计，完整评测申请单卡最多 30 分钟 | 发现配置、权重或统计差异时保存证据，定位并撤销本批配置读取改动，再复核受影响的检查 |
| B02，Q-02 | 单独确认后先跑异常诊断，再按 CHECK-Q02 核正常评测。预计需要一次短诊断及一轮完整评测。单独确认预算 | 若调用方依赖原退出方式，先交审新影响。需要撤销时只恢复缺标签分支和对应的检查改动，保留已验证的结构整理 |

## 4. 待确认与交接

- 建议先确认 B01。B02 待确认新的缺标签处理和调用方影响后再排执行。
- 本轮比较固定发布权重下的评测。完整训练、旧模型的实际评测和其他异常输入不在当前实跑范围。
- 若采用 B02，交付说明异常清单的处理差异，标出哪些旧结果需要按实际样本覆盖复核。
```
