# 质量优化方案 Spec 模板（code-idea-prepare · quality-spec）

> CIP 质量优化阶段（改法不改行为）的方案，**用户审过才执行**。**只动 reproduction 覆盖的核心路径**。
> 契约：性能严格相等（行为等价）。数值稳定性类改动可能改变实验结果，须逐项标明风险并请用户确认。
> 保存 `quality-spec.md`。

---

````markdown
# Quality Spec: <repo-name>

> 质量优化方案（改法不改行为）。审阅通过后才执行。鲁棒性/数值稳定性项逐项确认。

## 0. 优化空间摘要（来自质量审查）

- 质量优化空间：高 / 中 / 低
- 范围：**只针对核心路径**（reproduction 覆盖的）。未覆盖代码不优化（记 uncovered）

## 1. 健壮性（低风险 · 自主做）

| 位置 | 问题 | 优化（加校验/错误处理/边界） | 风险 |
|---|---|---|---|
| `data/loader.py:42` | 输入可能 None 未校验 | 加 None check + 明确报错 | 低·不改主逻辑 |
| `train.py:120` | 捕获所有 Exception 后未记录或抛出错误 | 只捕获相关异常并记录错误 | 低 |

## 2. 简化不必要的抽象层（中风险 · 自主做 + smoke）

> 对照 `coverage/hot-path.md`，优先简化训练主循环和模型前向调用中的多余层。少用的脚本和一次性工具按需处理。

| 位置 | 问题 | 优化（简化/扁平化） | 风险 |
|---|---|---|---|
| `models/wrapper.py` | 5 层包装仅转发调用 | 去掉多余的中间层 | 中·结构变逻辑不变 |
| `configs/` | 过度配置化（从不用的开关） | 删除确认未使用的配置项 | 中 |

## 3. 鲁棒性 / 数值稳定性（高风险，逐项请用户确认）

| 位置 | 问题 | 建议优化 | 风险 | 用户决策 |
|---|---|---|---|---|
| `loss.py:88` | 除零风险（理论上） | 加 epsilon | **高·可能微改数值→性能变** | 待用户确认 |
| `models/head.py` | softmax 溢出 | clamp logits | **高** | 待用户确认 |

> 这类改动**停下问用户**：解释"加 epsilon/clamp 可能让 metric 偏 X，破坏严格相等"，用户决定做不做。用户同意并实施后，在性能验证时重点核对相关指标。

## 4. 不做的（边界）

- **不改算法逻辑/实验语义**（归 execution）——质量优化只做行为等价 refactor
- **不优化未覆盖代码**（记 uncovered 交 execution）
- **不为优化而优化**——核心路径已够好就不动；研究代码不是生产代码，不必追完美

## 5. 执行 + 验证

- 健壮性 + 简化不必要的抽象层：自主做，每类改完 smoke
- 鲁棒性：即停问用户，确认才做
- 全部完成 → 完整性能验证（严格相等 ±0.1%，见 `verification-strategy.md`）

## 6. 用户确认

- [ ] 健壮性/简化不必要的抽象层清单认可
- [ ] 鲁棒性即停项逐项确认（做 / 不做）
- [ ] 同意边界（不改算法 / 不碰未覆盖 / 不追完美）
````

---

## 模板使用说明

- **质量优化的红线是"行为等价"**：加校验、简化结构、防崩溃可以；改算法数值（epsilon/clamp/截断）即停。
- **鲁棒性优化要诚实标注代价**：加 epsilon 防除零 = 数值微变 = 可能破坏 ±0.1%。让用户知情决策。
- **研究代码 ≠ 生产代码**：不要把 baseline 重构成生产级（过度抽象/全类型标注/全覆盖测试）——那会偏离作者意图、增加 execution 阅读负担。只清掉真碍事的。
