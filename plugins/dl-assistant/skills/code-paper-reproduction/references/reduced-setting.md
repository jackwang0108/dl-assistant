# Reduced 训练配置

本文件说明怎样为重复实验选择低成本的训练配置，核对缩减后是否保留了要研究的现象，并用实测对照决定哪些用途可以留在小规模、哪些决定需要升到更接近正式条件的规模验证。

**中期决策真正需要的证据是：同一个改动相对同一个基线的收益，会不会随着规模变小、消失或反向？**

在[运行手册 Step 5](workflow.md#step-5-按需准备-reduced-迭代配置)使用。运行成本、实际观察和适用范围随[复现报告与机读交接](reproduction-report-template.md)交付。

## 1. 从用途和实测成本选择候选配置

1. **写清下一步要做的判断。** 基线回归需要能重复执行的命令和可核对的结果。组件诊断需要能触发目标现象的输入和训练阶段。若要用小规模结果决定一种方法是否值得继续，还要有与同一基线比较的证据，并说明该比较是否需要升档。用完整小设定复现论文单列所对照的参考行和范围。
2. **先核目标配置本身的成本。** 从已有运行取目标机、设备数、精度、每步耗时、训练步数、评测和保存频率。已有记录不足时，按批准范围用候选命令短跑到吞吐稳定，从日志取每个优化器更新的耗时，同时记录启动和数据加载开销。用「稳定后的每次更新耗时 × 计划更新次数 + 启动、评测和保存开销」估算一轮。如果日志按 microbatch 计时，先按梯度累积和实际更新频率换到同一单位。标明哪些是实测、哪些是估计。
3. **对照预算推荐首档。** 目标配置已在迭代预算内时，直接用目标配置。否则从实际需要保留的条件出发，估算符合用途的候选档位，解释推荐档的成本、覆盖和风险。若可负担的配置缺关键条件，提出能做的局部检查，或说明目标规模迭代需要的资源和周期，由用户确认。
4. **交审后执行。** 给出首档、预计投入、拟用的已有或获准对照，以及触发升档的观察。按[运行手册 Step 3](workflow.md#step-3-按目标执行评测训练或组件检查)托管长任务。实际耗时或峰值显存偏离估算时，更新记录和下一档成本，需要追加投入时回审。

## 2. 逐项核对缩减后还保留了什么

在 `alignment.md` 或其引用的配置记录中写明目标条件、候选条件、改动理由、核查办法及对结论的影响。先找出决定研究现象和测量能力的条件，再决定缩减项。优先保留与当前研究问题直接相关的模型容量、输入、数据组成、必要训练阶段和指标口径。

| 条件 | 怎样核对 | 发现差异时怎样处理 |
| --- | --- | --- |
| 训练数据量与组成 | 记录原数据版本、抽样规则和 seed，固定可复用的样本 ID 清单。对照完整数据，统计各来源、类别、关键分组和稀有场景的数量，核标签和文件仍可由实际 loader 读取。多来源训练同时查实际采样权重 | 优先补齐影响目标现象的样本，或改用更大的档位。比如改动针对小目标，核含小目标的样本数和实例数，再确认评测能单独读出该组。覆盖仍不足时，缩小可交付用途 |
| 验证集与指标 | 核能否沿用正式验证集、标签映射、预处理和聚合方式，保存实际参与统计的 ID 或分组计数 | 必须缩验证集时，记录固定清单及被排除的分组。各档若使用不同验证范围或指标，先建立共同评测或限定为各档内观察 |
| 模型、输入和优化设置 | 对照模型与初始化、输入分辨率或长度、预处理、增强、精度、每卡 batch、累积、归约和 BN。用实际生效配置与运行日志核对 | 先判断改动是否触及要研究的机制。若同时改变数据量和模型容量等条件，就把证据解释到这组条件，记录哪些变化还需单独核查 |
| 训练长度与调度 | 用实际 loader 长度和日志核优化器更新次数、样本暴露、warmup、衰减、EMA 更新及 checkpoint 选择时点，并标明预期现象在哪个训练阶段出现 | 依据研究问题说明是否保持 epoch、更新预算或指定阶段。需要换算时写出依据并核生效值。关键现象可能晚于停止点时，延长到必要阶段或限定为早期行为检查 |

每档保留实际配置、覆盖项、子集清单和生成方法。基线走一次正式的该档命令，核实际样本、阶段和指标，以及每轮时间、峰值显存等资源。只有局部检查时，按实际覆盖说明用途。

## 3. 在每档内部比较，再核对规模变化

1. **先决定用哪个对照。** 优先用已有、与当前方法问题有关且条件可追溯的原论文消融、现有实验或获准改动。说明它能检查什么，以及为什么与后续决策有关。缺合适对照时，先交付小规模的基线和成本，将跨规模收益记为未知。
2. **每档配同一基线和同一改动。** 在每档内固定子集、初始化或配对 seed、训练阶段、预算、评测清单和指标，注明实际还能控制哪些条件。用同一个研究改动比较各档，逐项记录不能固定的差异。已有运行可引用，先核代码、实际配置和证据是否可比。
3. **保存逐对读数并按问题解释。** 每对记录基线 run、对照 run、原始值、单位和差值。指标越低越好时，先写差值定义及改善方向。记录档内重复单位、次数、逐对差值和波动。需要区分随机波动时，依据当前疑点设计追加观测。某一档仅有一次时，只交付该次差值及未测的波动。
4. **先决定什么观察会触发升档。** 升档前核子集组成和实际调度等条件，确认变化来自何种比较范围。可只跑能影响当前决定的档位和对照。旧项目中按规模拟合得到的标记保留作历史记录，实际判断引用有条件可核的原始运行。

| 得到什么证据 | 当前用途和下一步 |
| --- | --- |
| 只有基线、只有一档，或较大档没有同一对照 | 交付已跑配置的基线、成本和覆盖。跨规模收益记为未知。若下一步必须据此取舍，补同一对照或直接在更适合的档位验证 |
| 同一改动在两档内方向一致，幅度有差别 | 记录该改动在实测条件下的方向和幅度。可据此安排后续检查，新的候选和正式收益按各自问题验证 |
| 较小档收益减弱、消失或反向，且档内观测支持这一判断 | 标记该改动对已测条件的规模变化敏感。小档用于复跑基线和局部诊断。用更合适的档位复核同类方法的取舍，按需要重查此前仅因小档结果被淘汰的候选 |
| 档内波动或关键条件差异让方向难以判断 | 写待区分的原因，选有信息量的一项补查，例如固定同一验证集、补关键分组或增加有条件可比的配对。预算不足时交付限制和升档条件 |

## 4. 完整示例 · 两档内方向稳定，跨档反向

以下是[运行手册示例](workflow.md#贯穿示例--从-17-样本试跑到复现标定)里的虚构可选训练分支。后续要反复训练，建议先用 30% 档测基线和局部行为，并用已有或获准的 60% 档对照核对方法收益的方向。两档使用同一验证清单、指标、模型和评测代码。各档固定各自的训练子集和协议，基线与消融只切换同一个模块，按 seed 配对。表中耗时是本例的单次实测，原始值均为 Top-1。

| 训练档位、配对 seed | 基线 run 与读数 | 消融 run 与读数 | 消融 − 基线（百分点） | 耗时（基线／消融） |
| --- | --- | --- | --- | --- |
| 30%，42 | reduced30-base-s42，74.0% | reduced30-ablation-s42，73.0% | −1.0 | 54／53 分钟 |
| 30%，43 | reduced30-base-s43，74.2% | reduced30-ablation-s43，73.0% | −1.2 | 55／54 分钟 |
| 60%，42 | reduced60-base-s42，76.0% | reduced60-ablation-s42，76.6% | +0.6 | 101／99 分钟 |
| 60%，43 | reduced60-base-s43，76.2% | reduced60-ablation-s43，77.0% | +0.8 | 102／100 分钟 |

两对观测在各档内方向一致，平均差值分别为 −1.1 和 +0.7 个百分点。先查两份子集对关键分组的覆盖、以及两档训练实际达到的阶段，保存任何差异。交付 30% 档供基线复跑和局部诊断。若要凭低档结果淘汰同类候选，升到 60% 复核；此前仅凭 30% 结果淘汰且仍值得做的候选，也按该条件重查。论文主张的收益按获准方案在正式条件下验证。这组证据覆盖该消融、已测两档和实际重复范围。

## 5. 交付格式

在 `reproduction.json` 按需保存 `reduced_setting`，在 `report.md` 说明用途、实测证据和升档条件。运行 ID 指向机读的 `runs` 记录及各自证据。候选阶段标 `proposed`，在规格或待办保留计划命令。实跑后标 `executed`，交付当前可复跑的入口及范围。可选的 `noise_floor` 仅在有同配置重复时保存原始读数、统计量定义、单位和引用。
