# 本轮复现与验证规格

保存spec.md。来源为实际setup/survey、研究说明与原文/发布记录。已有授权沿用，实质变化与未定投入才讨论；不能要求信息不足时先填一组数字假装可判定。

```markdown
# 逐目标复现与验证
> 当前日期、项目/组件/环境/代码版本、来源记录及批准范围。

## 1. 目标清单
目标ID | 需求/组件/来源待办 | 原条件复现或改条件验证 | 参考结果/行为及出处 | 本轮要判断什么
无官方权重、论文表格或数值指标时说明可用相关参照和限制，不编目标。

## 2. 每项目标的协议与可比性
协议ID/版本及来源，明确代码/config、模型/权重/初始化、数据/split/单位、预处理/采样/增强、指标/聚合、训练/保存/选择和相关设备/精度/随机性。
原条件、当前拟执行条件，哪些相同/不同/未定及影响；条件变更不覆盖原记录。

## 3. 取证方案与解释规则
需要评测、训练还是行为检查，必要前置及已有证据复用范围。
要观察什么、比较方法及依据，数值误差/抽样/运行随机性分别处理。
重复/seed/选择过程、追加/停止规则、无参照或证据不足时如何如实交付；不套任务默认容差或2×std。

## 4. 执行与预算
实际组件/环境、代码commit+diff、命令候选/config/资产身份、日志与输出位置。
未跑入口标未验证；成本估计依据/未知、已批准投入、依赖/并行与暂停条件。
允许的工程修复和需重新讨论的数据/协议/方法变化；不默认选型替换或调参追数。

## 5. 执行前自查
目标条件明确吗？参考/可比性核实了吗？判据与不确定性有依据吗？授权/预算/改变范围明确吗？
每项给clear/limited/needs_revision、来源、未知与行动影响；需要修正就先处理，不补任意数值。

## 6. 交付边界
本轮最多能支持哪些具体用途，哪些条件/规模/训练部分未覆盖；差距原因可能未知。
需要低成本配置时单独说明问题与代价，不强制scaling扫描或外推认证。
```

固定某次协议用于保留原比较条件，不是宣布它永远正确。更改需新版本、依据与实际授权，重核相应可比性；旧结果/预期保留。部分前置阻塞不阻止无关且已授权的验证，不因完整spec还未形成就自动开长训练。
