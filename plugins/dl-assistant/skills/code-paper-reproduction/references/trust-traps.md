# 复现差异排查

本文件说明怎样从实际复现结果出发，核对论文参考条件与本次运行证据，选择能区分可能原因的最小检查，并把排查结论写入 `alignment.md`。

在[运行手册 Step 4](workflow.md#step-4-核对可比性与实际差距)使用。目标和验收依据见[复现策略](reproduction-strategy.md)，按[核对模板](alignment-template.md)记录参考要求、实跑条件、排查动作和结论的变化。结果低于、接近或高于参考值时，都先查比较条件。用实际发现决定下一项查什么。

## 1. 先确定在比较什么

1. **定位参考结果。** 打开已确认的论文版本，核对 spec 中的表格行、列、图例或组件行为，以及对应的模型、数据划分、指标定义和单位。读图注、实验设置、附录与发布记录，确认报告的是固定权重的一次评测、最佳结果还是多次运行的统计。参考条件缺失或来源有冲突时，在 `alignment.md` 标为未知并写明影响。
2. **还原本次实际运行。** 从对应 run 的 `meta.json`、`command.sh`、解析后的配置、日志、`metrics.json` 和输出追踪执行路径。核对退出状态、实际加载的数据和权重、进入指标的样本，以及输出是否完整。配置说明准备使用的条件，日志、运行产物和实际调用分支用来核实生效条件。运行证据不足时，优先选能补到证据的短检查。
3. **写出观察和要区分的原因。** 记录参考与实测读数、单位、范围和证据位置。把实际条件不同、实现行为异常、参考信息不足和随机波动分别写清，保留能解释现象的候选原因及支持、反对证据。比如两次 top-1 相近但分母不同，先确定是否在统计同一批样本，再解释差值。

## 2. 按评测现象选检查

| 观察到什么 | 先打开什么、具体查什么 | 证据怎样改变判断 |
| --- | --- | --- |
| 参考身份不明，或结果更像表中另一行 | 回查表格标题、行列和脚注，再核模型变体、输入尺寸、发布版本和训练预算 | 找错行就先纠正引用。需要改变已确认的比较对象时，回 Step 2 确认后更新协议 |
| 指标同名，读数或分母对不上 | 从评测入口跟到实际指标实现和调用参数。检查分子、分母、单位、样本或分组聚合。检测核 IoU 阈值和类别，分割核忽略标签与全局或逐图聚合，生成核特征提取器、预处理和样本数，检索核查询方向与候选集合 | 有定义差异时记录具体项。若实现仍有疑问，取一组能区分两种定义的已知答案走同一指标入口，保存输入、预期和输出 |
| 样本数不符，或读数异常高低 | 读数据加载、过滤、采样和指标汇总路径，核真实清单版本与路径。导出实际计入指标的 ID 和出现次数，对照参考清单，检查遗漏、重复、末批和分布式汇总。怀疑数据重叠时按可取得的 ID、内容指纹或来源记录核查 | 找到不同划分或覆盖范围，就明确哪些结果还能使用。高分、满分、零分均按任务预期和评测证据解释。重叠检查注明覆盖的来源和范围 |
| 权重来源不清，或同一模型有多组参数 | 对照论文和发布说明，读模型构建、checkpoint 加载和选择分支。核实际文件、模型结构、raw／EMA、best／last、参数映射与加载结果。遇到 missing 或 unexpected keys 时定位到实际层，核哪些参数有意跳过、如何初始化及其依据 | 已确认文件和加载分支后才记录权重身份。关键参数来源不明或映射无依据时，保留可比性待定。需要修改加载行为时按实际影响走确认 |
| 输入、推理或后处理可能不同 | 对照论文实验设置与本次实际 eval pipeline。核输入尺寸、归一化、测试时增强、滑窗或多尺度、采样或解码、后处理和多次预测的聚合 | 明确究竟是哪项协议不同。核对代码与真实执行分支后，按批准范围选择单项检查，避免同时改几项再用结果倒推原因 |

命令从本项目的 `command.sh` 和实际路径取。先定位真实配置、入口和输出，再用 `rg -n 'checkpoint|weights|ema' <配置> <评测入口> <运行日志>` 查关键位置，沿调用返回加载实现。这里的路径占位符需要换成当前 run 的文件。关键词用于定位，报告引用读到的配置值、源码分支和日志证据。对于要求每个样本计入一次的协议，两份清单各行一个 ID 时，可用 `diff -u <(sort expected-ids.txt) <(sort evaluated-ids.txt)` 查遗漏和重复。协议允许重复时，按协议核每个 ID 的预期次数。

## 3. 按训练差异出现的位置排查

先确认差距出现在哪里。比较曲线前，对齐指标定义、横轴与记录频率，尤其区分 epoch、microbatch、优化器更新步和实际样本数。若只有重训 checkpoint 的最终评测不同，先按第 2 节核评测。发布权重的评测证据只覆盖其经过的路径，训练需要自己的证据。

| 观察到什么 | 具体检查与可保留的证据 |
| --- | --- |
| 初始 loss 就不同，或开始训练后很快偏离 | 从实际 batch 记录样本、标签、掩码、训练预处理和增强，检查预训练初始化、初始预测和目标函数的实际输入。比较首批分项 loss、参与归约的元素数和优化器是否真实更新。必要时用第 4 节的小检查区分不同原因 |
| 换了卡数或累积后，更新行为不同 | 读 trainer 的 forward、backward、同步、累积和 `optimizer.step()`。记录每卡 microbatch、参与的进程数、每次更新实际收到的样本数及末批。分别核 loss 的 mean／sum、梯度同步和累积归一化。再核 BN 是普通、同步还是冻结，训练和评测各用什么统计。样本数相同仍需核这些具体行为 |
| 在 warmup 结束、衰减或恢复时分开 | 从日志或短跑逐更新步记录学习率，读调度器的实际调用点和步数单位。对照预期的 warmup、衰减位置、终值、有效更新数及恢复时的 scheduler 状态。缩小数据或预算时明确依据与实际到达的阶段，把 schedule 差异写入规模比较 |
| 训练正常结束，但最后报告的结果不同 | 核训练数据划分和增强，回查用于报告的 checkpoint 选择规则、评测频率、EMA 启用时机与更新频率。若从 checkpoint 续跑，确认模型、EMA、优化器和调度器各恢复了什么。用日志和保存产物核实际选中的状态 |

只在条件可比较后解释波动。固定权重重复评测、不同训练 seed、改变数据抽样和改变评测样本各自记录。若需要排查同配置的不稳定性，先确认重复运行固定哪些条件，以及增加几次观测会怎样影响决定。保留每次读数，说明论文统计值的含义和本轮的观测范围。比较依据用已确认的协议与实际证据。单次小差距、论文的标准差或少数重复结果都需要结合相同条件和本次观测来解释。

## 4. 用组件检查区分具体原因

沿用 setup 的[组件行为与数值检查](../../code-project-setup/references/numeric-sanity.md)。可以直接引用同代码路径、同输入条件下已经取得的证据，注明覆盖范围。新检查先写观察目标、预期及依据。若固定 seed、关闭增强、改变输入或调整诊断配置，保留实际配置，说明它与正式协议的差别。

| 要确认什么 | 怎样做 | 能据此判断什么 |
| --- | --- | --- |
| 小批次上能否按预期完成学习和更新 | 先确认目标、样本、模型条件及正则允许预期变化。固定少量实际样本，沿用训练入口的 forward、backward 和 optimizer 路径，记录 loss、预测和预期会更新的参数。按任务决定检查步数和预期行为 | 观察到预期变化只覆盖本次设置与样本。未见预期变化时，分别核目标、参数冻结、梯度与更新步骤，再判断疑点在哪 |
| 初始 loss 的计算是否符合定义 | 固定一批已知输入或捕获实际初始预测，按真实标签、权重、掩码和归约手算小例子，与训练代码输出对照 | 可定位给定输入下的目标计算差异。只有均匀类别预测等前提成立时，才用对应的理论参考值 |
| 指定输入是否提供可用信息 | 明确要破坏哪项信息，把这一路置为常量或按明确规则打乱。固定标签、其他输入和运行条件，记录仍可用的输入、预测和指标 | 变化反映这项干预下的表现。若结果接近，分别考虑其他信息通道、指标不敏感和实现忽略输入，再选择下一项能区分的检查 |
| 模型实际收到的样本、标签和预处理是否对应 | 在进入模型前保存少量真实输入、ID、标签和必要的增强参数。图像可反归一化并叠加标注，文本核 token 和掩码，音频核时长、采样率和对齐 | 可以核对所查样本的对应关系、单位和变换。发现不一致时回查首次出现差异的变换或拼批步骤 |
| 输出的依赖范围是否符合设计 | 先读架构和掩码定义，写清预期允许依赖哪些样本、位置或输入。固定其余条件，扰动一个输入或对选定输出回传梯度，记录预测变化或梯度及所在位置 | 用于核给定条件下的依赖。跨样本交互按模型设计判断。零梯度要结合冻结、局部数值和条件分支解释，必要时另取输入或用扰动复核 |

## 5. 选下一项检查并记录何时结束

1. **先用已有证据缩小范围。** 有配置、日志、源码或产物就先查，逐一附出处。仍有多个解释时，选最省成本且能改变当前判断的一项。写清保持什么、只改变或观察什么、不同结果各支持什么，以及预算和授权。若只能同时改多项，写清这次能核对的是整套变更。
2. **单独保存尝试并回填。** 复跑用新 run，保留命令、实际配置、日志和测量。按 `alignment.md` 的差距与排查记录填写实测及判断变化，把可用于正式比较和仅用于诊断的 run 标清。修正运行以符合原协议时沿用协议版本。改变划分、指标或其他关键比较条件时，回 Step 2 确认并记录新协议。
3. **按能否回答目标决定结束。** 当前证据已能回答目标，进入交付并写明适用范围。还有会改变判断、且在已批准范围内的检查，回 Step 3。需调整关键实验条件或预算时回 Step 2。缺环境或资产时回 setup。预算用完、重复无新信息或参考条件无法取得时，保存已有证据、未决条件、对后续用途的影响，以及最有价值的下一项检查。需要验证新的科学假设时，由研究设计与实验执行阶段接手。

### 示例 · edge-vision 的 raw 与 EMA

沿用运行手册和核对模板中的虚构示例。目标 `EVAL-01 v1` 对照论文 v2 表 2 的 Vision-S 行，§4.2 指定 EMA，参考 Top-1 为 78.4%。

1. **观察和初查。** `eval-attempt-01` 退出码为 0，`metrics.json` 记录 388/500，即 77.6%。将 `outputs/evaluated-ids.txt` 与 Vision-Val v1/val 全量清单核对，每个 ID 均计入一次。回查日志、r1 发布说明和 `tools/eval.py`，确认实际加载的是 raw。
2. **写下可区分的检查。** 只切换到同一 r1 发布的 EMA，保持代码、环境、500 个 ID、预处理和指标不变。若日志确认加载 EMA 且差距缩小，支持权重变体解释此次差距。若 EMA 已加载但差距仍在，保留权重条件已对齐的结论，继续按证据核指标或输入处理。若日志无法证明走到 EMA 分支，先补加载证据，暂不解释新读数。
3. **记录结果与停止依据。** 用户确认后，用单独的 `eval-attempt-02` 保存 EMA 配置和运行证据。日志确认加载 EMA，500 个 ID 和指标口径相同，实测 392/500，即 78.4%。在 `alignment.md` 保留两次运行及判断变化，将第二次作为文中评测条件下的改前对照。该评测目标已获得所需证据，完整训练和训练间波动仍待另外验证。
