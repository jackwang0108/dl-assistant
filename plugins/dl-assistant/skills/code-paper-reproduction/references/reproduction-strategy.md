# 按目标选择复现验证与判据

本文件说明怎样根据复现目标选择评测、训练或组件检查，判断参考结果与实际运行是否可比，并确定需要什么证据才能把当前结果交给后续实验作为基准。

在[运行手册 Step 2](workflow.md#step-2-定位准确的参考结果与协议写复现规格)写规格时使用，执行中按实际证据更新判断。命令准备、长任务托管和保存位置见[运行手册 Step 3](workflow.md#step-3-按目标执行评测训练或组件检查)。

## 1. 先确定后续需要什么基准，再选运行

每项目标先写完这句。**「后续要在什么条件下比较什么，所以本轮要核到哪项结果或行为。」** 从已审阅的任务、setup 的实际证据和参考出处取条件。然后选最直接的验证。一个项目可有多个目标，每个目标分别写前置、运行和通过后能用在哪里。

| 后续目标 | 启动前先核什么 | 实际跑什么、留什么证据 | 可交付的基准 |
| --- | --- | --- | --- |
| 用发布权重比较推理、后处理或评测 | 精确参考行、模型、权重版本及变体、配置、划分、指标实现和输出单位 | 用实际入口加载该权重。保存加载记录、正式样本 ID、覆盖与聚合、预测或指标、日志 | 这一权重和评测协议下的结果 |
| 从规定起点重训，再比较方法 | 训练数据和采样、初始化或恢复条件、模型、有效 batch、损失归约、训练阶段、权重选择与最终评测条件 | 按批准的训练范围执行，将选定 checkpoint 交相同协议评测。记录初始与最终权重、训练运行、选择规则及逐次结果 | 实际跑完的训练与评测条件下的参考结果 |
| 在新设备、数据或其他条件下建立参考 | 与论文或发布结果相比，哪些条件变了、改变是否有意、同条件比较是否可行 | 在双方都能使用的条件下实测，或核有出处的参考行为。分别保存原条件和当前条件的记录 | 新条件下可复跑的基准，注明与原结果的差异 |
| 核数据、测量或一段组件行为 | 具体输入、定义、单位、预期输出与已知答案或参考的位置 | 从真实入口或项目原测试触发组件，保存输入、路径、行为和输出证据 | 对应输入、设备、形状或协议下的局部基准 |

缺少官方权重时，先核发布页、论文对应版本和 setup 的资产记录。确认不可得后，按实际目标选择其他有出处的参考行为或局部检查，并说明影响。缺 `ready_commands.eval` 时按 [Step 1](workflow.md#step-1-核对-setup-与当前现场)回查小样本和正式入口的差别。环境和必要资产已具备时，从真实配置与文档核正式入口。必要条件有缺项时交 setup 补齐。

## 2. 全量训练超预算时，选能回答当前问题的检查

1. 用目标机器的实测吞吐、实际更新次数、评测及 checkpoint 开销估计整轮成本。分开写实测、估算和未知。把要回答的训练问题与预算对照。
2. 先查论文或发布记录是否给了可直接复跑的小设定，及可观察的训练早期行为。再从下表选能减少当前未知的检查。需要结合多项证据时，逐项写它回答了什么。
3. 将每项结果绑定实际设定。全量未跑到目标终点时，把完整训练结果与所需资源列为待验证。在报告给出接手阶段和下一项检查。

| 当前卡住的未知 | 选哪种检查 | 怎样做并留证 | 仍需核什么 |
| --- | --- | --- | --- |
| 仓库能否在作者已报告的小设定复现完整结果 | 小设定完整训练 | 按对应模型、数据、训练计划和表格行跑完。核训练终点、权重选择方式、最终指标与实际波动 | 目标配置是否使用同一行为，以及目标规模的完整性能 |
| 目标配置能否启动并按预期完成早期更新 | 目标设定短训 | 从目标配置、资源和实际命令开始。明确跑到的步数或训练阶段，留早期更新、调度读数、显存或吞吐日志 | 未到的训练阶段、收敛终点和完整指标 |
| 不确定差距来自数据、梯度、状态保存或某个模块 | 针对性的组件检查 | 选能触发问题的输入。逐项核样本身份、损失或参数依赖、实际更新或保存与读回，保存可重复的检查 | 未覆盖的组件、配置和训练范围 |
| 目标结果或资源暂时不可得 | 交付可核的部分结果 | 保留已有可比运行和局部证据，注明阻塞位置。外部运行附版本、协议、出处与读取范围 | 对应条件具备后需执行的具体操作 |

短训按实际达到的阶段记录。用同条件的早期参照时，先核更新次数、已看样本和调度位置。早期轨迹、小设定结果和外部旁证各自记录。Reduced 用于后续反复迭代时，再按[低成本配置步骤](workflow.md#step-5-按需准备-reduced-迭代配置)确定目的和升级条件。

## 3. 把可比性逐项写到 alignment.md

先标清要比较的参考结果、来源版本、表格行及实际目标。用论文、发布记录、当前配置和源码核条件，再用日志和产物确认运行实际走到的路径。每项标 `一致`、`有差异`、`未知` 或 `不适用`，并写对比较的影响。

| 核对项 | 用什么证据确认 | 找到差异时怎么走 |
| --- | --- | --- |
| 模型、权重与初始化 | 发布说明、实际文件身份、加载日志、组件覆盖及选择的 checkpoint | 区分模型版本、原始与 EMA 参数、初始化与训练恢复。涉及换权重或变更协议时回规格确认 |
| 数据和输入 | 实际发布版本、划分清单、参与统计的样本 ID、预处理与标签映射 | 比对清单和有效输入，核筛样、重复、分片和最后一批。写明差异影响的分组或指标 |
| 指标与聚合 | 实际函数、单位、分子分母、样本权重、汇总方式和输出 | 确认指标名相同的两边是否执行同一计算。必要时用同一组预测重算并留记录 |
| 训练与结果选择 | 最终配置、有效 batch、优化器、调度、重复单位、选择 checkpoint 的规则 | 明确实际发生了哪些更新、比较的是选定终点、最佳值还是重复汇总。必要时按对应目标补跑 |

实质差异或关键条件未知时，先交付实际观察并标明可比性问题。需要研究另一套条件时，另记版本化目标和条件；原参考继续保留。最可能改变判断的检查优先，排查位置见[差距排查参考](trust-traps.md)。

## 4. 在运行前定比较判据、重复和停止条件

### 找到本轮可以使用的判据

1. **读原结果的统计口径。** 核原文的 `±` 表示标准差、标准误、区间还是其他统计量，重复单位是完整训练、固定权重评测、样本或数据子集。核次数及权重或结果的选择规则。作者只报单次或最佳值时，在规格记清这条限制。
2. **说清当前怎么比较。** 明确数值单位、容许差异及原因。依据可以是同一固定清单上的可核行为、已有同条件测量、参考协议的精度要求，或对本轮决策有实际意义的差异。在用户确认前把判断方式写入规格。缺少依据时，报告原值和观察差值以及未知。
3. **分开记录差距和波动。** 先核两边是否可比，再解释差值。报告给逐次结果和统计定义。只有一次就报告单次。已有同配置的标准差可作为该条件下的波动记录，进一步解释时还要考虑实际比较设计。

### 选能解释未知的重复方式

| 想知道什么 | 怎么选下一次运行 | 记录什么 |
| --- | --- | --- |
| 固定权重的评测本身会不会变 | 保持权重、输入清单、配置和评测协议。如同条件下仍有随机性，再按计划重复评测 | 每次覆盖的 ID、结果、实际随机来源和差值 |
| 从头或从指定权重训练的结果会波动多少 | 保持训练协议及最终 checkpoint 选择规则，规划独立训练重复。若比较两种设置，按可控制的共同条件成对安排，并注明配对依据 | 每次训练的起点、seed、配置、读取范围、最终权重和评测值。配对时保存逐对差值 |
| 差异是否取决于试跑子集 | 对照已核身份的子集清单。比较数据抽样影响时保持其他条件，另取有依据的清单 | 每份清单的版本、实际分组及各次结果 |
| 怀疑数字差异来自协议 | 找出一个具体差异，按批准范围做单项复跑，例如同一数据和模型只改为参考要求的权重变体 | 改前、改后的条件、命令和观察。确需变更协议时保留批准记录 |

交审时写出初始运行、什么结果值得追加、追加哪种检查、最多投入多少，以及何时停止。例子如下。先跑一次固定权重评测并核 ID 与加载记录。若发现 EMA 与 raw 的差异，按授权追证该条件。若协议已一致且输出重复性仍会改变判断，才按规格重复评测。若未知是重训波动，就安排独立训练重复。达到目标或预算、重复未增加有用证据、关键参照不可得时，收尾并说明当前能回答什么。保留失败、偏离计划、不同 seed 和不符合预期的所有尝试。

## 5. 交付逐项目标的判断

每项目标在报告里依次给**执行状态 → 证据范围 → 可比性 → 与参考的结果 → 后续用途及未决项**。例如「完成一次全量评测。已核 500 个样本和 EMA 权重，Top-1 与对应参考行一致。可供 prepare 做改前改后评测对照。完整训练留待验证。」按 [Step 6 的交付核对表](workflow.md#step-6-交付可比较的基准)提供命令、版本和证据路径。

## 示例 1 · edge-vision 的 raw 与 EMA

[运行手册的 EVAL-01](workflow.md#差距排查示例--样本一致权重变体不同)中，首次运行退出码为零，500 个样本都统计到了，Top-1 为 77.6%。参考行是 EMA 参数下的 78.4%，本次实际用了 raw 参数。先把这次结果保留作排查证据。获准后，只切到同一发布版本的 EMA 参数，其他评测条件保持一致。复跑确认调整和实际指标，再交付对应评测基准。重复原来 raw 配置无法验证这个解释。

## 示例 2 · 全量训练超预算

以下是虚构的训练复现场景。实测吞吐推算目标规模完整训练约 40 小时，这轮获准使用 8 小时。论文另有小设定报告值，完整运行约 5 小时。同一架构、全量数据条件下的启动和首个调度阶段短训约 2 小时。

- 需要一个有论文参考的完整训练对照时，先跑小设定完整训练，核同一小设定的 checkpoint 选择和最终评测。保留运行及结果，给下游使用该小设定的基准。
- 若本轮还需要核全量入口的实际更新与调度，在预算内另跑目标配置短训，记录有效 batch、实际步数、调度位置与资源。短训与小设定分别交付。
- 若只选一项，把优先级写进规格。一轮小设定训练给出这次实际结果，跨次波动仍未知。目标规模完整训练结论留待取得资源后核对。
