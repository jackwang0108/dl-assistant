# 代码发布执行细则

## 1. 范围与来源

先核源代码的提交、未提交修改、子模块（若使用）以及论文文件版本；记录实际文件摘要，不能只记录会移动的分支名。目标目录独立于源仓库，已有目录不覆盖。已有发布仓库更新时使用独立工作目录或分支，保留既有发布版本。

按内部报告的范围表列出代码、配置、分析脚本、权重、数据、结果和文档：来源及版本、提供方式、许可/署名要求、可获取状态、排除原因和复现影响。论文依赖的分析、失败边界或必要实验配置不能仅因来自探索阶段就删掉；未公开的无关研究记录不随发布提供。

区分项目自行编写部分与第三方内容。核实际保留文件、依赖、权重和数据的来源与分发要求，保留必要许可证和署名；用户选择项目许可证不能替代这些检查。许可不明时记录待核内容，不自动改成某种宽松许可或上传相关资产。需要核查外部条款时读取实际来源，不凭记忆声称兼容。

独立目录可以新建仓库，也可以使用适合公开范围的历史；默认不删除任何现有 `.git`，不改写原仓库历史。确有历史整理需求时先形成具体方案，避免删除来源信息。内部验证报告从一开始就存到目标目录之外，不依赖最后删除文件和历史来防止泄露。

完成整理前自查后，继续明确部分；版本或范围冲突只阻止受影响内容。

## 2. 最小整理与含义核对

建立对应表：论文页/节/公式或结果 → 原代码与配置 → 发布代码与配置 → 检查依据。分析、数据或评测贡献同样纳入，不默认所有研究都有训练模型。

保留原有可用结构；按依赖关系确认文件是否需要，不按目录名称批量删除。记录复制、删除、改名、重写及理由。模型、损失、数据处理、采样、训练调度、评测和权重转换等关键变化需要人类审阅相关代码差异。不要因为前向输出接近就省略语义检查。

检查实际执行配置及入口，不只比较配置文件文本。若整理改变了实验含义，先恢复原行为或交研究判断，不把它作为发布优化悄悄带入。

## 3. 按用途选择验证

优先沿用项目适用的环境方式；只维护有用途的安装入口，不强制 conda、两套 Docker 或重复依赖清单。记录环境文件、运行时、硬件和所需外部程序。无法构建的可选环境明确标为未验证，不写成已支持。

| 验证能力 | 可用检查 | 不能由此推断 |
|---|---|---|
| 安装与启动 | 新环境安装、模块加载、实际入口短跑 | 论文结果已经复现 |
| 数据行为 | 同样样本、划分、预处理和随机来源下比较实际输出 | 只要 shape 相同就处理正确 |
| 方法行为 | 对照关键计算、输出、梯度或参数更新；按任务检查 | 参数能加载就语义一致 |
| 发布权重评测 | 特定权重、数据版本与协议的完整或限定范围评测 | 已复现多次训练均值或从头训练结果 |
| 训练流程短跑 | 目标计算、梯度、预期参数更新、保存与需要时恢复 | loss 必须单调下降；短跑保证完整训练效果 |
| 完整训练 | 事先明确条件、资源和重复安排的真实运行 | 一次训练证明所有平台和随机种子可复现 |
| 分析或数据处理 | 从指定输入重新计算对应表、图或统计 | 只有主表指标值得验证 |

确定性对照尽量固定输入与执行状态；随机操作控制随机来源或采用有依据的分布/统计比较。固定随机种子不能保证所有操作确定性。按精度、计算路径和已有差异确定绝对/相对容差及依据，不通用设为 `1e-5`。`strict=True` 适用时检查参数匹配，模型重命名或转换要有映射与对照，不能用宽松加载隐藏缺失参数。

先匹配比较对象：同一权重的评测、同种协议的完整训练统计或特定分析输出分别建基准。统计量需对应实际重复、选择规则、单位、方向和数据条件；不能用某个最好权重冒充多次运行均值。论文报告值、上游原始值和此次验证值分别存储，不调宽容差来掩盖差异。

基准可按 [perf-baseline-template.json](perf-baseline-template.json) 生成。它是记录结构示例，不是检查器或 JSON Schema；空数组需要填写实际对象，未知数值用 null，无数值检查时省略对应对象。每个数值检查记录指标、来源、匹配对象、比较规则、实测结果和输入标识。项目确需自动回归时提供适用的脚本，区别通过、失败、未运行、输入缺失和不适用；缺文件或未检查不能返回通过。非数值检查保留实际报告，不伪造性能分数。

回归不一致时同时调查代码、条件、依赖、随机性、权重选择、基准汇总和论文誊写。发布代码造成的偏差在此修复；研究证据或贡献受到动摇时交 iterate，论文内容错误交 writing-paper。不要预设一定是整理代码的问题。

计算成本超出已授权范围时，交付已验证部分及未完成计划，不擅自全量重跑。完成验证后自查。

## 4. 新目录使用验证

从此次待发布版本建立新的使用目录（复制待发布文件或从本地提交导出），从 README 的获取步骤开始执行。检查未跟踪文件、作者缓存、绝对路径和未说明的环境变量。新目录本身不等于隔离环境；若仍复用环境、缓存、数据或权重，逐项说明，核公开获取步骤或标记未验证。需要时使用干净环境，不默认有容器权限。

下载来源涉及认证、收费、许可确认或大额下载时遵守已有授权；不能实际获取的部分记为未验证并给准备步骤。记录运行工作目录、准确命令、输入、输出、退出状态和检查结论，不记录凭证值。

README 与 AGENTS 共享实际入口及配置，避免维护互相矛盾的命令。快速示例说明缩减了哪些条件、验证什么；论文实验列真实资源、配置、数据和权重。没有测过的硬件不能填写显存下限或耗时保证。有限验证的训练命令可提供，但准确注明只测过短跑或尚未验证，不能声称所有文档命令都完成了完整运行。

## 5. 变化影响与发布前自查

每项检查保存输入指纹：代码提交与实际文件摘要、环境、配置、数据版本/划分/预处理、权重摘要、命令和原始输出。内部报告可以引用完整记录，公开文档只提供使用者所需的复现依据，不带无关私人路径。

后续改动先与已验证版本比较，逐项记录影响：

- 模型、数据、评测或配置变化：相关行为检查和结果比较待重验。
- 依赖或环境变化：相关安装和运行检查待重验，并判断数值结果是否受影响。
- 权重转换或重新上传：核转换行为、摘要和下载内容，必要时重做评测。
- 文档命令、路径或下载方式变化：重新检查相应使用步骤。
- 仅文字修正：核声明与证据是否仍一致，不无依据要求重跑全部实验。

旧记录保留但不能认证受影响的新版本。发布前自查核范围、版本对应、第三方要求、实际文件及文档声明。检查文件、打包内容、必要时的历史与分支、配置、日志和媒体中的凭证、私人路径及无关未公开研究内容；只输出定位和处理结果，不把凭证值复制进报告。文本扫描有误报和漏报，命中需判断，零命中不能证明没有泄露。匿名发布仅在实际需要时按该场景检查身份信息，不从科研代码发布默认推出匿名要求。

## 6. 上传、公开与交接

准备待上传文件清单、代码版本、资产摘要、目标账户/仓库、可见性和对应授权。已有明确发布授权直接执行；范围不明时先给具体清单再确认，不在内容检查前先公开权重。公开代码、公开权重和启用页面分别核实际范围。

上传后核远端版本与文件，按预期使用者的访问方式核获取结果，下载权重后对摘要。只有作者登录可访问不能证明公众可访问；无法匿名验证时标为未验证。上传失败、访问失败或部分资产不可得时记录实际状态，避免盲目重复上传；先检查远端已有状态和错误原因。外部操作达到已授权重试/资源边界时停止相关操作并交接。

分别报告本地准备、验证、仓库上传、资产上传、公开访问及可选页面的状态。不把私有上传称为已经开源；范围有限但声明准确的交付可以完成，不强制所有能力都验证通过。

项目页只在用户需要时增加，内容来自当前论文与已核结果，不伪造图表或效果。平台、目录和媒体存储按实际项目选择，公开前沿用相同的内容检查和授权范围。
