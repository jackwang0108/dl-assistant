# 代码发布执行手册

本文件说明怎样固定发布范围、整理与论文对应的代码、选择并执行验证，以及核对实际公开结果。

## 1. 确认范围、版本和来源

1. 记录论文 PDF 或实际稿件版本和摘要。核研究仓库的实际代码和脏工作区，不靠分支名判断内容。经确认的未提交修改也可作为来源，记录涉及文件和摘要。
2. 沿 `docs/research/research-rounds.json`、相应 `claim-code-map.md` 和 `execution-conclusion.{md,json}` 找到候选实现及证据。核已存在的 setup、reproduction 报告和运行说明，用其定位真实入口及环境。在过往记录不可用时从实际代码、配置和资产继续核查。
3. 按[论文实验记录](../../code-paper-experiment/references/records.md)取得有关的 `paper-results.json`。核批次、修订、`exp_id`、所用计划与 run-spec、执行状态、测量有效性、尝试、原始证据以及资产能否取得。W&B 辅助回查按[实验记录说明](../../wandb/references/experiment-records.md)。
4. 列出要提供的源码、数据、权重、文档、分析和可选项目页。逐项写来源、版本、获取方式、许可证或署名、排除理由和对复现的影响。区分项目自有代码、上游代码、依赖、数据、权重和媒体的分发条件。待核许可只阻止相关资产的分发，其他已明确事项可继续。
5. 确定验证能力、预算、候选目录、原始记录落点和实际外部授权。整理前在[内部报告](release-report-template.md)登记判断、依据和未决。

从实际研究仓库获取版本和差异。命令输出如涉及内部信息，存到内部记录目录。

```bash
git -C "$research_dir" rev-parse HEAD
git -C "$research_dir" status --short
git -C "$research_dir" diff --stat HEAD
git -C "$research_dir" submodule status --recursive
shasum -a 256 "$paper_file" "$selected_config"
```

## 2. 在独立目录整理，逐层对照原行为

按论文节、公式、图表或数据产物建立对应表。逐项记原仓库路径和版本、发布候选路径、有效配置、实际保留或改变的行为及核查依据。优先沿用可用目录和入口，记录复制、改名或删除的影响。研究记录留在内部。论文需要的失败边界、分析脚本或特别配置要从依赖和论文用途判断是否保留。

每整理一层就用可负担的检查对照源仓库。下表按需选行，有依赖的检查先核前置条件。关键实现发生变化时，给用户看实际差异和预期影响。

| 层 | 实际操作与核对 | 不一致时先查 |
| --- | --- | --- |
| 环境与入口 | 在候选环境调用项目实际解释器，用 `python -c 'import <模块>'` 核涉及的包和自定义算子，试正式入口的最小任务。Conda 或 Docker 按对外支持范围验证。 | 包版本、编译算子、可选依赖、启动路径、容器挂载与设备权限 |
| 数据 | 固定样本 ID、划分和随机约定，用同一配置取样。对照解码、预处理、张量内容、标签、批次和数据清单。 | 数据版本、路径映射、采样顺序、归一化、增强和标签编码 |
| 模型或核心计算 | 同权重、同输入、同精度和模式下比较关键中间量及输出。PyTorch 适用时用严格加载核参数完整性。权重格式有转换时保存映射并对照关键输出。 | 权重摘要和选择、参数名、默认配置、初始化、数值精度、预处理和推理模式 |
| 评测 | 同一权重、同一子集与协议先跑低成本对照，再按范围完成正式评测。对照样本级读数、聚合、单位和最终指标。 | 样本覆盖、过滤、阈值、指标实现、分布式汇总和权重选择 |
| 训练 | 有训练入口时，检查真实数据、目标值、梯度、预期参数更新、checkpoint 写入及需要时恢复。短跑记录步数与实际条件。 | 冻结参数、loss、优化器、scheduler、混合精度、随机性和恢复路径 |
| 分析与数据产物 | 用发布者可获得的输入运行实际脚本，复算指定表、图或中间数据。 | 输入版本、缺值处理、筛选、聚合或作图资源 |

验证结果出现差异时从最早可观察的层定位，先复核配置、输入和范围，再改动代码。固定 seed 只是控制手段之一。比较前按确定性、精度、硬件或历史波动提出容差及依据，重要验收取舍由用户确认。

## 3. 按公开承诺完成回归

- **环境和安装。** 根据项目可用的方式提供最少且实测可用的入口。如果提供容器，区分实际承诺。验证推理镜像时从外部路径挂载发布权重，记录加载和评测结果。验证训练镜像时挂载数据，核更新、保存和恢复能力。大素材按实际权利和获取方式存放，不默认随镜像提供。
- **匹配基准。** 按[数值基准模板](perf-baseline-template.json)分别登记论文值、可比参考值和此次实测。逐项核统计对象、实际重复或权重、数据协议和单位。CPE 来源记录批次、修订、`exp_id`、统计或读数 ID 及实际证据位置。引用回包中的单个权重测量时，回查所用 attempt 和资产版本。
- **评测与完整训练。** 示范入口、子集或训练短跑只说明其覆盖的条件。若要声明复现具体论文统计，按同口径完整运行所需的重复并保存原输出。预算或资产不足时，保存已验证项和未完成条件。
- **记录与长任务。** 每项保存工作目录、实际命令、提交和文件摘要、环境、设备、有效配置、数据、权重、退出状态和输出。长任务使用集群调度器或[共享长任务脚本](../../dl-assistant/scripts/run-long.sh)。从候选工作目录运行，使用内部检查目录和独立会话名。集群环境保存实际作业 ID。

```bash
cd "$release_dir"
bash "$run_long" "$session" "$check_dir" "$verified_command"
tmux has-session -t "=$session"
```

用实际会话名查 `"$check_dir/$session.log"` 和 `"$check_dir/$session.EXIT_CODE"`，需要时按[共享长任务说明](../../dl-assistant/references/long-run-ops.md)恢复。完成后区分通过、失败、未运行、输入缺失和不适用。

### 示例：论文均值、发布权重和候选评测

假设论文表 2 是三次训练的均值 76.3%，其中发布权重在原环境的单次评测是 76.1%。候选评测同一权重得 76.0%。保留三笔数值，只有 76.1% 和 76.0% 参与这项权重评测的容差比较，并记录使用的相同数据划分和权重摘要。README 可报告实际验证的权重评测及其范围，论文统计和完整训练能力另列。如果连原环境的单权重值也没有，可先记录候选观察，或在授权范围内补可比基准。

### 排查回归不一致

先核比较来自同一权重或同一统计对象以及数据、配置和单位，再核环境与执行路径。只有发布版出现偏差时，从上节各层找最早差异。两边都偏离已有表格时，核上游原始数据和论文誊写。已知的文字或数值问题交 writing-paper。核心研究依据变化时带具体读数和条件交 iterate。验证完成后在报告中登记证据和剩余限制。

## 4. 从新目录按读者步骤验收

验证实际待发布版本。发布候选已形成明确提交时，可从该提交导出到新目录，例如：

```bash
reader_dir=$(mktemp -d)
(
  set -o pipefail
  git -C "$release_dir" archive "$release_commit" | tar -x -C "$reader_dir"
)
```

确认导出命令成功后再使用新目录。Git archive 的覆盖范围是当前提交的归档内容。若对外入口涉及 clone、子模块、LFS 或下载归档，按真实方式另核这些依赖。用新环境或独立缓存跑 README 的获取、安装、数据准备和入口步骤，检查未跟踪文件、绝对路径、作者缓存与未声明环境变量。确需复用环境、数据或缓存时在报告注明，并区分已执行步骤和仍未核查的公开获取。README 和 AGENTS 复用实测命令与对应配置。

## 5. 核对候选内容、改动影响和发布条件

发布前核实际提交和待上传内容。检查跟踪文件、远端与可见性、是否拟带公开历史，以及附属文档、补充材料、权重和媒体中是否包含内部内容。查询敏感模式时输出文件路径，按命中定位核上下文，内部记录保留经过处理的结论。例如：

```bash
git -C "$release_dir" status --short
git -C "$release_dir" ls-files
git -C "$release_dir" ls-tree -r --name-only "$release_commit"
git -C "$release_dir" log --oneline "$release_commit"
rg -l --hidden -g '!.git' -i '(api[_-]?key|password|secret|/home/|/mnt/|/nas/)' "$release_dir"
```

按实际资产检查二进制、日志、路径、凭证和未发表信息。文本扫描只给人工核查入口。需要公开历史时检查实际拟发布的提交和引用。在独立候选中选择适合公开的文件和历史，源仓库和既有发布历史按原项目管理。

后续改变代码、环境、数据、权重或启动命令时，记录影响到哪些验证并重验。仅改说明文字时核声明与原证据的一致性。最终内部报告给出整理前、验证后、发布前三次自查及实际结果。

## 6. 按授权发布并验远端

列出代码提交、资产摘要、目标、可见性与授权依据。按授权分别执行代码上传、权重上传、公开仓库和可选项目页。若已有发布目标，先核远端已有版本，重试前定位是否已上传及具体错误。

上传后核远端提交和实际可用文件。用目标读者预期的访问方式复核可访问性，下载公开权重后对摘要。若用到项目页，样例、图表和媒体都来自用户给的或已核材料，先查实际呈现和链接。用同一内部报告记录本地候选、验证、上传、公开及访问验证，列出尚未完成或待用户决定的动作。
