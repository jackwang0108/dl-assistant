# 论文论证分析与讲解

本文件说明怎样拆解论文的主要论点、选择每部分的讲法，以及核查并记录支撑这些论点的证据。

定位这一块要回答的问题 → 调工具读取关键原文 → 按内容类型组织讲解 → 说明证据支持到哪里 → 更新卡片

在 [运行步骤](workflow.md) 的 Step 3 用本手册安排路线图，在 Step 4 逐块讲解和核查，在 Step 5 汇总判断。向用户展示时，用论文实际回答的问题命名各部分。

## 一、论点与关系

1. **找出主要论点。** 阅读摘要、引言中的贡献说明和实际结论。判断删去某部分会不会让关键结论失去依据，或让一项独立贡献无法理解。满足任一条件，就把它单独安排进路线图；补充细节归入相应主题。章节名称和 “We propose”“We prove” 等措辞只用于定位候选。
2. **分清依赖和并列关系。** 对作者声称的依赖，说明前一项如何支撑后一项。并列贡献分别讲解和判断，没有推理依赖本身不构成局限。区分提供动机、观察到相关性、用实验证据支持和通过证明推出。
3. **安排讲解顺序与详略。** 优先讲用户关注的问题和理解它所需的内容。完整精读通常从「⓪ 问题背景」进入，再按理解顺序讲解。为每项注明已核实的章节、公式或图表位置和讲解详略，沿用这些标题提示当前位置。

### 检查论点之间的衔接

| 作者给出的关系 | 需要核查的问题 |
| --- | --- |
| 发现 → 方法 | 哪项观察支持哪项设计？观察只提供动机，还是也排除了其他解释？ |
| 发现 → 定理 | 定理的结论能解释原观察的哪些部分？简化设定保留了哪些关键条件？ |
| 定理 → 方法或应用 | 应用实际满足哪些假设？放宽或不满足假设时，还能使用哪些结论？ |
| 方法 → 实验 | 实验检验的是整体效果、某项设计选择，还是作者提出的机制？ |

**路线图示例（虚构，仅示范编排）**。① 怎样测量遮挡程度和重建误差（测量定义与结果图，重点）；② 模块怎样使用遮挡信息（方法节与伪代码，重点）；③ 哪些证据支持模块在遮挡时有效（结果表和消融表，重点）；④ 未见过的场景里能否维持效果（附录或未决问题）。如果作者只把遮挡测量作为动机，就按动机讲，再单独检查消融能支持什么。

## 二、主要论点与证据对应表

| 要记录的内容 | 填写要求 |
| --- | --- |
| 论点 | 给主要论点一个笔记内部编号，写清作者实际声称什么，保留必要的量词、比较对象和条件。 |
| 原文位置 | 记录实际读取的来源和位置。源码章节与 PDF 印刷编号不同时标明各自位置。 |
| 证据 | 记录支持或质疑该论点的证明、对照、测量或案例，注明实际读到的出处。作者解释可记录为解释。 |
| 设置与条件 | 写明影响判断的模型、数据、指标、对照、假设、费用或误差范围。 |
| 证据判断 | 说明证据在什么条件下支持论点、哪里不足、哪里有相反证据，或还没核查什么。 |
| 未决问题 | 写清未排除的解释、缺失材料和下一项可执行的核查。 |

按下列步骤操作：

1. **定位主张。** 用一句话写下这部分要解决的问题与作者的回答，再回查作者在哪一节提出或限定了该主张。
2. **调用工具读取证据。** 按 [原文读取说明](reading-mechanics.md) 打开已核版本。TeX 用 `tex_outline` 定位，再用 `tex_read` 读取主张与证据所在章节及直接引用，读完所选范围的续页。PDF 用 `pdf_outline` 或 `pdf_search` 定位，再用 `pdf_read` 读取；图表、公式或版面会影响判断时，用 `pdf_render` 核对原页或区域。
3. **讲解并判断支持范围。** 先让用户看懂当前主张和证据本身，再明确能推出哪一步。多个论点共用一份证据时，分别说明它对每个论点的作用。相关性只能支持相应的观察，因果判断还需要相应的设计和证据。
4. **更新卡片。** 按 [卡片格式](paper-card.md) 填写 `claim_evidence`。已读证据支持该主张时记 `supported` 并说明条件；已读证据无法支撑该主张时记 `insufficient`；有实际相反证据时记 `contradicted` 并写明比较条件；关键材料尚未核查、暂时不能判断时记 `unverified`。具体疑点可提要写入 `limitations`，保留原文依据在对应记录中。局部论点编号仅用于本篇笔记及卡片。

### 填写示例

沿用卡片中虚构的《轻量特征融合》。已用 TeX 读到第 3 节的延迟主张，并渲染同版本 PDF 的第 6 页核对表 2。表 2 只报告参数量和精度，因此对**这张表能否支持延迟主张**，已有依据记 `insufficient`。若任务是判断**全文**是否提供延迟证据，而关键附录还未核查，则全文判断先记 `unverified`，待查附录后再更新受影响的条目。

```json
{
  "id": "C1",
  "statement": "新融合模块可以降低推理延迟",
  "claim_locations": [{"source_id": "tex-v2", "location": "第 3 节末段"}],
  "evidence_locations": [{"source_id": "pdf-v2", "location": "文件第 6 页，表 2"}],
  "conditions": ["同一数据集和模型设置"],
  "judgment": "insufficient",
  "reason": "本次核查限于表 2。该表报告参数量和精度，未报告实际推理延迟。",
  "open_questions": ["附录是否提供同硬件、同批大小的延迟测量？"]
}
```

## 三、不同内容的讲解与检查

按**当前论点**选择讲法。同一篇论文可以先讲分析发现，再讲方法，最后讲验证实验。下表用来选择与这项结论相关的检查，没必要把所有问题在每篇论文上过一遍。发现基线较旧、数据集较少或代码未公开时，说明它具体影响哪项判断。

| 内容 | 讲清什么 | 核查什么 |
| --- | --- | --- |
| 方法 | 输入、关键步骤、输出、设计理由与关键公式 | 核心改动和前提，设计理由来自作者还是解释所作的推断 |
| 验证实验 | 试验要回答的问题、设计、数字与结论 | 证据检验的是整体效果、组件作用、机制还是成本，比较条件是否对应 |
| 分析发现 | 测量什么、怎么测、观察结果与替代解释 | 测量有效性、样本选择、混杂因素及因果解释 |
| 定理 | 精确定义、量词、条件、结论和证明思路 | 条件是否完整、关键推导、常数或渐近范围，应用是否满足假设 |
| 实证规律 | 改变的变量、控制条件、拟合区间与具体数值 | 方差、同时变化的变量、拟合质量和区间外验证 |
| 数据集与评测基准 | 数据来源、标注与划分；任务、指标、评测结果的含义 | 覆盖性、许可、污染或泄漏，指标是否测到目标能力 |
| 系统 | 一次请求或任务经过的组件、输入输出、接口与资源 | 对照条件、成本、瓶颈、失败条件和复现所需环境 |

### 1. 方法与验证实验

- **讲方法。** 用一个输入走一遍关键步骤，指出论文实际改的是哪一步、为什么改、输出如何得到。按内容从架构图、伪代码、公式或小例子中选最便于说明的一项。设计动机引用作者实际提供的理由，推测另行标注。
- **讲实验。** 每次选一个实验，按「设计 → 数字 → 结论」讲。先说它要回答什么、与谁比较、哪些条件保持一致、哪些同时变化。再读指标、单位、比较对象和关键数值，最后指出它支持哪条主张。主表可能支持整体效果；模块作用通常查消融或诊断实验；效率看实际测得的延迟、吞吐、显存或其他与主张相符的指标。
- **检查理解。** 若用户想验证自己是否理解，可以请其解释输入经过这个模块后发生了什么，或说明某张消融表回答了哪个问题。

### 2. 研究发现与实证规律

- **发现。** 从测量定义、样本和观察讲起。比如探查实验能测出模型表征中包含某类信息时，还要检查测量方式和样本选择是否会产生同样的结果，再判断证据能否说明模型实际使用了该信息。
- **规律。** 先讲改变了哪个变量、其他什么条件保持不变，再用一个图上的点说明横纵轴、单位和趋势。区分已测区间内的描述、由拟合得到的估计和区间外的预测。读到均值或拟合曲线时，核对波动、样本范围和外推条件。
- **检查理解。** 可请用户说出测量对象、仍未排除的一种解释，或用自己的话说明结论适用到哪里。

### 3. 定理

- 先读命题和关键定义，说明量词、假设和结论。有助于理解的定义可配小例子，标明这是教学例子。
- 用几句说明证明整体分几步，每步建立什么。再按讲解目标展开关键推导或用户卡住的步骤；若某步依赖附录中的引理，先调工具读该引理。
- 应用或数值实验另查实际条件。用户问放宽假设会怎样时，区分原证明会在哪一步失效、结论是否有反例，以及论文是否给出其他条件下的结论。

### 4. 数据集、评测基准与系统

- **数据集。** 从一条样本追溯数据来源、筛选、标注和划分，说明代表的对象及未覆盖范围。论文声称某类覆盖、标注质量或可复用性时，分别核对统计、质量检查、划分与许可说明。
- **评测基准。** 用一个任务样例解释输入、预期输出和指标。结果比较要说明评测协议和指标差异能支持的结论。遇到污染、泄漏或偏向的疑问时，核对数据来源、划分及评测设置。
- **系统。** 顺着一个请求或任务追踪组件和接口，标出耗时、吞吐或资源占用的测量点。作者声称某组件解决瓶颈时，核查分项数据及测试环境，说明结果在哪些负载和资源条件下成立。

对任何类型，用户主动复述时直接指出理解准确的部分、遗漏条件和推理偏差。也可以选择关键处提出一个检查题；用户明确要继续时按其节奏推进。进一步的讲解方法见 [讲解指南](teaching.md)。

## 四、研究线索与卡片

`paper_type` 概括实际内容和讲解重点，`core_contribution` 记录作者的主要贡献及核查范围，`claim_evidence` 保存证据判断，`novelty` 单独记录与已有工作的核实结果。发现令人意外、定理较强或结果提升，都可以具体描述。

讲解时可以记下潜在的可替换组件、待解释的现象或可迁移的测量方法。组件记录写明它的作用、当前实现以及修改后要验证的假设。发现、定理和基准也能提供线索；没有可替换组件就留空。

先保存精读笔记。用户选择讨论后续研究时，再根据论文的局限、未决问题或可迁移方法筛选建议，按需核实外部文献。讨论过的建议写入 `connections`，具体格式见 [延伸讨论模板](connections-template.md)。
