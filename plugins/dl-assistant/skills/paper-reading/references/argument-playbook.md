# 论证原子打法手册（paper-reading · Step3-6 用 · agent 内部）

中心思想：**论文主线 = 一条论证原子链**。读懂 = 拆出原子、串成链、找到主战场，每块搞清它卖什么、证据撑不撑得起、环与环的衔接成立吗。

**本手册是 agent 的内部分析手册，内容不直接外泄给用户**：用户可见的是人话版的论文最小版、深读路线图和逐块讲解（写法见 `teaching.md`）；"原子""承重""主战场""攻击面"这类行话只进 card 和报告，不进对话。

SKILL.md 是骨架（什么时候判、流程怎么走），本手册是打法（怎么拆、每类原子怎么讲怎么查、多块怎么组合、card 怎么填）。

---

## 一、怎么拆（Step3 开头做）：定原子 → 串主线 → 定主战场

### 1. 定原子（可分离性测试）

原子是**主线论证链上的承重环**，不是"论文的组成部分"（那样引言、附录都算）。判据只有一个：

> **抽掉这块，论证链是否还完整**——断了，它是原子；论证照常，它是细枝末节（补充实验、顺带承认的 failure mode），路线图上一句带过，不占一块。

标志句式只是**辅助线索**（"We propose" → 方法类、"We find / show that" → 发现类、"We prove" → 定理类），可分离性不好判时参考，不作为依据。

**原子种类不封闭**。高频五类：方法（卖设计）、发现（卖结论）、定理（卖命题）、规律（卖实证趋势）、基准（卖评测）。按可分离性拆出新种类（系统设计、数据集、理论框架……）是正常现象，走通用骨架（第二节）即可。

### 2. 串主线

把原子按**论证依赖**串成链：哪个观察推出哪个 insight、哪个 insight 推出哪个设计、哪个设计由哪些证据撑。链条是 Step3 路线图的骨架——但给用户前必须人话化（⓪ 背景打头、块名用"这块回答的问题"，见 `teaching.md` 第二节）。

串不起来（两块之间没有依赖）往往意味着论文本身两张皮——这本身就是重要发现，记 `limitations`。

### 3. 定主战场

主战场 = 论文最核心的贡献所在的那块（偶尔两块），是讲透的发力点。判据：**抽掉哪块，这篇论文最不值钱？** 非主战场给"能理解主线"的最低剂量，带过的要明确说带过。

判完**只记 card** 的 `paper_type`（自由文本，"原子组合 + 主战场；证据是 …"）并指导讲法分配——**不把"这篇是 X+Y 两块、主战场是 X"整段倒给用户**，用户看到的是人话版最小版 + 路线图。**判不准就问用户最关心哪部分，别硬猜。**

## 二、通用骨架（每个原子都要过的最小闭环）

不管哪类原子，都过这五步；各类原子的差别只在重心放哪（第三节）：

1. **卖什么**：一句话说清这块声称了什么、证据是什么形式。
2. **讲逻辑链**，不复述原文。形式随块换：方法 = 发现 X → insight → 机制 → 为什么有效；发现 = 问题设立 → probe 设计 → 发现 → 说明什么；定理 = 命题 → 关键假设/构造 → 支点一步 → 意味着什么；验证实验 = 逐实验走「设计 → 数字 → 结论」——先讲清对照设计（和谁比、唯一变量是什么、这个对照回答哪个质疑），再读数字，结论最后从数字里长出来（细则见 `teaching.md` 第六节）。
3. **当审稿人查攻击面**：不问"有没有问题"，问"**我会怎么攻击这块**"。攻击点随证据形式：实验查公平性、测量查 confound、证明查假设、扫描查控制变量。疑点记 `limitations`。
4. **延伸候选**：这个卖点有没有自然的延伸口（Step6 的候选料——这里只收集候选，Step6 按"宁缺毋滥、0-3 条封顶"过滤后才提给用户，延伸必须给真实 arXiv 锚点）。
5. **验收**：用理解检查题，不问"懂了吗"——用户能复述这块的核心 + 指出最强质疑，才算过。

## 三、高频原子的命门

骨架都走，但每类原子的重心不同——命门就是该发力的地方。

> 各原子下的"连+用"清单是 **Step6 延伸的候选来源**，不是要逐条填满的 checklist——Step6 按 SKILL.md 的纪律过滤（宁缺毋滥、0-3 条封顶、每条从论文具体缝隙长出来）后才提给用户。

### 方法块（卖设计，证据=验证实验）

命门在**讲透设计选择** + **用/改**。

- **讲**：先看架构图，再讲核心逻辑链 + 关键设计选择（为什么不用更直接的方案）、方法依赖的假设强不强。细节优先级：设计动机高，完整实验数字低——数字不混进方法讲解，验证实验部分单独按「设计 → 数字 → 结论」逐实验讲透（见 `teaching.md` 第六节）。
- **讲查顺序**：先把每个实验讲懂（设计 → 数字 → 结论），再标不 solid——证据强度分层是内部评判，不能当首次讲解的结构（用户还没看懂实验就被告知"这层最弱"，理解就断了）。
- **埋替换点**：给每个组件标「这篇的核心贡献」（记 `core_contribution`）还是「拿来即用的现成件」（记 `swappable_components`：组件名 + 当前朴素做法 + 为什么可替换）。只标记，不展开。
- **查**：只盯公平性——baseline 版本老、数据集选得有利于自己、关键消融没做。消融暴露某组件是瓶颈或可简化 → 和讲的时候的标记对上，强化替换点。
- **连+用**：内向——换件（现成件找更强的上位方法族）、简化提速、修作者承认的 limitation；外向——迁 insight 到别的任务；作 baseline（坑、有没有公开代码）。
- **检查题示例**：「为什么不用更直接的方案 XX？」「去掉组件 Z 会怎样？消融验了吗？」
- **card**：重点 `swappable_components` + `key_findings` + `limitations`。

### 发现块（卖结论，证据=分析测量）

命门在**查**——分析本身就是证据，讲查并成一个循环。

- **讲查合一**：问题设立 → probe/测量设计 → 发现 → 证据强度。
- **攻击面**：confound 没控制、probe 设计缺陷、over-claim（相关说成因果）、cherry-pick 例子、只在单一模型/语言/数据集上验证。
- **连+用**：内向——修正它/利用它的方法（发现留出的方法空间，如"FFN 存键值记忆"之于 ROME，最强的 idea 种子）；外向——发现在别的 setting 还成立吗（验证边界本身就是工作）、probe 技术搬到哪（记 `connections`）；作证据引为动机，或检查自己踩没踩发现暴露的坑。
- **检查题示例**：「这个发现有没有别的解释（哪个 confound 没排掉）？」「换个模型/语言还成立吗？」
- **card**：重点 `key_findings` + `limitations`；`swappable_components` 允许为空。

路线图示例（发现块论文，人话块名）：

> ⓪ **这个问题是怎么来的**（§1）——FFN 到底在存什么，为什么这值得搞清楚。【铺垫】
> ① **怎么测出来的**（§2）——把 key 向量投影回词表的 probe 设计，新颖处在这。【重点讲】
> ② **存的是什么**（§3–4）——浅层句法、深层语义，这是核心发现。【重点讲】
> ③ **这个结论有多稳**（§5）——三个模型上都成立。【快速过】
> ④ **边界在哪**（§6）——只验了英文。【一句带过】

### 定理块（卖命题，证据=证明 + 数值验证）

命门在**讲数学**（精确，类比只当入口）+ **假设的代价**。理论内容的货就是数学本身，只给类比就是讲"水"（讲数学的细则见 `teaching.md` 第五节）。

- **讲（按序走）**：① setup 单独立一块——记号 + 关键定义，每个定义配 toy 例子算一遍，没立住不进定理；② 精确摆主定理——量词、条件、结论；③ 构造讲设计决策链（先试什么 → 撞什么问题 → 怎么解 → 为什么直接做法不行）；④ 证明只讲支点一步，其余给路线图；⑤ 假设讲成代价（排除了什么、放松了怎样）。
- **查**：数值验证把定理落地（预测拟合度、参数对比倍数）；informal 陈述省掉的条件、只在合成 setting 验证、gap 藏在常数/log 因子、构造与真实网络的差距。
- **连+用**：内向——放宽一条过强的假设（每放松一条就是一篇新定理）；外向——结论指导设计、当检查自己 setting 的依据。
- **检查题示例**：「放松这个假设，结论怎么退化？」「为什么更直接的做法不行？」
- **card**：`key_findings` 换成"关键定理/引理"；重点 `limitations`（假设强度）。

### 规律块（卖实证趋势，证据=大规模实证扫描）

命门在**扫描设计**（凭什么归因）+ **外推边界**。

- **讲**：先讲扫描设计——控制了什么、扫了什么维度、为什么这样设计能把规律归因到这个变量（归因逻辑是命门，设计讲不清规律就悬空）；再讲规律本身用坐标轴语言——x 是什么 y 是什么、趋势/斜率/拐点，配一个具体数值点落地。
- **查**：控制变量干不干净、有没有混杂因素跟着变、拟合区间外验了吗、只报平均趋势不报方差。
- **连+用**：外向——规律外推到别的 setting（验证边界）；当约束——自己设计的边界条件（"在这个规模下别指望 X"）；失效边界往往就是方法空间。
- **检查题示例**：「这个趋势外推到 XX 规模还成立吗？凭什么？」「有没有别的变量跟着一起变了？」
- **card**：`key_findings` 记规律 + 适用边界；`limitations` 记外推风险。

### 基准块（卖评测，证据=评测结果）

命门在**设计公平性** + **短板真实性**。

- **讲**：想暴露什么短板 → 怎么设计才能暴露（任务/指标的关键设计选择）→ 测出来谁强谁弱说明什么。排行榜不是重点，**短板和结果的对应关系**才是。
- **查**：短板真实吗（有没有可能测的是别的能力/artifact）、任务设计偏向某类方法吗、指标真对应短板吗、测试集污染。
- **连+用**：每个被暴露的短板都是方法块的 idea 种子（记 `connections`）；外向——评测协议 / benchmark 搬去测自己的工作；作动机（引为问题存在的证据）。
- **检查题示例**：「这个结果有没有可能是 XX artifact？」「换你来设计会怎么让这个短板更难躲？」
- **card**：`key_findings` 记暴露的短板；`connections` 记短板 → 方法空间。

### 新种类原子（系统设计、数据集、理论框架……）

没有现成命门清单，回通用骨架：卖什么 → 讲逻辑链 → 证据形式定攻击面 → 连+用 → 验收。判不准就问用户最关心哪部分。

## 四、组合规则（多块论文）

单原子论文少见，混合是常态。组合不引入新打法——**每块按自己的原子打法走**，组合只管三件事：

- **顺序**：按论证链走（发现→方法、发现→定理→应用……），不按 section 顺序；对外呈现为 Step3 的人话路线图（见 `teaching.md` 第二节）。
- **主战场**：主战场讲透；非主战场给"能理解主线"的最低剂量，带过的要明确说带过。
- **衔接检查点（组合的命门）**：环与环的接口最常出问题，每到一处衔接必查——
    - **发现 → 方法**：哪个发现推出哪个设计？还是发现和方法两张皮？
    - **发现 → 定理**：定理的每条性质真对上了观察到的现象吗，还是只解释了 toy 版本？
    - **定理 → 方法/应用**：定理的假设在应用 setting 里成立吗？
    - **方法 → 实验**：实验有没有回头验证 motivation 部分的预言？

例：分析先行论文（发现+方法）= 发现块讲查合一 → 衔接检查"发现→设计对应" → 方法块正常走；解释型理论（发现+定理+方法）= 定理块按序走，衔接查"定理有没有真解释现象""定理假设在方法 setting 成立吗"。

## 五、card 填写指导

- `paper_type`：自由文本，"原子组合 + 主战场"（如"发现+方法 · 主战场方法；证据=probing 测量 + 验证实验"）。
- **各字段按块填，不适用就留空**——发现块 `swappable_components` 可空；定理块 `key_findings` 可换成"关键引理"。不留空硬凑。
- `novelty`：按主战场块的维度记——方法记"idea 聪明吗"，发现记"意外程度"，定理记"结论的新颖/强度"。
- `connections[]`：一条连接一个条目（不合并）；`kind` 用四分类词汇（内向=方法上/证据上/边界上/解释上，外向=搬思想/推结论/借工具/当约束）；锚点必须真实。
