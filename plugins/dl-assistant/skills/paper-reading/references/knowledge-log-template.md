# `knowledge-log.md` 模板（人读 · 动态更新 · 个人学习记录）

这个文件记录用户主动提问涉及的知识。每个条目包含一段可独立阅读的讲解，并写明用户当时的疑惑。每篇论文的记录供用户日后查阅。

**读新论文时不参考历史档案**。确认背景时只依据用户在当次会话说明的熟悉程度。

> 与其他产物的分工：
> - **确认背景（Step 2）**讲论文**依赖的**底层技术——那是读懂本文的前提，进讲解过程，不进本档案（除非用户就此追问出了新疑惑）。
> - **判断性讨论**（用户对论文的质疑、观点、agent 回应）→ 进 `deep-reading.md` 的讨论实录。
> - **知识性提问**（「JEPA 是什么」这类补用户知识的）→ 进本档案。判据：这条的价值是「补我的知识」还是「评这篇论文」。

## 何时保存条目

- 用户表示理解、停止追问或转向其他问题时，把这几轮讨论整理成一个条目并写入文件。
- 当场记录实际误解和帮助澄清的解释或类比，便于用户日后回顾。
- **多轮追问的过程不进档案**，追问**暴露的疑惑点**进档案。
- 快速判断时也记录，包括论文本身不值得精读的情况。

## 条目结构（追加在文件末尾，新概念一个条目）

```markdown
## {概念名，如 JEPA}

**触发语境**：{读到哪节哪段触发的，如「RW 第 2 段提到 JEPA 作为自监督代表」} · 与本文的关系：{顺带提及 / 相关背景 / 可顺藤摸瓜（标一句理由）}

**完整介绍**：{自足的小讲义——是什么 / 核心原理 / 为什么重要 / 在本文语境里扮演什么角色。
写给未来的自己读：不依赖当时的会话也能看懂。篇幅按需，讲透为止，通常 2-5 段。}

**当时疑惑过的地方**：{具体的疑惑 / 误解 / 追问角度 + 怎么澄清的，
如「一开始以为 JEPA 是生成模型——实际它是表征学习框架；混淆点在它也用 encoder，
澄清关键：它预测的是表征不是像素」}

**进一步阅读**（可选）：{一篇相关文献或资源，附 arXiv ID 或链接}
```

## 每个条目写到什么程度

- 从用户已经熟悉的概念讲起，可以沿用会话中的类比。讲解应涵盖用户所问的语境。
- 写清当时哪里没理解、误解了什么、用了哪种解释或类比来澄清。
- 浅（差）：「JEPA：一种自监督学习方法。」（百科一句，没有你的痕迹）
- 深（好）：完整介绍 + 「当时以为 X，实际 Y，混淆点在 Z」+ 与本文的关系。

## 文件头（首次建档时写）

```markdown
# {论文标题} — 个人学习记录

读本文过程中主动提问引出的概念/技术介绍。每条在一个话题讨论结束后提炼写入文件。
```
