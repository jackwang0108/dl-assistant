# `knowledge-log.md` 模板（人读 · 动态更新 · 知识补缺档案）

读论文过程中用户**主动提问**引出的知识补缺档案——装的不是问答实录，而是**对用户不懂的东西的完整介绍**（小讲义），并标出用户当时疑惑过的地方。逐篇累积，隐性沉淀成用户的个人知识档案。

**只写不读（死纪律）**：本档案供用户自己回翻，**agent 读新论文时不得扫描它来预设用户懂/不懂什么、跳过概念**——每篇论文先完全独立地读懂，摸底只认用户当场说的（见 SKILL.md Step2）。

> 与其他产物的分工：
> - **背景摸底（Step 2）**讲论文**依赖的**底层技术——那是读懂本文的前提，进讲解过程，不进本档案（除非用户就此追问出了新疑惑）。
> - **判断性讨论**（用户对论文的质疑、观点、agent 回应）→ 进 `deep-reading.md` 的讨论实录。
> - **知识性提问**（「JEPA 是什么」这类补用户知识的）→ 进本档案。判据：这条的价值是「补我的知识」还是「评这篇论文」。

## 落盘纪律

- **闭环即建档，不答一句写一条**：用户可能追着问好几轮——等这个话题**明确闭环**（用户说懂了 / 追问停了 / 话题自然转向），agent 把这几轮交互**提炼**成一个条目当场落盘。
- **不攒到最后补**：提炼趁记忆热乎——卡点的具体形态（误解成什么、哪个类比点通的）拖到最后就只剩结论没有卡点了。
- **多轮追问的过程不进档案**，追问**暴露的疑惑点**进档案。
- 轻量路径（不值得读的文章）同样记——问题不问文章值不值。

## 条目结构（追加在文件末尾，新概念一个条目）

```markdown
## {概念名，如 JEPA}

**触发语境**：{读到哪节哪段触发的，如「RW 第 2 段提到 JEPA 作为自监督代表」} · 与本文的关系：{顺带提及 / 相关背景 / 可顺藤摸瓜（标一句理由）}

**完整介绍**：{自足的小讲义——是什么 / 核心原理 / 为什么重要 / 在本文语境里扮演什么角色。
写给未来的自己读：不依赖当时的会话也能看懂。篇幅按需，讲透为止，通常 2-5 段。}

**当时疑惑过的地方**：{具体的卡点 / 误解 / 追问角度 + 怎么澄清的，
如「一开始以为 JEPA 是生成模型——实际它是表征学习框架；混淆点在它也用 encoder，
澄清关键：它预测的是表征不是像素」}

**延伸指针**（可选）：{想深挖读什么——一篇关键文献 / 资源，带 arXiv ID 或链接}
```

## 深度标尺

- **完整介绍**不是百科词条复制——是「以你当时的理解为终点」的定制讲解：从用户已知的锚点出发（会话里用过的类比可以保留），到他问的那个语境为止。
- **疑惑点**是条目里最值钱的部分——它标记的是「这个脑子理解这个东西时的地形」；用户自己回翻时，能一眼想起当时卡在哪、哪个类比点通的。
- 浅（差）：「JEPA：一种自监督学习方法。」（百科一句，没有你的痕迹）
- 深（好）：完整介绍 + 「当时以为 X，实际 Y，混淆点在 Z」+ 与本文的关系。
