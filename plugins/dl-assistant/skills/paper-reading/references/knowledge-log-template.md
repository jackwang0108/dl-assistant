# knowledge-log.md：概念补充记录

保存阅读过程中已讲解的概念、技术和用户具体疑问，用于日后回顾。前置背景与用户追问都可以收录，不因其发生在哪一步而排除；论文评价讨论主要进入精读笔记。

一个主题结束或用户转向其他问题时，提炼已有内容并保存，不逐句抄对话。没有明确理解反馈时写“已讲解，理解情况未确认”，不能把不再追问当成已经理解。未解决的问题一并保留，不要求先解决才能保存。

## 条目格式

```markdown
## {概念}
- 内容类别：已有前置知识 / 本篇新定义或方法内容。
- 语境与本文关系：当前研究问题、实际章节或讨论问题；已给最小提要后说明为什么需要。
- 定义与作用：必要背景、机制和精确条件。
- 所需概念与讲解位置：解释依赖哪些已介绍内容；本篇特有内容在方法位置讲，不用它反向解释基础。
- 具体例子或计算：发生时记录，前置知识用独立例子，教学例子与论文结果分开。
- 用户的具体疑问与解释：发生时记录，不推测其原有认知。
- 理解反馈：自述理解、练习已检查或尚未确认。
- 待解决问题与参考来源：实际存在时记录，含稳定标识或链接。
```

条目应自足、使用直接说明和具体例子，不用抽象比喻替代技术解释。用户主动要求复习时可读相关条目；不能从历史学习记录推断永久掌握或擅自建立能力画像。本次会话已明确说过的背景可以直接使用，不必重复问。
