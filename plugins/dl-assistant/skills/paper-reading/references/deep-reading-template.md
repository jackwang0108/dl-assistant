# deep-reading.md 模板（Step 7 用 · 人读精读报告）

`deep-reading.md` 是一篇论文深读后的**人读精读笔记**，自给自足——日后的自己、下游 skill（如 idea-find 扫判断卡）只读它就能回血这次深读的全部判断。**只讲论文本身**；自然的延伸（这篇怎么被用上）单独落 `connections.md`（模板见 `connections-template.md`）。机读判断卡在 `paper-card.json`（schema 见 `paper-card.md`）。

报告**基于 card + 对话过程生成，但不是 card 的字段转储**——card 是字段，报告是叙事。

---

## 报告结构

```markdown
# {论文标题} 精读笔记

> **元信息**：{arXiv ID} · {作者} · {venue, 年份} · 读于 {date} · 论证块：{原子组合 · 主战场 X · 证据是 Y}
> **判断**：{值得深读——一句话理由，与 card 的 worth_reason 一致}

## 1. 一句话核心
## 2. 问题与动机
## 3. 核心 idea 与逻辑链
## 4. 论文最小版与深读路线图
## 5. 论证块拆解
## 6. 证据评估
## 7. 整体反思（批判收拢）
## 8. 讨论实录
```

### 1. 一句话核心（1-2 句）

电梯版：这篇干什么、核心 trick/发现/命题是什么。日后扫一眼就能回忆全篇。

### 2. 问题与动机（1-2 段）

它在解决/回答什么问题、为什么之前的办法或认知不够——作者声称的动机 + 我的核对（证据分层，见写作规约）。

### 3. 核心 idea 与逻辑链（1 段 + 逻辑链）

逻辑链格式（方法/机制型）：

> 发现「{问题/观察}」→ 直觉是「{insight}」→ 设计了「{机制}」→ 有效是因为「{为什么有效}」

其他块换对应链条：定理块=命题 → 关键假设/构造 → 支点一步 → 意味着什么；发现块=问题设立 → probe 设计 → 发现 → 说明了什么；基准块=想暴露什么短板 → 怎么设计才能暴露 → 测出来谁强谁弱。

### 4. 论文最小版与深读路线图

**原样收录 Step3 给用户的论文最小版 + 深读路线图**——最小版是论文的自足压缩版（问题背景→核心 idea→方法故事→关键结果→takeaway），路线图按块切（⓪ 背景打头、人话块名、每块带 §/Fig/Tab 路标 + 详略标注）。回顾文章时先看这节：最小版回血全篇梗概，路线图一眼重建讲解顺序。

示例（路线图部分）：

> ⓪ **这个问题是怎么来的**（§1+§2）——为什么大家想让模型"多想"，把思考说出来的路线浪费在哪。【铺垫】
> ① **它是怎么设计的**（§3–4 + 架构图）——三段式结构、随机圈数训练。【重点讲】
> ② **它真的有效吗**（§5 主结果表）——rec-scaling 曲线、双胞胎对照。【重点讲】
> ③ **循环结构白送了什么**（§6）——四个 zero-shot 能力。【快速过】
> ④ **潜空间里长什么样**（§7）——可视化现象。【当甜点讲】

### 5. 论证块拆解（2-5 段）

按块写：方法块=核心模块的设计动机 + 关键设计选择（为什么不用更直接的方案）；发现块=分析问题设立 + probe/测量设计 + 发现本身；定理块=精确命题 + 关键假设 + 构造决策链 + 证明支点。机制层面的归纳，不是复述原文。

- **不 solid 的地方单独成段**：假设太强、设计缺理由、消融没验证关键组件、confound 没控制、over-claim——写明是"作者没解释"还是"我的质疑"。

### 6. 证据评估（每个证据四段式）

> 想验证/支持什么 → 怎么做的（数据集 / baseline / 指标 / 关键配置；定理则是关键证明步骤）→ 结果是什么 → 说明了什么

**缺了"怎么做的"结论就悬空**——日后回读看不懂结论从哪来。验证实验、分析测量、数值验证都按这个式子；反直觉结果和 failure case 优先，不逐一列所有结果。

### 7. 整体反思（批判收拢）

Step5 的判断收拢，三段式：

1. **做对的地方**：这篇确实做对了什么（一两句，批判的对照）。
2. **逐条批评**：每条 = 问题是什么 → 具体指哪（论文实据 + §/表路标）→ 动摇什么（主干还是边角）→ 严重程度（致命 / 结论要打折 / 小瑕疵）。只收全文高度的增量批评，Step4 已标过的不重复。
3. **收拢判断**：哪些结论可以放心信，哪些要存疑——直说，不和稀泥。

### 8. 讨论实录

用户的关键追问和反馈 + 当时给的解答要点——揭示理解卡点在哪，是笔记的重要部分。要点式记，不逐字抄对话。

## 写作规约

- **中文**正文；论文原文引用、作者名、专有名词保留英文。对话里的 Unicode 符号（α β θ ∑）转成正式 LaTeX（行内 `$...$`，独立 `$$...$$`）。
- **证据分层**：陈述时分清「作者声称」「实验真正支持」「我的推断」，尤其 novelty 判断和实验评价，三层不混成一句。
- **自给自足**：不依赖对话上下文和 PDF 也能读懂。
- 被引论文带（标题, 年份）+ arXiv 链接。

## 反模式

- **card 字段转储**：把 json 字段平铺成节——字段已在 card 里，报告要叙事。
- **逐段翻译 abstract / intro**。
- **路线图写成章节摘要**：按 Intro/RW/Method/Exp 过一遍=和后面深讲重复；路线图按块切、⓪ 背景打头、人话块名带路标。
- **证据只有结论没有设置**。
- **通篇赞扬**：不 solid 处、质疑必须落笔。

## 完稿 checklist

- [ ] 一句话核心能让人 10 秒回忆全篇。
- [ ] 逻辑链四环节完整，不断链；链条形式匹配论证块。
- [ ] 论文最小版 + 路线图原样收录；路线图 ⓪ 背景打头、人话块名、每块带路标。
- [ ] 不 solid 处单独成段，标了证据层级。
- [ ] 每个证据四段式齐全（含"怎么做的"）。
- [ ] 整体反思三段式齐了（做对的地方/逐条批评/收拢判断），判断不和稀泥。
- [ ] 报告只讲论文本身；延伸与用法已单独落 `connections.md`。
- [ ] 讨论实录记了用户关键追问，不是空话。
- [ ] Unicode 符号已全部转 LaTeX。
