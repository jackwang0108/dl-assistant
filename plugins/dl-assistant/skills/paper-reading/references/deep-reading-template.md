# deep-reading.md 模板（Step 7 用 · 人读精读报告）

`deep-reading.md` 是供用户复查的精读笔记。读者无需翻阅原会话，也能了解对论文本身的分析和判断。延伸建议另写到 `connections.md`，供程序读取的卡片是 `paper-card.json`。分别参见 `connections-template.md` 和 `paper-card.md`。

根据卡片和对话过程写成连贯的说明，避免逐项抄录卡片字段。

---

## 报告结构

```markdown
# {论文标题} 精读笔记

> **元信息**：{arXiv ID} · {作者} · {venue, 年份} · 读于 {date} · 论证块：{论证类型 · 重点贡献 X · 证据形式 Y}
> **判断**：{值得深读——一句话理由，与 card 的 worth_reason 一致}

## 1. 一句话核心
## 2. 问题与动机
## 3. 核心 idea 与逻辑链
## 4. 论文简明讲解与深读路线图
## 5. 关键论证部分分析
## 6. 证据评估
## 7. 整体反思（批判收拢）
## 8. 讨论实录
```

### 1. 一句话核心（1-2 句）

简要概括：这篇干什么、核心 trick/发现/命题是什么。日后扫一眼就能回忆全篇。

### 2. 问题与动机（1-2 段）

它在解决/回答什么问题、为什么之前的办法或认知不够——作者声称的动机 + 我的核对（证据分层，见写作规约）。

### 3. 核心 idea 与逻辑链（1 段 + 逻辑链）

逻辑链格式（方法/机制型）：

> 发现「{问题/观察}」→ 直觉是「{insight}」→ 设计了「{机制}」→ 有效是因为「{为什么有效}」

其他块换对应链条：定理块=命题 → 关键假设/构造 → 支点一步 → 意味着什么；发现块=问题设立 → probe 设计 → 发现 → 说明了什么；基准块=想暴露什么短板 → 怎么设计才能暴露 → 测出来谁强谁弱。

### 4. 论文简明讲解与深读路线图

原样收录 Step 3 给用户的论文简明讲解和深读路线图。简明讲解包括问题背景、核心想法、方法、关键结果和一句话总结。路线图先列 ⓪ 问题背景，每项用所回答的问题命名，附章节、图或表的位置与讲解详略。回顾论文时先阅读这一节。

示例（路线图部分）：

> ⓪ **这个问题是怎么来的**（§1+§2）——为什么大家想让模型"多想"，把思考说出来的路线浪费在哪。【铺垫】
> ① **它是怎么设计的**（§3–4 + 架构图）——三段式结构、随机圈数训练。【重点讲】
> ② **它真的有效吗**（§5 主结果表）——rec-scaling 曲线、配对对照。【重点讲】
> ③ **循环结构带来了哪些无需额外训练的能力**（§6）——四个 zero-shot 能力。【快速过】
> ④ **潜空间里长什么样**（§7）——可视化现象。【简要提及】

### 5. 关键论证部分分析（2-5 段）

按块写：方法块=核心模块的设计动机 + 关键设计选择（为什么不用更直接的方案）；发现块=分析问题设立 + probe/测量设计 + 发现本身；定理块=精确命题 + 关键假设 + 构造决策链 + 证明支点。机制层面的归纳，不是复述原文。

- **证据不足之处单独成段**：假设太强、设计缺理由、消融没验证关键组件、confound 没控制、over-claim——写明是"作者没解释"还是"我的质疑"。

### 6. 证据评估（每个证据四段式）

> 想验证/支持什么 → 怎么做的（数据集 / baseline / 指标 / 关键配置；定理则是关键证明步骤）→ 结果是什么 → 说明了什么

**缺了"怎么做的"结论就悬空**——日后回读看不懂结论从哪来。验证实验、分析测量、数值验证都按这个式子；反直觉结果和 failure case 优先，不逐一列所有结果。

### 7. 整体反思（批判收拢）

Step5 的判断收拢，三段式：

1. **做对的地方**：这篇确实做对了什么（一两句，批判的对照）。
2. **逐条批评**：每条 = 问题是什么 → 具体指哪（论文实据 + 章节或表格编号）→ 动摇什么（主干还是边角）→ 严重程度（致命 / 结论要打折 / 小瑕疵）。只收全文高度的增量批评，Step4 已标过的不重复。
3. **收拢判断**：哪些结论可以放心信，哪些要存疑——直说，明确给出判断。

### 8. 讨论实录

用要点记录用户的关键追问、反馈及当时的解答，写明用户哪一步没有理解。无需逐字记录对话。

## 写作规约

- **中文**正文；论文原文引用、作者名、专有名词保留英文。对话里的 Unicode 符号（α β θ ∑）转成正式 LaTeX（行内 `$...$`，独立 `$$...$$`）。
- **证据分层**：陈述时分清「作者声称」「实验真正支持」「我的推断」，尤其 novelty 判断和实验评价，三层不混成一句。
- **可独立阅读**：不依赖对话上下文和 PDF 也能读懂。
- 被引论文带（标题, 年份）+ arXiv 链接。

## 反模式

- **card 字段转储**：把 json 字段平铺成节——字段已在 card 里，报告要叙事。
- **逐段翻译 abstract / intro**。
- **路线图写成章节摘要**：按 Intro/RW/Method/Exp 过一遍=和后面深讲重复；路线图按块切、⓪ 列在第一项、用具体问题写的标题标明原文位置。
- **证据只有结论没有设置**。
- **通篇赞扬**：证据不足之处、质疑必须落笔。

## 完稿 checklist

- [ ] 一句话核心能让人 10 秒回忆全篇。
- [ ] 逻辑链包含四个环节，说明环节之间如何推导；链条形式匹配论证块。
- [ ] 论文简明讲解 + 路线图原样收录；路线图 ⓪ 列在第一项、用具体问题写的标题、每块标明原文位置。
- [ ] 证据不足之处单独成段，标了证据层级。
- [ ] 每个证据四段式齐全（含"怎么做的"）。
- [ ] 整体反思三段式齐了（做对的地方/逐条批评/收拢判断），判断明确给出判断。
- [ ] 报告只讲论文本身；延伸与用法已单独落 `connections.md`。
- [ ] 讨论实录记了用户关键追问，不是空话。
- [ ] Unicode 符号已全部转 LaTeX。
