# 论文讲解指南（背景、简明讲解、深读路线图与问答）

本技能采用导师带学生的问答方式。这里说明如何讲解，暂停和继续的规则见 SKILL.md「问答与推进规则」。

---

## 一、Step2 确认背景（只补前置技术）

**开场提问模板**（按文章内容替换方括号）：

> 我已经拿到这篇文章了，精读前先确认你熟悉哪些相关知识：
>
> - 你对「[这篇文章的核心任务/领域]」了解多少？
> - 文章依赖一些底层技术，比如「[论文依赖的前置知识，如正态分布的性质 / 马尔科夫过程]」，你熟悉吗？
> - 有没有其他你觉得可能不太懂、想先补的地方？

**只认用户当场说的，禁止跨篇复用**：

- 不得扫描历史 knowledge-log、之前的深读产物，或凭"用户上次读过 XX"来预设背景、跳过概念——每篇论文先完全独立地读懂；跨篇比较/连接是 Step6 的事，本步之前一律不提。
- 即使用户确实在之前的会话里学过某概念，本步也照常问"这个你熟吗"——用户说熟才跳过。

**只补一类，且有明确范围**：

- **前置技术**：论文**依赖的**底层知识——判据是「抽掉这篇论文依然成立、在教科书或别的资料里也能学到」（正态分布性质、马尔科夫过程、transformer 基础件）。
- **范围限制**：凡是必须引用本篇的公式/section 才能讲的（作者自己的方法、推导、实验），一律留给 Step 4，确认背景绝不提前剧透论文核心技术。
- **论文自己的问题背景不在本步讲**（问题怎么来的、之前几条线各卡在哪）——那是路线图的 ⓪ 背景块，Step4 开讲；本步摸到的熟悉程度只用来调整第 ⓪ 项的讲解详略。

**循环细则**：

- 用户某概念不懂 → 立刻用大白话 + 类比讲清（不堆公式），讲完问"这样清楚了吗？还有疑问吗？"
- 用户追问 → 继续回答，直到疑问解决；用户对某方面已熟 → 跳过，不重复讲
- 用户说"跳过背景""直接讲方法" → 尊重，直接进 Step 3 或 Step 4

**介绍背景的原则**：先给"这东西是干什么的"一句话直觉，再给机制，不上来讲细节；概念有依赖（要懂 X 先懂 Y）就提前说"我先补一个前置概念"；涉及公式用 Unicode 符号 + 语言解释"这个式子在说……"。

## 二、论文简明讲解 + 深读路线图（Step3 的可见输出）

Step3 给用户三段可见输出：论文简明讲解 → 我的判断 → 深读路线图。本节讲第一和第三段怎么写（判断的写法就是 SKILL.md 的"明确给出判断"纪律，没有模板）。

### 论文简明讲解

**目标：读完这段，用户能向别人复述这篇论文在干嘛、做得怎么样。** 围绕 abstract 展开、补背景和细节，五段按序：

1. **问题和背景**：为什么这个问题值得做——缺背景就在这里补（不依赖 Step2 碰巧铺垫过什么，这段讲解应当可以独立理解）。
2. **核心 idea 一句话**。
3. **方法如何运作**。按实际顺序说明先做什么、再做什么、哪一步起关键作用。用具体步骤组织讲解。
4. **关键结果/结论**：最有分量的 1-3 个数字或结论，配一句"这说明什么"。
5. **一句话 takeaway**：这篇在整个问题版图上留下了什么。

用直白的语言讲论文内容，术语首次出现时附一句解释。篇幅以几分钟能读完为宜。讲完后，用户应能复述论文做了什么及结果如何。

### 深读路线图

**一条消息给完**，告诉用户接下来按哪几块深入。规则三条：

- **⓪ 先讲问题背景**："这个问题是怎么来的"（§1 + 相关工作），必讲，标注讲解详略（【铺垫，讲清问题就够】）。没有背景的路线图直接从方法开讲，用户容易跟丢。
- **用各部分实际回答的问题作标题**（"它是怎么设计的""它真的有效吗"），**不用类别名**（"方法块/发现块/基准块"只留在 card 的 `paper_type` 里）；每块一行 = 用具体问题写的标题 + 它回答什么 + 原文位置（章节、图或表的编号）+ 详略标注（【重点讲】/【快速过】/【简要提及】）。
- **不写元语言**：详略只用标注表达，不解释"为什么这块是重点贡献"。

**示例**（looped transformer 那篇）：

> 接下来按这五块深入：
>
> ⓪ **这个问题是怎么来的**（§1 + §2）——为什么大家想让模型"多想"，把思考说出来的路线浪费在哪。【铺垫，讲清问题就够】
> ① **它是怎么设计的**（§3–4 + 架构图）——三段式结构长什么样，为什么训练时圈数要随机抽。【重点讲】
> ② **它真的有效吗**（§5 主结果表）——测试时多转几圈成绩涨不涨，和"双胞胎"对照模型差多少。【重点讲】
> ③ **循环结构带来了哪些无需额外训练的能力**（§6）——四个不用额外训练就有的能力。【快速过，知道有就行】
> ④ **潜空间里长什么样**（§7）——几个有意思的可视化现象。【简要提及】
>
> 按 ⓪→④ 走，①②是这篇的核心，③④知道大概就行。

素材现成：章节树 + intro 贡献段 + 架构图，Step1 都拿到过——arXiv 论文首选 tex-mcp（`tex_outline` 章节树 + `tex_get_object` 直取架构图原图路径），源码不可用时或本地 PDF 走 pdf-mcp（`pdf_open` 后用 `pdf_outline` 查目录，再用 `pdf_render` 渲染看架构图）。

将路线图原样收录到 `deep-reading.md` 的第 4 节。逐项讲解时沿用相同的标题。

## 三、提示当前讲解位置（Step4/5 全程生效）

每讲新的一部分，先用一句话说明它在路线图中的位置，例如「① 设计讲完了，现在看 ② 它真的有效吗」。沿用路线图上完全相同的标题。

## 四、讲概念与公式的通用方式

- **先直觉后机制**：一句话说"这东西是干什么的"，再展开；类比优先，不堆公式。
- **用户没懂 → 换类比、拆成更小步骤重讲**，不是把原话重复一遍。
- 公式用 Unicode 符号（α β θ ∑）+ 语言解释"这个式子在说……"；只有写入文件文件才转 LaTeX（见 SKILL.md 核心纪律·符号规范）。

---

## 五、讲数学内容（定理块的核心讲法）

用类比帮助用户理解数学直觉，随后给出精确的数学内容。

- **类比是入口，不是替代**：类比负责给"为什么这不 trivial"的直觉；但定理陈述、关键定义必须按论文记号精确给出。讲完用户手里要留有精确版本，不是只剩一个比喻。
- **定义必配 toy 例子**：每个关键定义用 2-3 个元素的小例子实际算一遍（如讲 margin 就拿 2 个 key、3 个 value 真算一次 γ）。没有例子的定义讲解等于没讲。
- **公式讲结构，不做翻译**：讲一个式子 = 讲清每一项是什么、为什么它该出现、哪项大哪项小（如 margin = signal − cross-talk，容量界从哪项解出来）；不是把符号逐个念一遍。
- **符号跟论文对齐**：对话用 Unicode，但符号选取与论文一致（γ、W、F 不另起名字），用户回头翻 PDF 能对上号。
- **检查题代替"懂了吗"**：理论内容用理解检查题验收——"放松这个假设，结论怎么退化？""为什么更直接的做法不行？"答不上来就是没讲透，换方式重讲。

## 六、讲实验内容（验证实验 / 结果表的讲法）

实验讲解按「设计 → 数字 → 结论」进行。先说明实验怎么做，再让用户根据结果理解结论。

- **一次讲一个实验**，讲完再走下一个；主结果、消融、诊断实验分开讲，不合并成"证据分三层"一次性端出。证据强度的分层评判是内部分析方法（见 playbook），留到这块讲完或 Step5 才说，不能当首次讲解的结构。
- **讲设计必讲三样**：①对照组是谁（和谁比）②唯一变量是什么（其他全同，只改了什么）③这个对照回答哪个质疑（如孪生对照回答"收益来自循环本身还是数据配比"）。设计讲不清，数字就是无根之数。
- **读表先教看法**：先说表的行和列各是什么、关键比较在哪两行/两列之间，再讲具体数字。不给路标直接念数字，用户听到的就是一堆数。
- **结论从刚讲的数字里长出来**，一次一个；推断链长（细节 A → 推论 B → 大结论 C）就分步推，每步让用户跟上再走下一步，不两级跳。
- **能说什么、不能说什么跟着结论当场说清**：数字支持什么、不支持什么（相关还是因果、FLOP 等效还是性能等效）——点到为止，整体批判是 Step5 的活。
- **检查题验收**："这个对照是为了排除什么？""哪个数字最关键，为什么？"答不上来就是设计没讲清——回去重讲设计，不是把结论重复一遍。
