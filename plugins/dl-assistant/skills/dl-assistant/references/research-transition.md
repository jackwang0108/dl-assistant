# 研究判断、写作准备与后期返回

本文件统一idea-find、execution与iterate的交接含义。进入写作表示当前已有值得报告、且有证据依据的知识贡献，剩余工作可以明确安排；不代表研究永远结束或结论冻结。writing-paper、writing-paper-review、writing-paper-response与writing-paper-submission已完成配套修改；code-paper-experiment也已完成配套；code-paper-release也已配套论文与实现对应、分项复现验证、资产范围和版本变化后的重新验证。

## 五项判断与所需依据

| ID | 要判断什么 | 必须说明 |
| --- | --- | --- |
| knowledge | 已形成什么重要回答或问题 | 当前问题、实际发现、原认识如何改变、为什么值得知道。可以是方法、规律、边界、理论、评测或明确的新问题，不以模块或涨分数量代替。 |
| evidence | 核心回答是否有可信证据 | 逐项核心主张、来源/版本、实现和测量有效性、比较条件、反证、不确定性、替代解释及适用范围。现象可信而机制未知时只能按对应范围表述。 |
| novelty_value | 新增内容及意义是否核查 | 最接近工作已经知道什么、当前新增什么及其重要性；原文位置、检索日期/范围和限制。差异不是重要性的充分条件，supported不是创新认证。 |
| remaining_work | 核心贡献是否仍靠未来实验成立 | 每个剩余任务的未知、不同结果对结论的影响、是否可能动摇核心发现、资源/顺序和负责skill。核心事实/可信性/贡献意义仍待证实则继续研究。 |
| recommendation | 是否值得进入后期 | agent的具体建议、最强反对理由、风险、实际资源与用户决定。用户未决定标pending，不从沉默或deadline推导同意。 |

准备交写作时，前四项若有影响核心贡献的未决，不能标为已具备写作条件；第五项用户尚未同意则只保存建议，不执行交写作。允许在每项中保留不动摇当前表述的明确限制。

不打总分、不规定创新点数量，不承诺录用。发现并提出一个重要问题也可能成为贡献，但须有证据说明问题存在、已有认识不足、定义清楚及意义；泛泛提问或未验证猜想本身不足。阴性/反证也按同样标准评估，不承诺负结果必能发表。

讨论停止时同样记录上述认识与未知，但不要求满足写作条件。停止可能因为价值、资源或优先级，不能将未决填为证伪，也不能将停止迭代自动转换成进入写作。

## 剩余任务怎么分工

每个任务列：要减少的未知、可能结果及对主张的影响、当前证据缺口、计划/预算、责任与数据来源。

- 核心现象是否存在、数据/测量是否可信、关键解释是否成立或研究意义尚不明确：iterate设计、execution执行。若机制不是核心主张且未获证实，可明确限制而非编造机制。
- 核心回答已有依据，范围明确的补充比较、稳健性检查、展示或表达所需数据：writing-paper规划、code-paper-experiment执行。
- 只有表达不清但证据充分：writing-paper修改；不能为所有论证问题自动补实验。

按对研究判断的影响分工，不按训练规模、seed数、主表/消融名称或机器位置。全规模若决定核心结论是否成立，仍是研究验证；已知核心结果的补充实验仍可能推翻原判断，届时应返回。

按 [研究条件规则](research-conditions.md) 核对核心主张的目标条件、实际证据和保留条件；reduced 的局部支持不能按目标规模写成已成立。若改为局部问题，重新评估新增与价值；不能只缩小表述以保住进入写作的决定。核心收益能否迁移尚未知时，remaining_work 应明确列为研究未决。

## 进入写作的交接

iterate在用户确认后保存 `ideas/paper-package.md`，包含：
1. 当前研究问题、能给出的回答/明确的新问题，以及原来相信什么、观察到什么、改变了什么判断。
2. 核心发现—证据—条件/限制的对应关系；研究条件记录路径/版本、目标与实际差异、关键条件证据/未知和未完成目标验证；实现、数据、模型、统计代码与review的具体版本/路径。
3. 已核查的相关工作、实际差异及意义，收窄后保留/失去的贡献。
4. 最强反对证据、替代解释、事后发现、不能宣称的内容与尚待核查部分。
5. 五项判断的具体依据、agent建议、用户决定及self-check引用。
6. 明确的剩余任务、成本未知/依据、资源与运行中任务，不预设将得到阳性结果。
7. 来源研究版本、判断记录路径与日期；哪些是研究判断、哪些只是组织文字的建议。

论文贡献需单独论证，不能等于所有supported命题；无需强制方法tag、主表或最终机制解释。缺跨机器文件时明确缺什么，不编造已取得资料，不擅自扩大传输授权。

## 后期新证据与返回

写作入口应核对上述依据；有现稿但缺固定交接文件时，从材料整理当前判断，不为补模板重跑研究。组织论文、接收新结果、设计追加实验和回应审稿意见时，先区分表达问题、明确的补充工作和核心研究未决。

核心数据/比较/实现出问题、核心发现受到反证、核心机制缺证、新文献动摇贡献依据、收窄后价值不明或需要新假设时，应提出返回iterate。新结果的科学意义不由文件验收或审稿人意见自动决定；不是每个负结果都要求重启整个项目。

返回记录可写 `research-return-<唯一标识>.md`，包含：原研究判断及版本、新证据/质疑及来源、受影响主张/章节、已知/未知和竞争解释、相关数据/代码、现有任务状态与预算、建议和用户决定。质疑尚未核实时明确标待核实。

保留旧稿与证据；受影响内容标待重审，未受影响写作可继续。处理已有训练须按授权确认状态，不因返回而自动取消或重复启动。iterate完成后记录具体改变的判断/命题/范围与新证据，再交回写作更新相关内容；不能只换叙述保住原贡献。

## 同步范围

当前iterate负责产生研究判断；后期写作状态应引用其路径与版本，并记录新证据和返回状态，不维护一份脱离来源的“科学事实”。writing-paper的初始化、结构组织、实验计划、结果接收与关键自查已同步，并维护主张证据表和变化影响任务。review已加入版本绑定意见、贡献复述、争议/待核查与修改复查；response已按意见证据判断、研究分流、行动状态、回复陈述和跨意见影响进行核查。submission已改为带官方来源的要求清单、按需材料检查和人工提交待办，不认证科学内容或自动操作平台。code-paper-experiment已按共享执行状态、批次、精确重复、复算来源和部分交接配套；code-paper-release已按实际来源、复现能力、版本重验和发布状态配套，不把权重评测当作训练复现。旧字段与新规则冲突时明确指出并核对，不自动把success、supported、冻结方法或低效应视为贡献判断。
