# 自查与研究分工的案例检查

用于维护这三个skill时逐例推演；不是独立agent测评，也不证明服务器模型实际遵循。先用输入自行形成下一步，再与这里的行动依据比较。脚本测试只验证结构/版本/声明一致，不能从自然语言自动判定以下科学问题。

| 输入情况 | 应检查与改变的行动 | 不应发生的行动 |
| --- | --- | --- |
| idea-find只提出“把压缩用于音频，希望保留重要信息”，没有对象、条件或可区分解释 | candidate的problem/hypothesis需修正；先定义具体问题与假设，不交训练。早期草稿可以继续澄清，不按无idea淘汰领域。 | 填“创新压缩模块”后直接生成完整实验包。 |
| 新构想没有机制先例，但有明确条件、推理和可区分预测，效应未知 | reasoning可limited，说明证据缺口，讨论有预算的探索；不能把未知当反证。 | 自动降级为次要路线，或填预期提升证明可行。 |
| 方法误差下降，但特征变化只有相关性、多个解释均能产生 | execution的inference限制为性能观察；iterate比较解释，有价值才设计区分实验。机制未知不否定真实现象，也不允许归因。 | 声称设计机制已验证，或必须编出唯一原因才交接。 |
| 设计规定同样本对照，实际排除了困难样本且未经批准 | pre_run若已知则comparison/authorization需修正；开跑后才发现则在handoff记录偏差及受影响数据，不支持公平提升主张。是否重跑由批准设计与预算决定。 | 修改原计划掩盖排除，或只交最佳指标。 |
| 可靠直接反例违反“所有给定条件下X都成立”，虽然只试过一种实现 | iterate检查反例条件和可靠性后可拒绝该全称命题，不需先失败多个模型；修改范围分新ID。 | 为维护原假设强制多轮改组件，或将反例推广到所有相近问题。 |
| 原目标是广泛条件下的规律，最终只剩一个已知设置的微小差异，没有说明新增意义 | next_step的current_value需修正；重评价值，可停止或重新找问题。明确停止行动时未知仍可保留，不把停止当证伪。 | 借原大问题的重要性继续实验，或自动包装成短论文。 |
| 小规模结果存在，但全规模是否存在决定核心贡献，目前未知 | transition的remaining_work不能支持交写作；iterate设计关键验证，execution执行。 | 因实验名为“论文主表”就转CPE，再用预期结果完成论文。 |
| 核心实证发现及意义有依据，因果机制尚不清楚且不作为核心主张；剩余比较范围已明确 | 可建议按实证范围写作，明确机制未知，用户确认后交接；补充结果可能推翻原判断时返回iterate。 | 为开始写作强编机制，或要求解决所有未知才准写作。 |
| execution阻塞，部分数据不足以比较两解释 | handoff如实记录blocked/未决；iterate可讨论下一步成本或停止，不能将阻塞写为假设反证。 | 先无限修到全部实验完成才允许研究讨论。 |
| 写作中出现新数据与核心结果冲突，或新文献覆盖了原贡献 | 保存原稿/判断、新证据、受影响主张和资源；建议返回iterate核查，未受影响内容可继续。核对实际接收版本，历史记录有语义冲突时显式指出。 | 仅换优势描述维持原贡献，或把审稿质疑未经核实当事实。 |

真实行为评估应记录所用模型、输入、输出、实际动作及缺陷；与维护者自行推演分开。不得以通过这些例子的格式检查宣称创造能力、研究品味或科学推断能力已得到验证。

复验方法见 [系统验证](system-validation.md)。这些人工推演案例仍不等于真实模型测评；实际行为证据按具体输入和版本单独保存。
