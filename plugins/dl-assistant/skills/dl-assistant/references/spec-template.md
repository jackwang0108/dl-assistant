## §4 失败解读表

> **跑实验前写死**，不靠事后感觉——但预登记的是**解读结构**，不是死刑触发器：一次实现没产生效应，只证明这次实现没产生效应，推不出 claim 死。每条 = **观察模式 → 支持什么解读 → 嫌疑层 → 后路**，指向具体实验 + 具体信号。
> **每条必须带「判据三问」，光写结论不讲推导 = 用户在确认点没法审**：
> ① **验什么**——裁决哪个假设、机制链是什么（假设不成立 → 为什么这个量会呈现这个信号）；
> ② **阈值来历**——数字怎么定的（noise_floor 的几倍 / 论文消融幅度 / 量级估算 / 文献先例），允许粗；**没有先验时允许只写方向性预期（如「曲线应上升」「门控值不应饱和」），但必须显式标注「无先验」**；
> ③ **命中意味着什么**——支持哪种解读、嫌疑落在哪层（执行 / 设计选择 / 机制前提）、后路建议（修执行重验 / 换落点重设计 / 回 iterate 验尸）。**解读表命中永远不直接判死任何 claim**。
