# 下一轮取证设计

本文件说明怎样从当前研究问题和假设出发，设计能区分不同解释的取证方案，检查它的证据边界，并向用户讲清本轮投入及可能得到的结论。

在 [工作流 Step 4](research-workflow.md#step-4-选择证据写出对照并检查设计) 使用本文件。输入是已讨论过研究价值的问题、当前假设、已有数据及关键未知。主会话负责比较设计、给出推荐和向用户讲解。取证可以是定向观察、统计分析、理论检查、干预或训练实验，形式取决于什么证据能改变判断。

## 1. 明确本轮要回答的问题

1. **写出起始认识。** 对照 `spec.json`、对应候选记录和 `literature/literature.json`，写明问题及假设编号、目前相信什么、所依据的证据和最重要的未知。若尚无本项目结果，明确标为未执行。已有结果时，记下取得结果时的条件及能否用于本轮检验。
2. **写可区分的解释及预测。** 对每项关键未知，说明当前解释和最强替代解释分别会预测什么，以及哪种观察能改变判断。若两种解释预测相同，继续寻找能让预测分开的条件、观测量或对照。
3. **选本轮的取证性质。** 准备任务用于确认资源、接口、基准或测量可行性。探索用于发现现象或估计范围。确认用于检验事先提出的预测或区分解释。用探索材料提出的新假设，标为事后提出，并说明如何用独立数据或新的对照检验。
4. **回查决定设计的原文。** 先读现有证据记录和相关论文笔记，核对用于设计的实验条件、对照、公式或局限。只在缺项会改变设计或解释时补读。arXiv 原文按 [tex-mcp](../../tex-mcp/SKILL.md) 用 `tex_open` 固定版本，再用 `tex_outline` 和 `tex_read` 定位关键部分。仅有 PDF 或需要核原页时，按 [pdf-mcp](../../pdf-mcp/SKILL.md) 用 `pdf_open`、`pdf_outline` 和 `pdf_read` 读取相关页。把版本、章节、图表及适用条件写入 `literature/papers/` 的对应[论文证据笔记](templates/paper-evidence-note.md)，并更新 `literature/literature.json` 中受影响的证据。摘要或其他场景的结果可用于形成设计线索，使用时说明证据边界。

## 2. 比较取证办法并细化推荐方案

先列出能回答该未知的办法。一种设计已足够时，说明为什么推荐它。有实质差异的备选时，比较各自能区分的解释、局限和成本。例如，观察可以定位现象，干预才可能隔离机制。主会话结合用户的建议，主动提出并筛选备选。需要较大投入时，先判断是否有成本更低且保留关键条件的验证。

| 要写清什么 | 具体怎么做 |
| --- | --- |
| 操作与最小实现 | 按执行顺序写每步的输入、操作、输出和落盘读数。涉及代码时写改动模块、接口、关键计算和训练或推理中的接入位置。精确代码位置与命令待仓库核实 |
| 目标条件与缩减条件 | 先写最终要解释的任务、模型、数据、设备和评测协议，说明假设依赖哪几项。再记录可缩减项、依据及解释范围。改动会改变所研究机制时，保留该条件或重新定义问题 |
| 基线与对照 | 为每组写改变什么、保持什么、能排除哪种解释。优先设置可信的简单基线、必要的正反或分项对照及测量检查。多个因素一起变化时，说明能否用交叉或额外干预分离作用 |
| 指标与观测设计 | 明确观测单位、数据来源和划分、计时起止、指标计算、重复方式、随机性及误差来源。需要归因时，收集能区分解释的中间读数，并事先确定怎样检查它们的有效性 |
| 风险与成本 | 记录代码、数据、设备和权限是否实际可用。把耗时或资源分为已有实测、有出处的参考值与估计，写明缺失项及低成本备选。关键能力未知时可先做可行性检查 |

把推荐设计写进 `evidence-design/design.md`，并记下影响结论的设计选择、放弃的备选及理由。需要同时比较多个设计时，分别保存并注明问题与假设编号。[取证方案模板](templates/design-record.md)可供安排内容。完整论文方法和后续实验只记录有依据的条件分支，等本轮结果影响判断时再细化。

## 3. 说明设计依据、判据和可能结果

为关键选择标出依据。可以是同条件直接支持、跨条件间接支持、尚无证据、存在反证或材料未取得。间接支持写清差异及能迁移的部分。有反证时核查它是否适用于当前条件，再决定修改解释、保留边界或优先验证。没有先例时根据推理、可区分的预测及取证价值判断是否推进。

基线数字注明是本项目实测、论文报告还是估计，并附来源、版本和测量协议。判据按实际任务代价、测量波动、已知变化范围或用户确认的约束确定。数值误差、统计不确定性和实际意义分别说明。缺少依据时，先用基准估计波动或写有推导的定性预测。取证前保存判据和实际设置。若发现需要改动，记录原因、受影响的结果及是否需要重新取证，再确认实质变更。探索得到的新阈值在独立验证中使用，注明来源和数据复用范围。

| 可能结果 | 怎样解释和处理 |
| --- | --- |
| 执行完成，关键测量不可用 | 说明缺失、截断、测量扰动或条件偏差。修复测量，并确认受影响的对照是否需要重做 |
| 有可信、可比的观察支持或削弱预测 | 指明对应命题、对照和范围。列出已排除与仍可能成立的解释，供后续按实际证据填写 `evidence_assessment` |
| 发现稳定差异，仍有多个解释 | 保留可靠观察及其条件。查找能分离因素的对照，或将本轮主张限定到现有证据能支持的范围 |
| 结果复现已有认识，或出现可信反例 | 分别说清对当前命题和科学问题的影响。若反例界定了已有结论的适用范围，结合最接近工作核查新增 |

设计时重新回答「即使做成功，结果会回答什么科学问题，论文能据此提出什么新结论？」说明哪些结果只确认实现或测量可用，哪些结果能支持候选机制或边界主张。实际取得证据后，`code-idea-execution` 记录执行、测量和证据情况，`code-idea-iterate` 用这些结果重新判断研究新增。当前方案只记录预测、对照和解释，初始证据判断保持 `pending`。

## 4. 按风险独立核查，逐条修订

先由主会话用下面的视角自查。对成本高、归因有争议或关键结果依赖特定条件的设计，判断是否有必要独立核查，以及需要核哪几项。

- **可区分性与测量。** 关键预测是否都有相应对照。是否存在基线不公平、多个因素同时变化、指标口径漂移、样本泄漏、测量伪影或误差未计入。现有设计得出何种结果时仍无法归因。
- **假设与已有工作。** 关键推理前提是否有依据，最强反证的条件是否适用，最接近工作是否已回答同一个问题。发现会改变研究价值的文献，就更新证据记录并回 [Step 3](research-workflow.md#step-3-深入查新对照最接近的工作并讨论是否继续) 复核。
- **启动条件与成本。** 核对关键实现、实验载体、数据与指标接口是否真实可用。估计所需投入是否有依据，是否能先完成更便宜的检查。

需要委派时，先向用户说明分工、输入、独立输出文件和理由，得到确认后再派发。为每项审查给出当前问题与假设编号、设计版本、相关证据、资源约束以及要回答的问题。审查者只写分配的独立文件，汇报时附关键证据位置和文件路径。审查份数按风险选择。

独立核查原件存入 `evidence-design/reviews/`，可参考[独立核查模板](templates/design-review.md)。每条写**问题、证据或设计位置、对哪个判断的影响、建议动作**。区分已证实的缺陷、目前未知的风险和改进建议。主会话在 `evidence-design/design.md` 逐条记采纳、修改或保留的理由，再复核关键问题是否解决。若仍无法区分解释，先修对照、缩小本轮结论或只保留准备任务。缩小或改变科学问题后，回 Step 3 重新评价研究价值。

## 5. 向用户讲解方案并确认投入

按这条顺序讲解，必要时再给实验表。

> 要分清什么 → 为什么这个设计能分清 → 每个对照有什么作用 → 看见不同结果会怎样判断

讲清本轮要减少的未知与科学问题的关系，给出推荐和成本依据。涉及用户不熟悉的概念时，先解释它为什么影响结论，再展开实验细节。核查后总结关键修改、仍待确认的条件，以及这些条件如何限制可能得到的结论。

在 `spec.json` 分别记录用户认可的研究取向与批准的具体投入。关键资源、测量能力或正式实验成本未知时，可先提交小范围准备任务，写明完成条件和停止点。有明确实验设计时，按 [Step 5 草案交接](research-workflow.md#step-5-提交草案确认投入和交接版本) 准备文件，向用户确认当前版本和投入。用户可以只批准其中一个阶段。符合本轮目标的证据也可能支持调整、补证或停止。

## 示例 · 同一设备上的裁剪与融合

以下沿用[运行手册案例](research-workflow.md#完整示例--边缘设备上的视觉模型加速)。论文和情境均为虚构。上游证据表明组合部署在另一台设备上测得收益，当前 Q2 研究组合收益何时出现。H2 关注中间写回量，H3 关注运行时算子实现的切换。

以同一个基础模型设计四种配置，保持设备、运行时版本、验证集和批大小一致。使用相同输入和计时起止位置，分别记录模型裁剪带来的形状变化和实际选择的算子实现。

| 配置 | 这组用于回答什么 |
| --- | --- |
| 原模型，无融合 | 建立基准延迟、任务质量和测量波动 |
| 仅裁剪 | 观察关闭融合时，换成裁剪模型会改变什么 |
| 仅融合 | 观察原模型上单独启用融合会改变什么 |
| 裁剪与融合 | 测量组合收益，并与两种单项配置比较 |

四组可估计各配置在所测条件下的效果。如要判断两项改动的交互，先说明在哪个尺度上比较单项和组合，并核对四组条件及测量误差。即使组合收益稳定，若写回量和算子实现总是一起变，仍无法把差异归到其中一个机制。

独立检查可指出这个归因缺口。主会话据此把 **baseline-timing 基准核查**放在前面，先确认重复波动、计时方式和轨迹能否采到。baseline-timing 能给出测量和成本依据。之后在用户批准范围内设计 **configuration-comparison 对照**。若能固定算子实现再改变写回量，才有机会检验 H2；若能在写回量相近时比较不同实现，才有机会检验 H3。每个新增对照都核查是否改变了别的关键条件。做不到隔离时，保留组合效果及其设备和设置边界，把机制归因列为待证。

向用户说明可以这样讲。「我们要分清少写回数据和换了算子实现各起什么作用。四组先让我们看到每个配置下发生了什么。它们若同时变化，我们能说组合在这台设备上快了多少，机制还不能分别判断。我建议先确认轨迹能否区分它们，再决定是否投入正式对照。」
