# 文件、版本与研究决定

默认 `<项目>/docs/idea-find/<日期>-<topic-slug>/`，尊重用户指定目录。保留已有目录名和 specs 文件名，便于下游发现；名称不要求继续采用旧的17步流程。

```text
<日期>-<topic-slug>/
├── spec.json                       本次目标、讨论决定、进度、变更与下一步
├── self-checks/                    candidate与handoff自查，按输入版本分别保存
├── idea-seed.json                  用户起点、兴趣与资源；允许尚无想法
├── layer1-方向/
│   ├── pitches/                   早期问题构想，不是必须填满的候选池
│   ├── survey-channels/           各次检索/独立分析原始记录，文件名不覆盖
│   ├── literature.json            论文、证据及命题关系，不是“已证实空白”矩阵
│   └── 方向N-<slug>/              当前问题与假设，按需保存价值与启动判断
├── papers/<论文slug>/             来源文件与按版本定位的证据笔记
├── layer2-<方向slug>/              本轮取证方案与独立核查，仅需要时建立
└── specs/
    ├── <方向slug>-idea-spec-draft.md
    ├── <方向slug>-idea-plan-draft.md
    └── <方向slug>-claim-tree-draft.json
```

只建立当前工作需要的文件，未形成实验交接时不生成虚假的完整 specs。研究说明草稿用于 baseline-survey；实验计划和假设记录随研究说明交给中期，不能据此跳过前置步骤。

## 进度与决定

`spec.json` 使用 schema_version=2。包含 topic、created、origin（用户目标/兴趣/背景/资源与未知）、current_problem、current_hypotheses、status、decisions、revisions、next_step、self_checks（相关记录路径）。status 可用 exploring/discussing_value/planning_evidence/ready_for_handoff/paused/stopped；ready 仅表示本轮设计可交接，不代表环境就绪或假设成立。

每条 decisions 保存讨论对象、agent 的建议和依据、用户实际答复、获得的授权、未决定事项及时间。区分兴趣、价值讨论、取证投入、研究说明与计划确认；一条答复可授权上下文明确的一组工作，但不得扩写成科学事实。

revisions 保存原问题/假设、当前版本、变更原因、新证据、保留/失去的研究意义和重新讨论决定。仅更正排版可以简记；改变命题需要新假设ID及与旧命题关系，不能覆写旧命题后沿用ID。研究问题用局部Q编号、假设H编号，后续与 claims 的映射在交接草案注明。

## 读写与并发

主 agent 负责累计文件和最终交接；子 agent 只写独立分配的文件，返回关键结论、来源位置与文件路径。需要共同编辑的材料由主 agent 串行合并，不能多个 agent 同时追加 literature/spec。

每次检索/阅读保留实际参数、时间、范围、版本及完整性。资料可复用，但先检查身份、版本、已读范围及当前问题是否匹配；文件存在不等于已核查需要的内容。

同日新研究用唯一运行标识区分；同一研究继续时保留修订和旧确认版本。修改累计JSON时先完整写入同目录临时文件、校验再替换；JSON不能有重复键。历史草案不静默覆盖，不迁移其他项目或已结束研究。

## 保存顺序与恢复

先保存已知起点和原始来源，再记录观察/推理及候选；问题成形后记录价值讨论，取证设计后记录投入与最终确认。每轮更新“原来相信什么／观察到什么／改变了什么判断”；尚无本项目数据如实写未执行。

暂停或停止也保存当前认识、剩余问题与下一步，不强迫完成全部文件。继续时读 spec 的进度和对应原始证据，核对断点；不能从文件缺席推断候选已被否定。

## 旧记录的解释

旧 pitches、layer1/2、文献笔记可以作背景，但“幸存”“立得住”“空白真实”“创新点”等词不自动映射为新流程已通过。先检查支持的具体事实和研究价值；不读取旧 novelty 或 worth_reading 作为排除候选的规则。

共享claims与execution已采用支持、创新性和执行状态分开的格式。保持交接字段结构，明确研究假设、项目证据pending及创新性未确认；当前后期skills已配套新版语义；接收历史项目记录时仍须核对缺失与冲突，不按旧标签推算研究结论。

中文解释，技术名称和稳定ID保留原文；公式和跨机器交接遵循 dl-assistant。能在已授权位置取得所需文件就先读取，确实缺失时再说明需要哪些来源和版本。
