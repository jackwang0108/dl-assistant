# 模板：挑错-<视角>.md（Step 12 独立挑错 agent 落盘 · 漏洞清单不打分）

> 流程见 `method.md`；公共语言规范见 `output-contract.md`。

独立挑错按**视角**切，数量随路线数/会议档次伸缩（1-3 个），放 `layer2-<方向slug>/挑错/`。每个挑错 agent 带一个视角（feasibility / novelty / assumption / 验证完备性），**攻全部路线**（跨路线对比天然保留）。**产漏洞清单，不排序打分。**

**验证完备性必查**（可并入综合挑错，但任务书里必须显式列出）：拿"**v1 跑完能不能裁决核心赌注**"戳每条路线——每条核心假设有没有对应的便宜验证实验（没有 = 验证闭环断点）；该做的对照 / sanity 检查有没有被忽略（没对照就无法归因，结果出来也白跑）；kill 信号读什么数、阈值清不清楚；某个假设能不能用更便宜的实验先验掉（能在 v1 前花一天排掉的雷，不许留到 v1 跑完）。这条视角戳的不是"论文里还缺什么实验"（那是 iterate 的活），是 **v1 的验证闭环完不完备**。

```markdown
# 独立挑错（视角：{feasibility / novelty / assumption / 验证完备性}）：{方向 slug}

**严重度三级**（Step 13 修复分诊的直接输入，不许偷懒全标"一般"）：

- **致命** = 戳中核心假设，崩了整条路线全塌
- **严重** = 设计要大改（换组件 / 换机制）
- **一般** = 可修（补证据 / 加预实验 / 调细节）

## 逐路线漏洞（本视角）

### 路线1（slug）

| 漏洞 | 严重度 | 实证依据（标出处） | 建议的验证/规避动作 |
| --- | --- | --- | --- |
| {核心假设 H 站不住} | 致命 | {论文 X 表 3 实测该条件下反而下降 → papers/x/x-note.md} | {先做预实验验 H} |

### 路线2（slug）

...

## 跨路线观察（本视角）

{几条路线共同的隐患 / 哪条相对最稳——但仍是"供讨论的观察"，不是判决}
```

**填好的样子**（示例行）：

| 漏洞 | 严重度 | 实证依据 | 建议动作 |
| --- | --- | --- | --- |
| 核心假设"循环 3 次后仍涨点"站不住 | 致命 | 论文 X 表 3：循环 3 次以上同条件下反降 1.2 个点（papers/x/x-note.md） | 先做 50 样本预实验验该假设，再决定保留循环设计还是退到单次 |
| 解码头要自己从零写，无量产实现 | 严重 | 三篇相关工作均为自研未开源（literature.json 最接近评估） | 评估改造成接 Y 库现有 decoder 的代价 |
| 核心假设 H 在 v1 里没有对照组，结果出来无法归因 | 严重 | 路线1「第一裁决」节只跑完整方案、没有关掉 H 的对照 run | v1 加一组 ablate H 的对照 run，成本半天 |

> **挑错铁律——产弹药不产判决**：
>
> - 正例："路线1 的核心假设 H 站不住——论文 X 表 3 实测反而下降（papers/x/x-note.md），建议先做预实验验 H"
> - 反例："路线1 得分 7、路线2 得分 9，推荐路线2"
>
> 打分排序会让用户变成只能挑高分的验收员，就不是一起打磨了。挑错只让讨论有真凭实据；选哪条、怎么改是主会话跟用户一起打磨的事。
>
> **边界**：挑错挑的是 v1 方案的验证闭环和核心假设（假设站不站得住 / 对照和 sanity 有没有漏 / kill 信号清不清楚），**不是完善假想中完整论文的方法**——"论文里还应该有什么实验 / 组件"不归这里补，那是 iterate 基于实验证据的活；也不复查文献覆盖——新不新、全不全由 Step 3 的强制扫新保证。
