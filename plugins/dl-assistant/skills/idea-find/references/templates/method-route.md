一路线一文件。**讲 v1 怎么先跑起来**——最小可执行实验方案，不是完整论文方法。主会话先建骨架，细化子 agent 读证据笔记把 v1 最小实现做实。

## 技术直觉（骨架 · 四问）

{四问：在哪动手（改哪个环节/组件）+ 用什么机制（核心 idea 一句）+ 赢在哪（打哪个有名字的 baseline、哪个指标、凭什么赢、赢多少算成）+ 凭什么信能成（挂哪个钩子，指回哪篇笔记的哪条证据）——主会话基于全局证据摘要写的初步构想。四问答不全不许落盘；「赢在哪」必须能填进方向的主表预览}

填好的样子（示例）：

> 在哪动手：latent 空间的 refine 环节，不动 backbone。用什么机制：单次 decode 换成 3 步循环 refine，每步用自注意力读回上一步的预测再修正。赢在哪：打 X（当前最强，Y benchmark 85.2），目标 ≥87——refine 补回单次解码丢的细粒度，Y 自己承认这个损失。凭什么信：循环 refine 在检测任务上被 X 验证有效（papers/x/x-note.md 第 3 节），且 Y 自己承认"单次解码丢失细粒度"（papers/y/y-note.md 第 5 节）——钩子正是它的 limitation。

## 先例自检（骨架必填）

{核心赌注（赌哪个机制/方向会赢）对照 papers/ 里已深读最近邻的结论方向：有没有同构先例、先例的结论是什么方向。先例结论与赌注相反 / 零先例的核心直觉 → 本路线必须显式标注为**高风险路线**（赌什么、输了退到哪），不许当主线}

## 第一裁决（骨架必填）

{最便宜能**裁决核心假设**的第一个实验：做什么 / 读什么数 / 什么结果算证实·证伪 / 成本多少——成本必须在 idea-seed.json 的用户资源约束内；主线的第一裁决必须天-周级可启动。v1 默认分析先行：核心赌注压在未验证假设上时，第一裁决 = 假设裁决的分析/诊断实验（"赢"= 假设被干净证实或证伪，不是指标涨）；核心假设已有强先例支撑时才可以是直接打 baseline 的第一赢实验。无裁决设计的"先跑跑看"门控预实验不许当路线主结构}

## 方法细化（做实后）

{颗粒度：一个工程师读这份文件能把 v1 最小实现写出来、不用再问设计意图——pipeline 几步、每步输入/输出/操作、关键结构/目标函数、训练和推理各怎么走。范围锁死在 v1：只写跑通第一裁决 + 裁决核心假设所需的实现，不为假想完整方法补全组件（v1 之外的想法记进「v1 之外（留 iterate）」节）。不写实验设计（阶段三 plan 的活），不写 file:line（execution 填）}

- 核心机制怎么落地 —— 依据 papers/{论文}/{论文}-note.md 的{某条证据}
- 关键结构/公式 —— 依据 {某篇某式}

> 每个设计决策三态标注：**直接证据**（同类组件实测有效，引出处）/ **间接证据**（机制别处验证过，说清距离）/ **无证据·假设**（显式标注——挑错的主要靶子）。不许把"我觉得合理"混进前两种。
>
> 每一步尽量落在已落盘的证据笔记上；笔记没覆盖、本路线又需要的，才围绕具体缺口自主补检索（补下的 PDF 进 papers/<论文>/、新证据追加进对应 note.md）。
