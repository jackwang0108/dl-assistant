# 模板：papers/<论文slug>/<论文slug>-note.md（Step 9 深读子 agent 落盘 · 一论文一份）

> 流程见 `method.md`；公共语言规范见 `output-contract.md`。

面向"接下来要设计方法"抽的**带出处证据**，不是全文泛述。和同目录的 `.pdf` 一一对应，可跨方向复用。

```markdown
# 深读证据：{论文标题}（arXiv:xxxx）

> 对应同目录 {论文slug}.pdf。面向"设计方法"抽证据，每条标出处。

## 核心机制（凭什么有效）

- {底层原理，不是方法名} —— 出处：{第几节}

（标尺：写到"能向别人解释它凭什么 work"——原理一句话 + 关键两步；不抄全文、不堆细节。）

## 关键公式 / 结构

- {核心式子 / 模块怎么搭} —— 出处：{式几 / 图几}

（标尺：记结构和符号含义——每个符号是什么、各项起什么作用；不逐个抄推导步骤。）

## 实验设置

- 数据集 / 条件 / baseline —— 出处：{第几节 / 表几}

（标尺：只记对方法设计有约束的字段——数据集和规模、算力（几卡几天，论文报了才记）、评测协议、关键 baseline + 对路线设计有参考的主数字。）

## 作者明说的 limitation / future work

- {论文自己承认的短板} —— 出处：{第几节}

（标尺：照原文意思记，不夸大不软化——这是路线的合法出发点，记歪了 Step 10 会被带偏。）

## 钩子清单（Step 10 生成路线时直接汇总用）

| 类型 | 内容 | 出处 |
| --- | --- | --- |
| limitation / future work / 失败自述 / 可替换组件 | {一句话} | {第几节} |

## 一句话：这篇能支撑什么

{给主会话生成路线时的索引句——回传摘要用这句}
```

**钩子清单填好的样子**（示例）：

| 类型 | 内容 | 出处 |
| --- | --- | --- |
| limitation | 作者承认单次解码丢失细粒度结构，小目标掉点明显 | 第 5 节 |
| 失败自述 | "we tried adding more layers but it saturates"——堆容量此路不通 | 附录 B |
| 可替换组件 | 解码头是独立模块，论文自己用的就是现成件，可直接换 | 第 3.2 节 |

> **回传纪律**：子 agent 返给主会话的摘要 = "一句话能支撑什么" + 2-3 条最关键证据，**不含逐条出处细节**（那些在本文件里）。主会话一起打磨到需要精确出处/数字时才 `Read` 本文件。摘要是索引，全文是仓库。
