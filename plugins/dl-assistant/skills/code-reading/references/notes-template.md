# 中文代码阅读笔记与进度

笔记供用户理解与恢复，不是理解合格证或新的机读契约。主线默认保存；独立任务按实质讲解保存必要进度或尊重用户不落文件要求。按约定范围写，不凑固定章节/接入点，不补造用户反馈、实测或未读内容。

```markdown
# {项目/模块}：{本次阅读问题}
> 实际日期、代码位置/commit和未提交diff、目标范围、本次实际环境/config与上游来源（相关时）。

## 1. 最小运行场景与完成条件
输入、输出、要理解的操作及其与本轮任务的关系。
阅读范围：相关路径/接口/数据变化/框架机制、明确不在范围的内容；逐项进度和剩余条件。

## 2. 路径概览与必要基础
实际入口/配置、主要源码位置及调用关系；哪些源码明确、哪些为条件推断。
已有基础用独立例子解释，再连到当前问题；本篇方法或框架具体调用在对应位置讲。

## 3. 逐段源码—解释—观察
位置/版本和必要代码片段 | 本段问题/职责 | 输入输出/单位/形状/类型/状态 | 解释与依据类别 | 实际观察/条件/来源或待验证 | 理解进度
静态定义、条件推断、独立教学/局部验证、项目实际观察分别标。
用户口述/截图可见内容/agent运行和事前预测分开，没有结果不写实测。

## 4. 必要框架机制与论文对应
解释本次实际遇到的机制、来源/版本和未核实部分；论文对应含论文身份/版本/位置、成立条件和实现差异。
不强贴一行等于一个公式，不相关则省略。

## 5. 后续审阅所需接口与影响（仅与目标有关时）
具体研究/修改需求、位置、输入输出和单位/形状/语义、实际调用/配置/资产兼容、潜在影响、未知和需要的验证。
不默认找接入点，不将纯函数叫安全，也不要求列永久不可修改的部分。

## 6. 用户追问与理解状态
实际问题、解释与反馈；区分已讲、用户自述理解、做过具体理解检查及范围、疑问/跳过。
“继续”表示推进，不自动表示掌握；没做检查如实写，不当理解失败。

## 7. 观察材料、调整和下一步
实际运行/调试/教学材料路径、版本/条件/必要结果；哪些临时状态/源码/配置已恢复、哪些仍未决。
讲解顺序/解释的实际修正及原因；下次从哪个源码问题继续，缺哪些前提/来源/运行结果。
```

## 依据与范围要求

源码位置需要对应实际版本，行号只是定位辅助；仅有上游报告或旧笔记不能确认当前对象。需要恢复时核代码/config/环境与原条件，静态阅读不默认“环境没配”，动态观察也不默认全项目可运行。

shape/值写清依据和条件，含不确定维度或动态分支；教学输入不伪装真实样本。运行证据保留实际入口、输入、模式、状态/随机性相关条件和来源，记录局部调用与真实入口差异。

覆盖/调用观察只说明已观察范围；未出现的代码先记未知用途，不叫死代码、不顺手删除。修改影响按实际依赖说明，不给无条件安全/危险标签。

## 两个短自查位置

讲解前：问题/场景是否先清楚；基础是否依赖未讲内容；解释/预测/观察是否混淆；是否夸大用途或修改保证。发现问题就调整，不只是勾选。

交接前：约定范围/进度和用户实际参与是否真实；源码—解释—观察是否可追溯；推断/缺失/未验证和恢复情况是否保留；关键疑问是否丢失。修正或标阶段性，不无限补讲到用户说懂，也不凭笔记完整宣布掌握。

无需新增自查JSON/脚本；在已有进度记实际修正和未决影响即可。静态与动态阅读都可完成约定范围，但完成不自动确认尚未检查的理解或运行行为，后续关键代码仍需用户审阅。

## 研究条件核对（与本轮用途有关时）

引用条件记录的路径和版本，写明目标与实际条件、必须保留项的代码/配置/数据位置及检查证据、未知/偏差、所查范围和不能外推的内容。记录下一次目标条件验证的触发点或不适用理由。按本 skill 职责分别说明静态调查、准备、阅读或实际运行，不能将尚待检查项写成已落实；条件或假设变化后重新核对。
