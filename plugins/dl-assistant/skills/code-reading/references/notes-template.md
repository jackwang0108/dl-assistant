# 中文阅读笔记模板（code-reading）

> Stage 3 保存笔记前必读。**主线模式（EX 之前）按完整版写，「候选接入位置与改动影响」节不可省**；按需调用时可裁剪（至少保留 1/3/4/5/10）。
> 笔记用中文写；代码路径、类名、函数名、变量名、命令保留原文。所有 shape 标来源：`debug console 实测` / `脚本实测` / `源码推断`。

## 笔记结构

```markdown
# <repo 名> 代码阅读笔记 — <主题>

> 日期：YYYY-MM-DD ｜ repo：<路径> @ <commit> ｜ 模式：A 精读 / B 静态读 ｜ 主线 / 按需调用
> 追踪路径：<入口命令> ｜ 状态：完整 / 阶段性（未追踪：...）

## 1. 入口模式与环境
## 2. 用户背景与技术栈
## 3. 仓库结构概览
## 4. 追踪路径与主调用链
## 5. 逐段阅读记录
## 6. Tensor / Data Flow 表
## 7. 框架机制解释
## 8. 候选接入位置与改动影响（主线模式必写）
## 9. 用户追问与解释
## 10. 仍未读懂的问题与下一步
```

## 每节写什么、写到什么程度

**1. 入口模式与环境**
A：setup report 路径 + 本次追踪用的 ready command + launch.json 配置要点（env python / args / 是否使用单进程调试配置）。B：注明「静态阅读，repo 专属环境未配，需仓库环境的内容未经运行验证」。写到别人拿这节能复现本次阅读上下文为止。

**2. 用户背景与技术栈**
技术栈表（库/框架 | 在项目中的用途 | 用户熟悉度）+ 本次展开讲过哪些框架机制、哪些用户已熟跳过了。这节决定重读笔记时哪些解释可以跳过。

**3. 仓库结构概览**
入口层 / Config 层 / 数据层 / 模型层 / 训练评估层 / 工具层，各层关键文件+一句职责。具体填写要求：浅 = 六层各一行；深 = 附关键文件表（模块 | 文件 | 作用 | 阅读优先级）。

**4. 追踪路径与主调用链**
本次追的入口命令、主线模式注明是否 reduced 入口（推荐是，理由：小时级跑完整个 loop）、主调用链一览（每跳 file:line + 一句职责）。A 附断点计划（断点位置 ↔ 第 5 节段落的对应）。

**5. 逐段阅读记录**（笔记的主体）
每段一节，固定要素：

- **位置**：file:line + 这段在调用链的哪一跳。
- **idea**：1-2 句「这段解决什么、核心直觉」。
- **源码片段**：实际代码（带行号），关键行内联注释 shape。
- **张量形状和数值**。注明来源是 debug console 观察、脚本实测，还是源码推断。
- **论文映射**（repo 对应论文时）：「line 42 = Eq 3: attention weight」式。
- **死代码 / 可改性**：死代码标「不影响运行」；可改性标「改起来安全 / 危险（危险点）」。

具体填写要求：浅 = 位置+idea+行号，无源码片段；深 = 五要素齐全。主线模式按深写，按需查询可浅。

**6. Tensor / Data Flow 表**
主要调用路径上的张量形状变化：段 | 输入 shape | 输出 shape | 来源标注。和第 5 节不重复——这里是全链路一张表，看 shape 怎么一路变。

**7. 框架机制解释**
本次展开讲过的机制（registry / Trainer / ZeRO / hook……），每条**自包含**——读者不看源码、不翻会话记录也能懂。

**8. 候选接入位置与改动影响（主线模式必写）**
记录每个候选接入位置、该处输入输出、调用方和修改风险，供后续实现参考。

| 接入点 | 位置 | 接口契约（in → out，shape/类型/语义） | 改动影响范围（谁调用 / config·registry 如何配置或注册新实现 / 动不动 trainer） | 风险 |
| ------ | ---- | ------------------------------------- | ---------------------------------------------------------------- | ---- |

再加一小段「**应保留原样的部分**」：核心训练循环、分布式 setup、以及为什么不动。

具体填写要求：主线笔记须注明位置、输入输出约定、改动影响范围和注册方式。仅列模块名称时，读者还无法定位并接入新实现。

浅/深示例（同一个接入点）：

```text
浅：loss 可以换，在 loss.py。
深：接入点 = 自定义损失。位置 loss.py:60 的 build_loss(cfg)。
    契约：输入 preds dict（cls [B,N,C] / bbox [B,N,4]）+ targets list[dict] → 输出 scalar loss；
    新实现必须在 registry 注册 @LOSSES.register_module()，在 config 中修改 type 即可使用新实现，trainer 无需修改。
    改动影响范围：只被 trainer.py:311 一处调用；风险：危险——内部隐式假设 targets 已 normalize 到 [0,1]
    （在 dataset 侧做的，loss 里没检查）。
```

**9. 用户追问与解释**
本次用户真实追问过的问题 + 当时的解释。这是下次再读时最先看的节。

**10. 仍未读懂的问题与下一步**
尚未阅读的调用路径、尚待验证的源码推断、建议下一步（回 setup 解 blocker / 追另一条路径 / 直接进 execution）。
