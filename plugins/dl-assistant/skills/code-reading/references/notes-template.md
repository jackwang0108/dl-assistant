# 中文阅读笔记模板

按[阅读流程](workflow.md)保存实际读过的范围、依据和未决项。有明确改动需求时记录候选接入位置。代码标识符、路径和命令保留原文。

## 笔记结构

```markdown
# <repo 名> 代码阅读笔记 — <主题>

> 日期：YYYY-MM-DD ｜ repo：<路径> @ <commit> ｜ 方式：静态阅读 / 局部诊断 / 交互调试 ｜ 主线 / 按需调用
> 追踪路径：<入口命令> ｜ 状态：完整 / 阶段性（未追踪：...）

## 1. 入口模式与环境
## 2. 用户背景与技术栈
## 3. 仓库结构概览
## 4. 追踪路径与主调用链
## 5. 逐段阅读记录
## 6. Tensor / Data Flow 表
## 7. 框架机制解释
## 8. 候选接入位置与改动影响（按需）
## 9. 用户追问与解释
## 10. 仍未读懂的问题与下一步
```

## 每节写什么、写到什么程度

**1. 入口模式与环境**
写代码和配置版本、实际入口、观察方式与已核环境。使用调试时列解释器、入口参数和运行条件，静态部分注明待核范围。

**2. 用户背景与技术栈**
技术栈表（库/框架 | 在项目中的用途 | 用户熟悉度）+ 本次展开讲过哪些框架机制、哪些用户已熟跳过了。这节决定重读笔记时哪些解释可以跳过。

**3. 仓库结构概览**
入口层 / Config 层 / 数据层 / 模型层 / 训练评估层 / 工具层，各层关键文件+一句职责。具体填写要求：浅 = 六层各一行；深 = 附关键文件表（模块 | 文件 | 作用 | 阅读优先级）。

**4. 追踪路径与主调用链**
写入口命令、实际条件和调用链。使用 reduced 时记缩减范围。附实际使用的断点计划，便于对应下文的讲解。

**5. 逐段阅读记录**（笔记的主体）
每段一节，固定要素：

- **位置**：file:line + 这段在调用链的哪一跳。
- **idea**：1-2 句「这段解决什么、核心直觉」。
- **源码片段**：实际代码（带行号），关键行内联注释 shape。
- **张量形状和数值**。注明依据是源码明确、条件推断、独立小验证或项目实际观察。
- **论文映射**（repo 对应论文时）：列论文概念与实际实现位置，说明条件与差别。
- **调用覆盖和改动影响**：写实际查到的入口、未观察到的路径、相关依赖和待做验证。

具体填写要求：浅 = 位置+idea+行号，无源码片段；深 = 五要素齐全。主线模式按深写，按需查询可浅。

**6. Tensor / Data Flow 表**
主要调用路径上的张量形状变化：段 | 输入 shape | 输出 shape | 来源标注。和第 5 节不重复——这里是全链路一张表，看 shape 怎么一路变。

**7. 框架机制解释**
本次展开讲过的机制（registry / Trainer / ZeRO / hook……），每条**自包含**——读者不看源码、不翻会话记录也能懂。

**8. 候选接入位置与改动影响（按需）**
记录每个候选接入位置、该处输入输出、调用方和修改风险，供后续实现参考。

| 接入点 | 位置 | 接口契约（in → out，shape/类型/语义） | 改动影响范围（谁调用 / config·registry 如何配置或注册新实现 / 动不动 trainer） | 风险 |
| ------ | ---- | ------------------------------------- | ---------------------------------------------------------------- | ---- |

说明已核实需保留的运行条件和依据。

具体填写要求：记录候选接入点时注明位置、输入输出约定、改动影响范围及相关注册方式。仅列模块名称时，读者还无法定位并接入新实现。

浅/深示例（同一个接入点）：

```text
浅：loss 可以换，在 loss.py。
深：接入点 = 自定义损失。位置 loss.py:60 的 build_loss(cfg)。
    契约：输入 preds dict（cls [B,N,C] / bbox [B,N,4]）+ targets list[dict] → 输出 scalar loss；
    新实现必须在 registry 注册 @LOSSES.register_module()，在 config 中修改 type 即可使用新实现，trainer 无需修改。
    改动影响范围：本次核到 trainer.py:311 的调用，其他入口待查。内部假设 targets 已 normalize 到 [0,1]
    （在 dataset 侧做的，loss 里没检查）。
```

**9. 用户追问与解释**
本次用户真实追问过的问题 + 当时的解释。这是下次再读时最先看的节。

**10. 仍未读懂的问题与下一步**
尚未阅读的调用路径、尚待验证的源码推断、建议下一步（回 setup 解 blocker / 追另一条路径 / 直接进 execution）。

## 交付前自查

- [ ] 所有 shape 都标了来源，没有把「源码推断」写成实测
- [ ] 有明确改动需求时，第 8 节写清接入位置、输入输出约定、改动影响范围和注册方式，并说明哪些部分应保留原样及其理由
- [ ] 框架机制解释自包含，不依赖会话上下文
- [ ] 代码标识符保留原文，解释是中文
- [ ] 阶段性笔记标了「阶段性」并列出未追踪部分
