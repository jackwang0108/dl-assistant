# 主动规划并落实图片与视觉表达

每页都明确视觉表达的任务。好图帮助看见结构、差异、变化、样本或证据；装饰性图标、边框和卡片不会自动减少理解难度。不规定每页必须有照片，也不规定固定图文比例。

## 从内容选择形式

| 本页要让听众理解什么 | 优先考虑的表达 |
| --- | --- |
| 研究对象/使用场景 | 用户已有图片、真实设备/界面截图、带具体对象的示意图 |
| 问题确实存在 | 代表样本、失败案例、对照图、实际分布；标选择规则 |
| 方法如何工作 | 输入/输出/数据流、模块对应与整体图，必要时逐步展开 |
| 两种方法差在哪里 | 同一样本/坐标/尺度的对照、差异标注、局部放大 |
| 结果支持什么 | 来源可查的图表、不确定性、分组和样本；少用只写大数字的卡片 |
| 为什么发生变化 | 区分已观察关系与假设的解释图，缺证据处显式标未知 |
| 算法或参数直觉 | 可检查的几何/信号示意、滑块教学例子，附静态关键状态 |
| 系统做到了什么 | 真实演示/截图/日志片段，对应具体验收条件 |
| 希望讨论什么 | 关系图、选项比较；简短问题页也可纯文字 |

纯文字是允许的选择：简短标题、清楚结论、明确待答问题，或当前确无能改善理解的视觉表达。记录具体理由。连续大量纯文字页时重新检查是否遗漏方法图、数据图或样本；不要用“加一个图标”敷衍。

## agent 的取材责任

形成逐页规划后主动准备素材，不能只写“此处放图”。可执行操作包括：

1. 检查用户已给文件、项目图表/真实截图和已批准的可用资产。
2. 获取论文图表及相邻原文，核论文版本、图号、实验条件。tex-mcp 适合源图，pdf-mcp 可渲染原页或裁剪；按当前工具 schema，不编造调用。缺少直接图时可以解释性重绘并标明来源与改动。
3. 根据真实数据绘图，保留输入、处理/绘图脚本与实际输出。出版级科研图使用标准绘图工具，不凭语言生成一条看似真实的曲线。
4. 绘制清楚的 SVG、流程图或可检查的几何示意。模型示意需与实际实现对应；未知机制用假设标签，不能画成已经证实的箭头关系。
5. 对确需真实情境图片的页面检索来源/使用条件并本地保存；不直接热链搜索缩略图。
6. 对适合概念说明的素材使用当前可用生成工具。记录生成来源和“概念示意，非实验结果”等标注；不生成伪造的实验截图、样本输出、仪器或人物照片作为证据。

先根据解释需要选择，非固定取材顺序。取不到重要素材时提供实际替代方案及限制；不要直接退回密集文字或用不相关通用配图填位。所有ready素材需实际放到对应页，检查器会核文件和 data-asset-id 的页面关联。

## 素材记录与阅读检查

在规划的assets中保存id、用途、文件、alt、来源(kind/ref)、状态和适用的标注/署名；可加sha256、裁剪说明、权限/共享范围、真实数据/脚本引用。论文图、用户照片、生成插图的使用条件不同，要按实际来源核，不把搜索可见当任意可用。

缩放后重新看：坐标/图例/关键标注是否能读，裁剪是否丢掉条件，对比是否一致，颜色含义是否稳定。必要时重绘简化、拆成几页或局部放大。原图和裁剪/重绘版分别保留，避免覆盖原始材料。

HTML建议：

```html
<figure>
  <div class="visual"><img data-asset-id="method-overview" src="assets/method.svg" alt="输入音频经过编码、聚合与预测三个步骤"></div>
  <figcaption>根据当前实现绘制；箭头表示数据流，非因果证据。</figcaption>
</figure>
```

每张图都应帮助讲述者指出具体对象/关系。图中alt不替代视觉检查；图表数据有效性不由文件存在或哈希一致认证。

## 静态和交互共同规划

交互页记录：输入、输出、操作方式、初始/重置状态、需要展示的关键状态、实际实现与静态备用。互斥显示、音视频或滑块不靠“截图最后一帧”自动完成解释。

例如展示音频差异：现场提供同一样本播放器、标注的波形/频谱与条件；PDF保留代表片段、尺度、标注和可得到的观察，不宣称纸面可以听出差异。展示阈值作用：现场滑块改变指定模拟量；PDF列出几个关键阈值及其输出，明确是教学模拟。
