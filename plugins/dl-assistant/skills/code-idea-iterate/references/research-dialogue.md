# 研究判断对话方法

> iterate 三个对话密集环节的手法：理解上版（证据盘点）、诊断决策（讲懂推理链 + 定版型）、方案与 plan 共同打磨。
> 本文件只管**怎么和用户聊**——聊的内容（候选怎么生成、spec/plan 怎么写）归 `spec-design.md` / `dl-assistant/references/plan-writing-principles.md`。
> 目标：让用户**跟得上、能决策**——研究判断是人和 agent 一起确认，用户跟不上就等于 agent 自己确认了。

## 手法一：边查边讲，别攒到最后

每次要查文献 / 读结论 / 拉证据，**先用白话讲为什么要查、现在判断卡在哪**；查完讲「这几条证据说明了什么、对判断有什么改变」。不要把所有发现攒到最后一次性倾倒——用户会失焦，失焦后只会说「嗯」。

## 手法二：先介绍概况，再按用户需要展开

不要一次性把所有分析灌给用户。先给**压缩全景**（一屏能看完的骨架：上版干了什么 → 结果如何 → 问题在哪 → 有哪些出路），让用户按自己节奏点「想深挖哪块」。用户问到哪，agent 展开到哪。

## 手法三：讲懂纪律

- 每提一篇论文：附「它干了啥、为什么跟这相关」——默认用户没读过。
- 每用一个专业术语：紧接一句话白话解释。
- 数学符号对话里用 Unicode（α、β、θ），不用 LaTeX。
- 讲推理链时讲「为什么这么判、基于哪些证据」，不只讲结论——用户要审的是推理，不是结论。

## 手法四：推进信号纪律

- 用户沉默 /「嗯」/ 只回答问题 ≠ 推进信号——继续答、换角度重讲，轮数无上限。
- 用户明确「懂了 / 没疑问 / 继续 / 确认 X」才是推进信号。
- **不要比用户更热爱流程**——用户喊「这些我懂，直接说下一步」就顺着跳。

## 手法五：先征集用户的想法

在任何 agent 生成候选的节点之前（idea-find 的 pitch 池 / 路线骨架、iterate 的候选生成），先做这一步——**先收用户的原始想法，再谈生成**：

- **先说明具体问题，再听用户的想法**：用一两句说明每个待解决的问题、已有线索，或可用的资源与专长。不许夹带 agent 自己的方向倾向。
- **禁预锚句**："我在想是不是可以 X 或 Y——你觉得呢？" = 先给候选方案再征求用户想法，征集作废。先展示候选会影响用户提出自己的想法。
- **邀请半成品**：明确说"半句话、一个类比、一个'我就觉得哪里不对'都行"——用户可以先说直觉，之后再补细节。
- **收到后**：原话级别记下，标来源「用户」，进候选方案清单当一等候选；agent 的活是细化 + 否证性压力测试（先例三问、撞车检查照做），不是拿自产候选抢位置。
- **用户暂无想法时继续**：用户说"没有 / 你来"→ 由 agent 继续补充候选。这段对话安排在主流程已有的确认点之前。

## 候选的呈现格式（给用户选时）

方案候选（spec-design Step C 产出）摆给用户时用这个骨架——每个候选只是一个角度，**不是完整方案**：

```
可能的方向：

**方向 A：[一句话角度]**
- 来源逻辑：[为什么这个角度能补缺口]
- 关键思路：[用什么机制]
- 参考：[1-2 篇机制先例 URL + 一句话它们做了什么]
- 风险：[最可能因什么原因未达预期]

**方向 B：……**
```

然后问（选定动作是**排除法**，不是单选）：

```
这几个角度，哪些明显不行、直接划掉？剩下的都交给实验试。或者还有别的想法？
```

## 共同编辑（用户选定方向后）

1. **生成初稿**：核心假设 + 技术路线 + 与上版本质差异 + 预期结果。
2. **逐轮打磨**（不是一次成品）：
   - 用户质疑某点 → agent 查文献 / 证据补充 → 更新初稿。
   - 用户说「这假设有问题」→ agent 调假设、重新推导。
   - 用户说「换角度试试」→ agent 基于新角度重新生成。
   - **每次改动都说清楚「改了什么、为什么」。**
3. **细化到可执行**：核心假设 + 要验证哪些 claim + 成功 / 失败判据——这些写入 spec 写入文件；写 plan 时，方法设计 + 实验设计也走这套共同编辑（出初稿 → 给用户讲懂每实验原理 → 用户质疑 → 查文献补 → 更新 → 认可）。

## 按需文献验证（贯穿，不是提前全验）

- 用户质疑「这方法是不是已经被做过了」→ `paper-search` 查重。
- 用户质疑「这机制真的有效吗」→ 读相关论文验先验。
- **不是提前验证所有方向**，只验证当前在讨论的那个。选定方向后、写进 spec 前，再做一轮正经验证。

## 工具 + 输出规范

- 文献搜索必须用 `paper-search` MCP 取真实数据（`semantic_scholar` + `scholar`），**禁止编造论文**；读 arXiv 论文全文首选 `tex-mcp`（`tex_open` 打开固定版本 → `tex_outline`/`tex_read`），源码不可用时降级 `pdf-mcp`；本地 PDF 直接用 `pdf-mcp`。
- **参考文献给 URL（arXiv / Semantic Scholar / Google Scholar），不给 `paper_id`**——横切规范见 `dl-assistant` SKILL.md「横切规范」。
- 论文信息（标题 / 作者 / 年份 / venue）必须来自工具返回。
- 用户在做选择（选方向）时不需要搜索；上下文已够时不重复搜索。
- 用中文写所有分析、候选、结论；专业术语保留英文。
