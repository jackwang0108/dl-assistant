# 证据复核与原因调查指引

本文件说明怎样从一条具体实验观察出发，复核原始证据、比较可能解释，并记录每次检查改变了什么判断、还留下什么未知。

在[运行手册 Step 2](workflow.md#step-2-核证据并向用户解释)需要深入复核证据或调查原因时使用。按[调查记录模板](autopsy-template.md)保存实际检查，给 `next-step-decision.md` 提供依据。

## 1. 确定要解释的观察和范围

1. 从用户当前要做的判断出发，挑一条会影响该决定的观察。写清具体问题、实际读数和原预测。例如，组合配置的延迟低 1.8 ms，要判断现有证据能否把差值归到写回量变化。
2. 从结论中的观察 ID 找到实验 ID、实际 run 和原始产物。读批准的设计及修订、元记录和测量代码，核比较用的样本或数据、配置、权重、单位、统计方式及运行状态。标明哪些条件来自源码或配置，哪些已有实跑证据。
3. 先核观察本身。如果报告和原记录不一致，确定哪个版本或哪种统计范围造成差异。结果只在某个子集、档位或训练阶段出现时，把该条件写进问题。读数缺失或测量无效时，说明缺口会影响哪些判断。

## 2. 为仍可解释观察的原因写区分办法

- **先从证据产生解释。** 从分组差异、配置变化、执行日志、测量偏差和研究假设列出可能原因。并列保留可以共同起作用的因素。已有证据只够说明某个解释不适用时，记录判断及范围。
- **逐项列支持和反对。** 说明这个原因若起作用，还应观察到什么。再找当前材料中最不支持它的观察。把没有记录、查过未发现、实测与预测相反分开记。
- **找能区分解释的变化。** 例如写回量下降和实际算子切换都能导致同方向的延迟差，就查已有组里是否有实际算子相同、写回量不同的配对。若两个因素在每个相关配对里都变，现有读数仍可描述配置差异，机制解释保持开放。

## 3. 选最能改变判断的下一项检查

| 现有材料 | 怎样检查 | 查到什么才改变判断 |
| --- | --- | --- |
| 已有原始读数，但汇总或配置条件不清 | 用原纳入与聚合规则复算。按实际 run 对照输入、配置、单位和被纳入的记录。保存命令或计算方法 | 若差异来自统计口径，重述该比较实际可用的范围。口径一致后再分析可能原因 |
| 有轨迹、配置或日志可交叉核对 | 按实际运行 ID 将轨迹与生效配置对应。记录实际算子、写回量及其采集条件，再查是否存在能固定一个因素的配对 | 有可比配对时回到实际读数核预测。缺配对时记录现有组为什么无法隔离机制 |
| 只找到源码里的可行入口 | 从命令和配置沿实际调用追到选择或回退分支，核输入和设备条件。写清明确看到的能力及未经实跑确认的部分 | 若源码足以排除该入口，改提其他办法。若只能说明可能可用，把验证实际分派写成待补任务 |
| 需要新增测量、运行或正式对照 | 写明待分辨的解释、应保持及应改变的条件、所需读数、可能结果和成本。将拟做任务纳入取证方案交 execution | 在确认范围、条件和预算后取得证据，再回到当前问题判断 |

每次检查记录材料和版本、实际操作、观察、受影响的解释及下一步。事后复算或发现须标明来源和范围。相同现象可能出现在多个步骤，优先查最能把解释分开的比较。

### 判断是否需要断点诊断

1. **先定位异常及其影响。** 用原始读数、日志、配置和测量代码确认问题出现在哪个 run、样本或阶段，以及会影响哪项研究决定。已有调试记录时，核实际入口、代码版本和触发条件是否与该观察对应。
2. **选能分开解释的观察。** 例如某类样本指标突降，现有汇总无法区分「模型预测变差」和「评测掩码排除了有效样本」。先用保存的预测、标签和有效样本计数复算。如果还缺运行时状态，提出在评测掩码应用前后观察样本 ID、有效数和分母，写清哪些结果会支持或削弱各解释。
3. **按需要交 execution 取证。** 将原 run、最小触发场景、需保持的条件、目标符号或观察值、成本和停止点写进补查任务。经确认后，由 execution 按[断点诊断](../../code-idea-execution/references/training-dynamics-debug.md#需要查看运行时状态时用断点)执行。可用时选 `mcp-debugger`，否则用项目调试器或可复跑的局部脚本观察同一状态。
4. **用所查范围更新判断。** 一个断点可说明特定输入走了哪个分支。若还需判断问题有多普遍、对总体指标有多大影响，提出在目标数据和测量协议下复算或复测。把诊断观察、适用条件、仍成立的解释及建议写入 `autopsy.md`，在决定记录中引用。

## 4. 判断何时结束或恢复

- 已有证据足以回答当前决定时，写结论所涵盖的条件和剩余未知。
- 现有材料无法继续区分解释、关键证据不可得或下一项检查超出可用投入时，记录具体阻塞。写清什么证据到手后值得恢复。
- 将过程和复算保存在 `autopsy.md`，把影响选择的结论及其出处写入 `next-step-decision.md`。用户决定、投入和停止点在后者记录。
