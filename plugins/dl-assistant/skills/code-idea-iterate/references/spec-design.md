# 从实际证据发展假设与下一轮设计

先写原认识、实际观察与判断变化，再选择需要减少的重要未知。没有原因结论也能设计取证；不能先把猜测写成机制事实，再设计修复方案。

## 提出和比较解释

对确有必要讨论的解释分别记录：
- 具体主张、条件、推理链；数据观察和推理分开。
- 支持与反对证据、来源位置、未取得的信息。
- 与其他解释相同和不同的预测；当前数据能否区分。
- 假设成立时新增什么认识，证据相反时改变什么判断。

agent主动生成，不等用户先提供创意；来源不限于旧方法缺陷，也可来自异常、规律、跨条件差异、理论不一致或文献冲突。没有先例不自动降级；推理尚不成立就先补推理，不能用乐观标签替代。

## 按重要未知选择行动

| 未知 | 可能行动 | 解释限制 |
| --- | --- | --- |
| 实现/测量是否可信 | 检查源码、数据、已知答案测试 | 一次测试通过不证明整体正确 |
| 现象是否稳定 | 合理重复、扩大样本、检查条件 | 不只在结果接近时追加到显著 |
| 多个解释都可产生观察 | 设计不同预测的干预或测量 | 相关性或某组件有效不证明机制 |
| 原预测受到反证 | 修订/替换假设，或停止 | 不要求先试多个模型；也不推广为整个领域错误 |
| 出现未预期规律 | 明确事后假设，安排相应取证 | 说明数据复用，必要时独立确认 |
| 结果成立但意义不清楚 | 比较相关工作、重评价值 | 不用继续加组件替代价值判断 |
| 条件或范围已改变 | 重新定义问题，分配新命题ID | 不借用原大问题的重要性 |

不要求固定路线数、固定单变量或全部候选都试。比较最有希望改变重要判断的行动，包括不做实验；说明识别能力、成本依据、预算与机会成本，不编造胜率或GPU耗时。未知不重要或代价不相称时可不追。

## 探索与预先检验

探索需明确问题、观察范围、分析、预算与停止条件，不需预知效应；结果可以产生新假设，但需注明事后性质。预先检验明确预测、对照、解释范围和依据，不编造提升数字或统一统计阈值。

已有数据的事后分析不是一律无效，也不能伪装成预先检验。复用数据对推断的影响、竞争解释、选择过程和必要独立确认应明确。诊断或纯分析可独立成为下一轮，不必塞进一个新方法计划。

## 用户决策与执行交接

先给推荐、最强反对理由、较便宜选择及成本未知，再讨论兴趣、当前贡献意义和具体投入。用户可提供想法或质疑，不负责替agent发现好问题。

确认当前行动后按共享spec/plan模板交execution。科学设计未明确就继续讨论；精确工程入口可由读真实代码后补齐。不要把接口缺失与研究问题未知混为一谈。起草计划前执行主文件next_step自查，存在影响本轮解释的缺陷时先修正，不把自查变成写完材料后的盖章。
