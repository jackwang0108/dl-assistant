只在批准下一轮实验后保存 `00-from-previous-version.md`；机器摘要使用同名JSON。当前决定记录可直接引用，不能把所有讨论强行转成新版本。

## 问题与版本

研究上一轮版本、本轮版本、问题/假设ID；实现起点commit/模型可能来自更早版本，单独说明选择理由。

## 原来相信什么、观察到什么、改变了什么

原认识与依据 → 实际数据与来源 → 证据支持范围与研究判断 → 仍未知。保留反证和原核查报告；事后解释注明，不要求每轮查明机制。

## 本轮为什么值得做

当前问题定义，原范围与新范围、保留/失去的意义；与已核查工作差异及重要性。关键未知、候选解释、不同预测和本轮要改变的决定。

## 命题变更与继承

新增/修订/替换/停止追踪的命题和具体依据；含义或范围变更建立新ID（包括总假设），保留旧证据及关系。相同命题不清空历史、不因过去supported就免于条件核查。资源停止不自动refuted。

## 本轮设计与投入

本轮探索/检验目标，选择测量、分析、理论或方法的理由；不能识别部分、已批准预算/范围与待定工程入口。详细设计见02，关键代码审阅由execution进行。

## 来源与自查

实际代码/数据/模型/配置、上一轮结果与review、当前判断记录、next_step自查和用户决定。新证据改变设计时保留原批准计划及修订，不覆盖成“原本就这么想”。

## 研究条件核对（与本轮用途有关时）
